# 手走清单 —— 只有人点得到的那些断言

`db/fixtures` 问"建出来的库跑起来对不对";`scripts/smoke-routes.mjs` 问"每条路由渲不渲得出来"。
**这份清单问第三个问题:操作员在屏幕上【读到的那句话】是不是人话。**

没有任何自动化跑得到它,原因是具体的而不是懒:

* 冒烟只发 **GET**,它断言 2xx —— 它从不提交任何表单;
* 表单用 `useActionState`(客户端组件),**没有渐进增强的隐藏字段**,所以
  无 JS 的 POST 根本到不了 action;走 Next 的 action 线格式需要客户端 bundle 里的
  action id,而那正是浏览器才有的东西;
* fixture 是 SQL,它够得到 RPC,**够不到 action 与 locale 文件**。

于是"数据库那侧完全正确、而屏幕上是一串机器码"这件事,**只有人点得出来**。
IOD-1b 与 IOD-2 各付过一次账,两次都是人点出来的。

## 什么时候跑

改动了 **action 的错误分支、`*ErrorCodes.ts` 的集合、`messages/*` 里的错误/告警句子**,
或者新加了一个会抛到界面上的 RPC 错误码 —— 跑与之相关的那几条。不必每次全跑。

## 怎么起

```bash
npx next dev -p 3000
```
临时管理员账号自己建(参照 `scripts/smoke-routes.mjs` 的 `signIn`),或用一个真账号。
**被拒的走法不写任何流水**,可以放心在 live 上点;标着【会写库】的那几条会留下
**永久的 `inventory_movements` 行**(台账只进不出,`BEFORE DELETE` 抛 `MOVEMENT_IMMUTABLE`),
所以那几条要么别在 live 上点,要么接受它留下来。

## 1 · 库位分类落闸:明确排除 → 拒绝(IOD-2)

**前提**:一个在用库位配了 allowed_classes(例如只允许 `focused`);一个物料的分类
**不在**其中(例如 `non_focused`)。

**走**:`/inbound/new` → 选那个物料、那个库位 → 保存。
**期望**:红条是一句话,并且**说得出三条出路**(换库位 / 把这一类加进该库位 / 改物料分类):

> Location SG… is configured to hold specific material classes, and non_focused is not one of
> them — so nothing was saved. Pick another location, add non_focused to that location under
> Inventory → Storage Locations, or correct this material's classification in the material dictionary.

**不期望**:`IOD_CLASS_EXCLUDED|SG…|non_focused`(机器码原样)。

**为什么在这份清单里**:拒绝由 RPC 抛出(fixture 59 B3/E/F1/F2 已经钉住"抛得对"),
**但"抛完之后有没有被翻成人话"住在 action 的错误分支 + `messages/*` 里** —— fixture 是
SQL,够不到那两处。这一条 2026-08-13 手走时是红的:action 那时用一句手抄的正则挑
错误码,新码没被挑中,于是走了 `saveError` 分支把机器码端了出去。
现在判据改成 `isStockErrorCode()`(与 `STOCK_ERROR_CODES` 同一份),漂开的那条路没有了,
但**"句子长什么样"仍然只有人看得见**。

其余三个落地点同理,改了任何一处错误分支就顺带走一遍:
`/inbound/receive`、`/output/new`、以及批次页上的**转移**面板(它不重定向,告警直接回到面板)。

## 2 · 日期必填:说人话,不说约束名(IOD-2-fu1 / FIN-32)

**走**:`/output/new` → 填物料与数量,**产出日留空** → 保存钮应当是灰的、下面有一句
琥珀色说明;再想办法提交一次(绕过界面那道守卫)。
**期望**:

> Output date is required — the stock movement records the day the goods were actually produced

**不期望**:`new row for relation "inventory_movements" violates check constraint
"inventory_movements_business_date_required"`(约束原文)。

到货日在 `/inbound/new` 与 `/inbound/receive` 上同理。

**为什么在这份清单里**:这一条现在**有一半是自动的** —— fixture 25 H 臂断言三个 RPC
少了日期会**按名**拒绝(`ARRIVAL_DATE_REQUIRED` / `OUTPUT_DATE_REQUIRED`),那是
2026-08-13 手走之后补上的:当时 RPC 自己一道守卫都没有,只有 app 那一层有,
于是任何不经过表单的调用者都会撞到 FIN-32 的 CHECK 并拿到约束原文。
**剩下的一半仍然只有人点得到**:那个名字有没有在两个 locale 里接成句子、
以及界面那道守卫(禁用提交 + 说明)是不是真的在。

## 3 · 落地告警:琥珀、成句、一条一行(IOD-2)

**走**:把货收进一个**没配过 allowed_classes** 的库位,或收一个**未分类**的物料。
**期望**:落地页(`/inbound`、`/output`、收货完成页)顶部一条**琥珀色**横幅,
一条告警一行,并且**批次确实建出来了** —— 告警不是拒绝。

【**会写库**】这一条的期望结果是"保存成功",所以它会在 live 上留下永久流水。
2026-08-13 的做法是**只走渲染那一半**:直接请求
`/inbound?warn=%5B%22IOD_CLASS_UNCONFIGURED_LOCATION%7CSG…%22%5D`,
真组件、真本地化、不写库。RPC 会不会吐出这两个码,由 fixture 59 B1/C/E/F3 钉住。
两半合起来等于整条路径,而没有任何一行永久流水。

## 4 · 物料表单的【提交】那一半:安全库存阈值真的落库(SS-1)

**两条,新建与编辑各一条 —— 它们是两段不同的代码**:`app/materials/new/actions.ts`
走 `.insert()`,`app/materials/[id]/edit/actions.ts` 走 `.update()`,各有一份取值、
一份校验、一份写入。走通了一条不代表另一条。

**走 A(新建)**:`/materials/new` → 填必填项 + 安全库存填 `500` → 保存 →
回到列表,该物料那一列应当显示 `500 kg`,**而不是「未监控」**。
**走 B(编辑)**:`/materials/<id>/edit` → 把阈值**清空** → 保存 →
列表那一列应当变成**「未监控」**,而不是 `0`。
**走 C(两条表单各一次)**:阈值填 `0` 或 `-5` → 期望是那句话:
「安全库存必须是大于 0 的数字 —— 不想监控这个物料就留空」,
**不期望**约束原文 `materials_safety_stock_qty_positive`。

**为什么在这份清单里 —— 与前三条同一个理由,而且是同一堵墙**:表单用
`useActionState`(客户端组件),**没有渐进增强的隐藏字段**,所以无 JS 的 POST
到不了 action;走 Next 的 action 线格式又需要客户端 bundle 里的 action id。
冒烟只发 GET,fixture 是 SQL 够不到 action。**2026-08-13 的 SS-1 手走只走到了
渲染那一半**(两张表单的字段与提示句都确认渲染出来了,列表那一列也确认了),
**提交那一半一次都没有人点过** —— 那正是这一条存在的理由,别把它读成"已经走过"。

数据库那一侧不必在这里走:CHECK(NULL 或 > 0)由 fixture 60 F 臂两个方向各拒
一次,告警对 NULL 不响由 D 臂钉死。这一条只问【表单填的值有没有原样落进去】,
以及【拒绝有没有说人话】。

## 5 · 申报量真的落库,而【留空落的是 NULL 不是 0】(GRN-1b)

**两条,两张收货表单各一条 —— 它们是两段不同的代码**:
`app/inbound/new/actions.ts` 走 `create_inbound_batch`,
`app/inbound/receive/actions.ts` 走 `receive_inbound_batch_against_po`,
各有一份取值、一份校验、一份 RPC 调用。走通了一条不代表另一条。

**走 A(填了)**:`/inbound/new` 或 `/inbound/receive` → 申报量填 `1000`、
过磅数量填 `800` → 保存 → 打开该批次详情,「与采购单的对照」一段里应当出现
**「申报与实收不符」**,并写出 `申报 1000 / 磅秤 800 / 差 −200`,以及判它的那两个阈值。

**走 B(留空 —— 这一条才是要害)**:同样两张表单,申报量**什么都不填** →
保存 → 详情页**不许**出现「申报与实收不符」,而且不许出现任何"申报 0"的字样。
库里那一列应当是 `NULL`。**填 0 与留空必须是两种结果**:留空 = 没记录过,
0 = 供应商申报了零(一句没人说过的话)。

**走 C(选了采购行之后)**:在 `/inbound/receive` 选一个供应商 → 选一张采购单 →
选一条采购行。**数量框会被预填成剩余量(那是对的,便利)**;
**申报量框必须【仍然是空的】**。这一条是这三条里最重要的:
一个被预填的申报量,是系统替供应商说了话 —— 它会让"申报与实收一致"在没有任何
供应商文件的情况下成立,而那正是这一列存在要回答的问题。

**为什么在这份清单里**:与前四条同一堵墙 —— 表单是 `useActionState`,
冒烟只发 GET,fixture 是 SQL 够不到 action。数据库那一侧由 fixture 87 E 臂
三个方向钉死(没记 = NULL、相符 = 数字 0、超差 = 报),**这一条只问
【表单填的值有没有原样落进去,以及留空有没有真的留空】**。

## 6 · 收错料的那句话说的是【收下了】,不是【被拦住了】(GRN-1b)

**前提**:一张 confirmed/receiving 的采购单,某一行订料 A;现场收到的是料 B。

**走**:`/inbound/receive` → 选那张单、那一行 → **把物料改成 B** → 保存。
**期望两件事,缺一不可**:
1. **保存成功**,批次建出来了 —— 收错料【不拒绝】(换料是可以谈成的正当安排);
2. 批次详情的「与采购单的对照」里出现**「收到的不是订的料」**,写出两个料号,
   并且**明说这批货已经收下、已经入账**。

**为什么第 2 点的措辞是这一条的全部**:告警在屏幕上极容易被读成"这批货被卡住了"。
读错的操作员会去找一个并不存在的放行按钮,或者**更坏:再收一次**。
所以这一条要走的不是"有没有提示",而是**"提示有没有说清楚货已经进来了"**。

【**会写库**】走这一条会留下永久的 `inventory_movements` 行 —— 台账只进不出。
要么别在 live 上点,要么接受它留下来。

## 7 · 供应商模式面板的两个【只有人看得见】的状态(GRN-2)

**为什么这一条必须在这份清单里,而不是做成 fixture**:fixture 88 钉住的是
**视图**那一半 —— 无权读者拿到【0 行】(H 臂)、没有可比对收货的供应商仍然
拿到【一行全 0】(G/J 臂)。但"这一行 0 在屏幕上被印成哪一句话",是
`ReceiptPatternPanel` 里的一个 React 分支,**fixture 是 SQL,够不到它**
(本文件开头那三条理由,第三条)。而这两句话恰恰是这一刀的全部意义。

**走 A(具名空状态)**:`供应商` → **Staff Reimbursements** → 「收货记录」面板。
**期望那一句话是**:
> 最近 180 天里,没有任何一条【有订量可比】的收货 —— 所以这里没有可供评判的东西。
> 这【不是】一份干净的记录:它的意思是,还没有人能够检验这家供应商。

**不期望**:任何一行"短交 0 次 / 超收 0 次"之类的零。**看到零就是这一条失败了** ——
五种差异的计数在这个分支里【整块不渲染】,因为它们的分母是 0,而印出来的零会被
读成"全都合规"。同一块面板下方仍应印出「没法评判:1 条」——
那 1 条正是它唯一的收货。

**走 B(受限)**:用一个持 `module.suppliers.view`、【不持】`module.purchasing.view`
的账号打开任意一家供应商。**期望**:
> 这份记录在采购模块那道门后面,而你没有那个权限。这是一句【权限答复】——
> 它不是在说这家供应商记录干净。

**不期望**:空白、零、或者「这不该发生」。
**这一条今天在线上走不通**:实测五个持 suppliers.view 的角色(admin / auditor /
finance / gm / procurement)【全部】也持 purchasing.view,所以要走它得先临时建一个
只给 suppliers.view 的角色。**记下来而不是省掉**:角色表会变,而那一天没有人会
记得回来补这一条 —— GRN-1b 在批次详情上栽的正是这个分支(当时它渲染的是
「这不该发生」,对着 warehouse 与 operations 两个真实角色天天说)。

## 8 · 设备采购的整条链(EQP-1c-b)—— **这一条是那一刀的关闭条件**

**为什么它在这里:** 前面几刀(EQP-1a → 1c-a)全是操作员够不到的管道。
闸门绿、fixture 全过,都【不能】说明这个模块能用 —— 那正是本仓库记过的结构盲点
(月结走查在八步里点出七个页面级缺陷,而当时每一道闸都是绿的)。
所以这一刀的关闭条件是这条走查,不是一次绿闸门。

**在生产上走。** 它【会写库】:一张资产卡、一张采购单、一笔付款、一笔开支、
一条冲抵分录。这些都是真凭证,走完留下的东西见本节末尾「残渣」。

### 走之前

用一个同时持 `module.finance.edit` 与 `module.purchasing.edit` 的账号(admin 即可)。
**若你想顺带验一验权限那一半**,再用一个只有采购、没有财务的账号走第 2 步 ——
期望看到的那句话写在第 2 步里。

### 步骤

1. **登记机器。** `财务 → 固定资产` → 右上角「登记一台机器」。
   * **应当看见**:表单顶上一块蓝底说明,把【两扇门】分开讲 ——
     这一张是"已经决定要买、钱还没付";另一张(开支表单的资本勾选项)是
     "当场买断、发票在手"。**读不出区别就是这一条失败了** ——
     选错门的代价是一张成本对不上的卡。
   * **应当看见**:一句说明"这张表单上没有价格,而这是刻意的"。
     **不应当看见**:任何金额/单价字段。
   * 填:名称(例如 `熔炼炉 A`)、取得日、使用年限(月)、类别=设备。
   * 提交后**应当跳到这台机器的卡片页**,编号形如 `FA-2026-xxxx`。
   * **卡片页上应当写着**「还没有记过成本」与「尚未投用」——
     **两句话不一样,而且都不是空白。** 看到空白格就是这一条失败了。

1b. **(若这家机器供应商还没建)登记它。** `供应商 → 新建`。
   * 「供应商类型」多选里**应当有【设备供应商】这一项**(EQP-1c-b-fu 加的 ——
     Tim 第一次走查时四个选项全是电池价值链上的角色,卖机器的一个都不沾)。
   * 「这一家是什么」选**供货商**(goods_supplier)——那句话对机器供应商是真的,
     而且它与上面那个多选回答的是两个不同的问题:一个问能力,一个问他们做哪一行。
   * **已知的一处不完美,看到不必当成缺陷**:这个多选留空是允许的,而
     留空与「一种都不是」在列表页是同一个空格子 ——
     记在 `docs/known-issues.md`,等主数据那一刀处理。

2. **开一张设备采购单。** `采购 → 采购单 → 新建`。
   * 选供应商、币种、下单日。
   * **应当看见**:明细上方一个「材料 / 设备」的**模式开关**,
     旁边一句话说清"一张单要么全是材料、要么全是设备,不能混装,
     请在动手【之前】选好"。
     **这句话必须在你打字之前就在那里** —— 这一条的全部意义就是它:
     等你填完两种行、按下提交才被拒,那次拒绝浪费的正是你刚打的字。
   * 选「设备」。**应当看见**:
     - 「机器」下拉,列出第 1 步那台(格式 `FA-… — 熔炼炉 A`);
     - 数量与单位变成一个**读不了也改不了**的 `1 unit`,旁边一句
       「一行就是一台机器…四台机器是四条行」;
     - 一句「设备行永远不收货」。
   * **不应当看见**(EQP-1c-b-fu 修的就是这三样,Tim 第一次走查时它们还在):
     - 一个可以输入数量或单位的框;
     - **「计价公式」下拉** —— 一台机器有一个谈定的价,不按行情公式结算;
     - **「预计化验」那一段** —— 一台机器没有金属含量。
     三者都是【隐藏】,不是变灰:一个禁用的控件邀请人问「我为什么不能用它」,
     而这里的答案是【这个问题不适用】。
   * 「删除本行」在只有一行时是灰的,**旁边应当有一句话说明为什么**
     (「一张单至少要有一行」)。灰着却不说理由,读起来像是坏了。
   * 填一个估价(例如 100,000)。
     **应当看见**:同一行的「金额」变成 **100,000.00**。
     **不应当看见 0.00** —— 那是 EQP-1c-b-fu 修掉的一个缺陷:此前设备行的
     数量只在提交负载里被换成 1,屏幕上那个「1 unit」只是一段写死的文字,
     于是「金额 = 数量 × 单价」里的数量是空的,**填了价金额也一直是 0.00**。
     它还会往下传:估算总额是各行金额之和,而【按百分比的付款计划】乘的就是它 ——
     一台机器订单上的「30% 定金」会算成 0。看到 0.00 就是这一条回归了。
   * 提交。
   * **权限那一半(可选)**:用只有采购、没有财务的账号打开这张表单并选「设备」。
     **应当看见**:「你看不到资产卡 —— 那需要财务模块的权限。这与"一台都没登记"
     不是一回事。」**不应当看见**:一句"还没有登记过机器"——
     那句话会把一个权限答复说成一个事实陈述。

3. **看采购单页,以及供应商手里那一份。**
   * 采购单详情页的明细行,**机器那一格应当是它的名字**,不是 `—`。
     (EQP-1a 刻意把它留成破折号,理由是"命名它是界面那一刀的事" —— 就是这一刀。)
   * **列头应当写「机器」,不是「物料」**(EQP-1c-b-fu2 修的);
     **不应当看见「计价公式」那一列** —— 它在设备单上永远只能是一个破折号,
     所以整列不出现,而不是留着画横杠。
   * **右上角不应当有「按此单收货」这个按钮**(EQP-1c-b-fu2:隐藏,不是变灰 ——
     机器到厂不是一次收货,那不是一个可以问的问题)。取而代之,页面顶上
     **应当有一句话告诉你机器到了该去哪**(记在它的资产卡上)。
   * **页面下方不应当有「收货差异」与「收货批次」两整节** —— 同样的理由:
     设备行永远没有收货行,那两节会渲染成一排"暂无收货",而那读起来像
     "还没收到货",不像"这件事不适用"。
   * 点「打印/PDF」。**供应商那份上的行名也应当是机器的名字**,而且
     **那张纸上的列头也应当是 Machine**(EQP-1c-b-fu2)。
     行名这一处 EQP-1a 早就修好了(`po_document_data` 里
     `COALESCE(物料名, 资产描述)`),屏幕与纸取的是同一份实现 ——
     **两份不可能各说各话**;若它们仍然不一样,那本身就是缺陷。
   * **付款计划那几行:「on on shipment」这种重复的介词应当没有了**
     (EQP-1c-b-fu2 修的,只改了 PDF 模板那一处;屏幕那侧一直是对的)。
     **注意:你在这一刀之前已经签发过的 v1,里面那个重复的词【原样留着】** ——
     一次签发是"当时发出去了什么"的记录,不因为后来修好了模板就改写。
     那是设计,不是遗漏;**不要重新签发只为了让它好看**。
   * **抬头地址应当只出现一次「Singapore」**,不是
     「25 Haji Lane, Singapore, 189218, Singapore」(EQP-1c-b-fu2)。
     发票那份同理(它此前是"Singapore 189218"下面再来一行"Singapore")。

4. **付定金。** `财务 → 收付款 → 新建`,方向"付出",对象=该供应商,
   核销行挂到这张**采购单**上(不是挂到某张发票上),金额例如 30,000。
   * 回到采购单页,**应当看见**预付合计变成 30,000。

5. **把发票记成一笔开支,挂在那条设备行上。** `财务 → 开支 → 新建`。
   * 勾上「资本支出」。**应当立刻看见两个单选,各带一句话**(EQP-1c-c 加的 ——
     在这之前这张表单【只会新建一张卡】,对一台已登记的机器无路可走):
     - 「这笔支出买的是一台【新】机器」——由这笔支出生出卡并带上成本;
     - 「这笔支出是给一台【已登记】的机器加成本」——**本次选这个**。
     **模式必须是你选的,不是系统猜的** —— 选错的代价不对称:把"加成本"
     错走成"买新机器",会多出一张【撤不回来】的资产卡。
   * 选「已登记」之后:
     - **描述 / 类别 / 投用日 / 年限 / 残值 这几栏应当【消失】**(不是变灰)——
       它们属于【那张卡】,不属于这笔支出;
     - 出现「哪一台机器」下拉,**里面应当有第 1 步那台**
       (只列【还加得上成本】的:尚未投用、未处置);
     - 出现「采购单行(可选)」下拉,**里面应当有第 2 步那条行**。
   * 供应商=同一家、状态=挂账(unpaid)、金额=发票金额。
   * **看一眼下方的过账预览**:借方应当写着 **1500 固定资产-设备**,
     **不是一个省略号**(EQP-1c-c 修的 —— 资本模式下科目下拉是隐藏的,
     此前预览就落到了「…」)。
   * **故意先犯两个错,各看一句话**:
     - 供应商挑成**另一家** → 应当读到
       「采购单 … 属于另一家供应商,与这笔支出上的(…)不是同一家」;
     - 状态选**已付**、且不填供应商 → 应当读到
       「挂在采购单 … 上的支出,必须说出开这张票的供应商」。
       **注意它【不是】"供应商不一致"** —— 拿 NULL 去比不是不一致,是没人说过。
       读到"不一致"就是这一条失败了。
   * **第三个故意的错(可选,但值得看一次)**:如果那台机器【已经投用】,
     「哪一台机器」的下拉里根本不会有它。硬要试的话,服务端会说
     「机器 … 已于 … 投用。从那天起它的成本就冻住了……系统把这个判断交还给你」——
     **不应当读到 `ASSET_ALREADY_IN_SERVICE` 这串字母**(EQP-1c-c 之前会)。

     「成本从哪来」里有一行指着这张开支单;「由哪张单买的」一节应当指着
     第 2 步那张采购单与那一行。**

6. **再记一笔试试。** 同样走「已登记」模式、同一台机器。
   * **「采购单行」下拉里那条行应当还在,但【是灰的】,后面跟着一句
     「已由 EXP-… 报销」**(EQP-1c-c:问题【适用】但被挡住 → 禁用并说明理由;
     只有【不适用】的东西才隐藏。藏起来会让人以为那条行不存在,
     而它就在采购单上明摆着)。
   * 所以这一步**挑不动它** —— 那正是这条推导在界面上该有的样子。
     若你想亲眼看那句服务端拒绝,把这一步留给下面的"故意犯错"清单。

7. **冲抵定金。** 打开第 5 步那张开支单(`财务 → 开支 → 点开它`)。

   * **先故意把冲抵日留空** → 应当读到「冲抵日必填 —— 它决定这笔分录落在
     哪个期间,系统不会替你填。」**这一条是本刀的 X1,它此前默默用"今天"。**
   * 填日期与金额(例如 30,000),提交。
   * 回到机器卡片页:「那张单上的定金」一行**应当显示 已冲抵 30,000、还可冲抵 0**。

8. **试着投用它。** 卡片页底部「投用」。
   * 若你想看那句拒绝:先**新登记一台**机器(第 1 步),对**那台**点投用 →
     应当读到「资产 … 还没有任何成本。资产卡是在【决定要买】这台机器时建的,
     成本随发票到来 —— 请先把发票记到这张卡上。」
   * 对**第 1 步这台**(已经有成本的):卡片页「投用」一节
     **应当写着「可以投用了」,并提醒投用会把成本冻住**。
     填一个投用日提交,**应当成功**,卡片页顶上「投用日」出现那个日期。

### 一路上不应当出现的东西(看到就是缺陷)

## 9 · 设备的一生:保养、停机、保养间隔(EQP-2d)—— **这一条是那一刀【和整个设备模块】的关闭条件**

     (「是 —— 判断为延长了寿命或提高了产能」+ 你写的理由),下面一行小字是
     **系统的建议**,而它这次应当写着 *阈值建议:算不出来 —— 这次活没有挂已过账的
     支出单*。**「算不出来」不是「不达标」** —— 看到「不达标」就是缺陷。

7. **开一段停机,试着开第二段,再把第一段关上。**
   「停机」→「开一段停机」:停机时间填今天某个时刻,原因写 `主轴承异响`,保存。
   * **应当看见**一块**琥珀色、带粗边框**的区块,写着
     **「这台机器现在停着 —— 从 <时刻> 起,还没有人记下它什么时候恢复」**,
     下面一行小字「还在停」。
   * **不应当看见**一段结束时间是空白的普通流水行 ——
     **「开着的一段」与「少填了一栏」在屏幕上必须长得不一样。**
   * **应当看见**那块区块里一句话解释为什么没有「再开一段」的按钮
     (*一台机器同时只能停一次*)。**不应当看见**一个按不下去又不说为什么的按钮。
   * **【故意触发第二条拒绝 —— 要两个标签页】** 这条拒绝在正常操作里
     【碰不到】,因为屏幕不会给你一个服务端保证会拒的按钮。它真实的出现方式是
     **两个人同时开**,所以这样复现:
     1. 在**标签页 A** 打开这一页,**先不要开停机**;
     2. 在**标签页 B** 打开同一页,开一段停机(上面那一步);
     3. 回到**标签页 A**(它还不知道 B 干了什么),点「开一段停机」并保存。
     * **应当看见**这一句,一字不差:

       > **这台机器已经有一段开着的停机了。** 一台机器同时只能停一次 ——
       > 先把开着的那一段结束掉,再开新的一段。如果你并不觉得有开着的停机,
       > 那多半是刚刚有别人开了一段;刷新一下页面就看得见。

     * **不应当看见** `duplicate key value violates unique constraint "uq_equipment_downtime_open"`。
   * **【故意触发第三条拒绝】** 在那块琥珀区块里,把「恢复时间」填成一个
     **早于停机时间**的时刻,点「结束这一段」。
     * **应当看见**:**机器不可能在停机之前就恢复。请检查这两个时间。**
     * **不应当看见** `violates check constraint "equipment_downtime_period_order"`。
   * 把恢复时间改成一个**晚于**停机时间的时刻,结束它。
   * **应当看见**琥珀区块消失,流水表里那一行的「恢复时间」有了值、
     「停了多久」有了时长,而**整行不再是琥珀底色**。

8. **再故意撞两条间隔上的拒绝。**
   * 「保养间隔」→ 那条间隔 →「修改」→ **把公斤间隔填 1000、提前量填 1000**,保存。
     * **应当看见**:*公斤的提前量必须不小于 0 且【小于间隔本身】…
       提前量等于间隔,等于一盏从第一天起就亮着的灯。*
     * **不应当看见** `…lead_kg_shape`。
   * 「加一条间隔」→ 种类仍选 **例行保养** → 随便填个天数 → 保存。
     * **应当看见**:*这台机器的这一种活已经有一条间隔了。请改那一条,
       不要再加一条 —— 同一种活的两条间隔会互相把对方的钟拨回去。*
     * **不应当看见** `…one_per_kind`。
   * 「加一条间隔」→ 种类选 **维修** → **公斤与天数都留空** → 保存。
     * **应当看见**:*公斤、天数,至少写一个。*
     * 然后**取消**,不要真的加这一条(它会给残渣多一行)。

9. **最后看一眼「只记录,不上看板」与「不再监控」是【两件事】。**
   把那条间隔的「到期之后」改成 **只记录,不上看板**,保存。
   * **应当看见**那一行多一个灰色标签「只记录,不上看板」,而**读数还在**;
   * **回首页**:两块牌子都是 0(它不上看板了)。
   * 改回 **上看板**。
   * **点一下「不再监控」但在确认框里选取消** —— **应当看见**确认文案说清楚
     这两者的区别(*…如果你只是不想让它上看板,请把这条间隔改成「只记录,
     不上看板」—— 那样读数还在*)。**不要真的删**,留着它。

### 一路上不应当出现的东西(看到就是缺陷)

* 任何一串 **`violates check constraint "…"`** 或 **`duplicate key value violates …"`**
  的裸约束违例 —— 本刀把设备三张表的 **16 条约束**全部接上了句子,
  出现裸约束名就说明漏了一条;
* 任何**全大写下划线的机器码**(`MAINT_*` / `DOWNTIME_*` / `INTERVAL_*` / `ASSET_*`);
* 「保养间隔」一节里出现 **「未到期」而不是「未监控」**(第 1 步),
  或者一个**没有诚实提示的 `0 公斤`**(第 3 步)—— 这两条是本刀的核心;
* 一块**把「已到期」和「将到期」合起来数**的牌子;
* 一段**开着的停机**看起来像「结束时间忘了填」;
* 一个**按不下去又不说为什么**的按钮;
* 「阈值建议」把 **「算不出来」显示成「不达标」**(空不是零);
* 首页某块牌子显示 **「受限」**,而你点进那一页却看得见数据
  —— 那是把"你看得见"说成"你看不见"(EQP-2d 修的正是这一处)。

4. **第 8 步三条被拒的间隔一条都不落库。**

**这些都不过账 —— 三张表一分钱都不动总账**(`equipment_maintenance` 的表注

## 10 · 进料的五条状态轴,以及它们的门(PROC-2b)

> **【这一节是【加进来的】,不是走过的】** PROC-2b 只写了这些步骤,一步都没有走。
> 不要把它读成"验证过了"。**它与 §8 / §9 一起,等 Tim 的同一次坐下。**
> 排在 §9 之后:§9 关的是设备模块,这一节开的是加工重建的第一扇门。

**为什么需要人点:** 五条轴 PROC-2 就建好了,而在 PROC-2b 之前【一个都填不了】。
更要紧的是 **PROC-3 那道闸**(拒绝未放电的料进炉)**在有人能记下"这批货已经放过电"
之前是建不出来的** —— 这一节走的正是那条路。

**在生产上走。** 它会写库:一种物料的三条轴,以及一批进料货的安全状态与化学体系确定度。

### 走之前
用一个同时持 `module.materials.edit` 与 `module.inbound.edit` 的账号(admin 即可)。

### 步骤

1. **看"不适用"是怎么说话的 —— 这一步是本刀最要紧的一屏。**
   `物料 → 登记一种物料`。**先什么都不选。**
   * **应当看见**形态、来源、规格尺寸三块各是一行灰底的话:
     *先选种类 —— 这一条适不适用要看它。**这【不是】"不适用"**,是还不知道。*
   * **不应当看见**三个空下拉,也不应当看见【什么都没有】——
     一个没有解释就消失的控件,与一个加载失败的控件长得一模一样。
2. **选「包装材料」。**
   * 三块应当变成:*不适用:包装材料 不回答状态轴。只有电池料才有形态、来源与规格尺寸。*
   * **注意那句话里的"包装材料"是从字典里读出来的** —— 换一种种类,那个词跟着变。
   * 「可以被投进加工吗」那两个钮**应当整个消失**,换成一句"这个问题由种类回答"
     —— **不应当**看见一个禁用的、预选在"不可以"上的钮(那还是一个默认值)。
3. **改选「电池料」。** 形态与来源变成真的下拉;**规格尺寸【还是】一行灰底的话**,
   而且换了一句:*先选形态 —— 这一条适不适用要看它。*
   * **这两句话不一样,而它们必须不一样** —— 一句说"要看种类",一句说"要看形态"。
     写一句话会有一半时候是错的。
4. **形态选「黑粉」。** 规格尺寸那一行应当变成:
   *不适用:黑粉 不需要拆解,所以没有"来自哪一类应用"可记。*
5. **形态改选「整包」。** 规格尺寸这才变成一个真的下拉,而且**以「请选择」开局** ——
   **不应当**预选任何一项。
6. **【故意触发两条拒绝】**
   * 种类选电池料、形态留「请选择」→ 保存。**应当看见**:
     *这一类物料必须说出【形态】与【来源】。两者都永远不会替你填。*
   * 形态选「黑粉」之后,若你有办法让规格尺寸带上值(例如先选整包+某个规格,
     再把形态改回黑粉),保存 → **应当看见**:
     *黑粉 不需要拆解,所以没有"来自哪一类应用"可言。规格尺寸请留空。*
   * **两条都不应当出现** `violates check constraint` 或 `MATERIAL_...` 这样的机器码。
7. **把这种物料建出来**(电池料 / 黑粉 / 退役料 / 可以投料),记下它的编号。
8. **到一批进料货上记状态。** `进料 → 任意一批 → 编辑`,滚到「到货状态」那一块。
   * **应当看见**五个复选框**一个都没勾**,下面一句琥珀色:
     *这批货【没有记过任何安全状态】。那的意思是**没有人记过**,不是"这批货是安全的"。*
   * **勾上「进过水」与「破损或变形」两个** —— 一批货可以同时是两者。
   * 「带电未放电」「进过水」等旁边**应当看见**一句小字「记录为不可投料」;
     **而它今天不拦任何人**(闸在 PROC-3)。
9. **化学体系确定度:那条界必须摆在你面前。**
   * 下拉以「— 没有记过 —」开局。**应当在下拉【下面】看见**:
     *「已知混合」的意思是你【知道】它是混的 —— 一个确立的事实。
      如果你分不出来它是什么,那是「待识别」,不是「已知混合」。*
   * **这句话不出现就是缺陷** —— 站在一个乱糟糟的集装箱前面的人,
     最容易把"我分不出来"选成"已知混合",而那两个的后果完全不同。
   * 选「待识别」,保存。
10. **再回来把它改掉 —— 这一步是 PROC-3 的前提。**
    把安全状态改成只勾「已放电并核验」,保存。
    * **应当看见**保存之后只剩那一个 —— 保存是【整组替换】,不是往上加。
    * **这一步证明的是那个【转变】记得下来**:一批货到的时候带电,后来才放电并核验。
      **只在收货时记一次,PROC-3 那道闸就永远无法被满足。**

### 一路上不应当出现的东西(看到就是缺陷)

* 任何 `violates check constraint` / `violates foreign key constraint` 的裸约束名;
* 任何 `MATERIAL_*` 的全大写机器码;
* 一个**没有解释就消失**的控件(第 1 步);
* 「不适用」与「还不知道」**说同一句话**(第 3 步);
* 任何一个**预选好的**下拉或勾选框;
* 「没有记过安全状态」被显示成一片空白,而不是那句话(第 8 步)。

### 残渣

一种新物料(带三条轴)、一批货上的安全状态行与确定度。**都不过账。**
走完请记进 `docs/known-wrong-until-cutover.md`,与 §8/§9 的残渣并排。
