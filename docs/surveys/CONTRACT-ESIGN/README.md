## Tim's rulings (2026-10-30, after Step 0) — verbatim
Grilling's scope changes 1–7 accepted (signing vs activation, the signatory owns their signature, a server-computed sha256 for every version,
pdf-lib 1.17.1 with password-protected PDFs refused by name, F settled by evidence, the added questions, and the clarifications).
- **Q1** (changed from the recommendation): signing is allowed only on ACTIVE contracts (terms already approved through the CFO activation request), so the company never signs terms that are not yet approved. Uploading or replacing the unsigned contract file is allowed on draft and active contracts. Suspended, expired and terminated contracts cannot be signed. Activation does not require a signed file; the CFO approval path is unchanged.
- **Q2** Uploading the countersigned scan sets signed_on to that day if it is empty; our side's signing date is shown from the signing record.
- **Q3** New code action.manage_signatories, granted to admin only; it covers the signatory list and the stamp. To sign, a person must be on the list and able to read that contract; action.contract_terms is not required.
- **Q4** Each signatory, logged in as themselves, draws their signature on screen once; it is stored as their own specimen; replacing it keeps history; admin cannot set it for them. At signing the specimen is placed with a printed line: name, title, time (SGT) and "signed electronically in Evoltrya OS".
- **Q5** Signing requires re-entering the password, checked on the server without replacing the session; the check is recorded with the signature.
- **Q6** (c). The signatory picks page and position on a preview, with the last page, bottom right, pre-selected; the stamp is placed the same way when chosen.
- **Q7** A signatory or admin can void a signed version with a written reason, before or after the countersigned scan; the voided PDF stays stored and listed as "void"; after a void the file can be replaced or signed again; removing someone from the list never voids what they signed.
- **Q8** The contract file needs the contract's read rule plus that side's price code; otherwise it shows 「受限」 with the reason.
- **Q9** Exactly one of our signatures per version in v1; multiple signatories are queued as a later cut.
- **Q10** Holders of action.contract_terms upload the countersigned scan, PDF only, and only after our side has signed.
- **Q11** No public verify page in v1; the hashes are listed on the contract page.
- **Q12** 25 MB for contract files, set on the bucket; the portal's 10 MB is unchanged.
- **Live proof**: the throwaway contract must be ACTIVE before signing; activate it through the real CFO activation path inside the proof only if that can be done with throwaway accounts and fully removed afterwards; otherwise prove the signing path on the local rebuild and prove on live only what does not need an active contract (upload, refusal of signing on a draft, the signatory list, the specimen, the stamp), and say which. → **the latter** (the CFO decision writes an append-only `approval_log` row and needs the real cfo role — neither can be fully removed).
- **Split**: do not split.

## Step 1 — what was built
- **Migration** `db/migrations/2026-10-30-contract-esign.sql` (built from the mirrors by `db/scripts/build_contract_esign_migration.py`): code `action.manage_signatories` (admin only) · tables `contract_signatories` · `signature_specimens` · `company_stamps` · `contract_files` · 19 functions · buckets `contract-files` (private, 25 MB, PDF) and `signing-assets` (private, 1 MB, PNG) with four storage policies (upload / read each; no update, no delete) · change-log bindings for the four tables.
- **App**: contract page — section 「合同文件」 (`app/contracts/[id]/files/`: versions with sha256, upload original / countersigned straight to storage, void with reason; 「受限」 without the side's price code) · `/contracts/[id]/files/[fileId]` (stored bytes, sha256 re-checked, 409 on mismatch) · `/contracts/[id]/sign` (pdf.js preview, click to place signature / stamp, default last page bottom right, password re-entry) · `/settings/signatories` (list, add / remove, company stamp) · `/me` 「My signature」 (draw once, only for people on the list).
- **Password re-entry (Q5)**: the server action signs in again with the typed password on a separate, non-persisted client (the browser's session is untouched), runs every signing step with that token, then signs that one session out (`scope: 'local'`). `contract_sign_begin` reads the token's `amr` password time and refuses if it is older than 5 minutes; that time is stored on the signed row (`password_verified_at`).
- **Fonts**: the printed line uses Helvetica when it is all Latin; with Chinese it embeds Noto Sans SC whole (+≈1.4 MB) — fontkit's `subset: true` drew blank glyphs (measured, `docs/known-issues.md` CONTRACT-ESIGN-CJK-FONT-ADDS-1-4-MB).
