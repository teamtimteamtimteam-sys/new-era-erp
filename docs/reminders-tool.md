# 提醒(`/tools/reminders`)—— 它是什么,它对谁显示什么

**CONV-7 ①(2026-09-04)。** 首页的「当前待办」整块搬到这里,并【重画】。
`operations_now` 那 34 支的**规格**仍然住在 `docs/dashboard-arm-inventory.md` ——
本文件不复述任何一支的谓词,它记的是**搬家这件事**、**权限的实测**、
以及**界面为什么长成这样**。

---

## 1 · 为什么搬(Tim 的裁定,不要重开)

信号**天生跨模块**,所以把它们拆回各自的模块会丢掉「一眼看完所有该操心的事」
这件事本身。给它们一个**自己的去处**,人就是**想看的时候去看**,而不是一登录
就被推一脸 —— **那正是安静的首页得以成立的前提。**

首页因此只剩下:零模块权限的那句话、两条**不带任何数字**的链接(提醒 · 月结),
以及「我的」两张卡。

> **首页那条「提醒」链接为什么留着** —— CONV-0 在 `/pricing` 上裁过的区别:
> **可达(reachable)与找得到(findable)不是一回事。** 提醒在工具菜单里有自己
> 的条目,所以它可达;而首页是所有人**一直用来看待办的地方**。这条链接
> **不印任何计数** —— 它不推,它只指路。

## 2 · ★ 权限:立项时怀疑的那个洞【不存在】,而实测把它钉死了 ★

立项时的怀疑是:这些牌子长在人人都看得见的首页上,**可能今天就是不分权限
地画给所有人**;一旦搬进工具,就成了绕过权限系统读数据的路。

**实测结论:那个怀疑是错的。每一支被查两道,而且两道用同一个码:**

1. **库那一侧** —— `operations_now` 末尾那个 `WHERE`:
   `(has_permission(permission) OR has_any_permission(arm_permission_widen(item_type)))
    AND (arm_permission_any(item_type) IS NULL OR has_any_permission(arm_permission_any(item_type)))`
   无权的支**整支缺席**(不是零)。
2. **页那一侧** —— `allows(specFor(arm), perms)`,与视图**逐字同形**。
   无权的支画成**具名的受限**,而且**根本不开门**(不查、不给链接)。

### 2.1 逐角色实测(2026-09-04,live 授权)

| 角色 | 看得见几支 / 34 | 看得见 `hr_alerts` |
|---|---|---|
| `admin` | 34 | 是 |
| `auditor` | 34 | 是 |
| `gm` | 34 | 是 |
| `finance` | 26 | 否 |
| `operations` | 16 | 否 |
| `cfo` | 15 | 否 |
| `procurement` | 14 | 否 |
| `warehouse` | 11 | 否 |
| `sales` | 9 | 否 |
| `hr` | **3** | 是 |
| `employee` | **0** | 否 |

**0 到 34。这不是"不分权限"。** `employee`(零权限)在这一页上看到的是一句
**具名的话**(`reminders.nothingVisible`),不是一张白页,也不是 34 个零。

### 2.2 两侧对同一个人给出同一个答案(实测,并做过故障注入)

用【页面自己那两个模块】(`lib/modules.ts` 的 `allows()` × `lib/reminders.ts` 的
`REMINDERS`)对 11 个角色的 live 权限集逐一求值,与库那一侧同一个谓词的答案
**逐支**对比:

```
roles compared: 11   mismatches: 0
```

**故障注入(必做,否则这条比较可能什么都没比):** 把 `wht_due` 那一条的
`permission` 从 `module.finance.view` 改成 `module.hr.view`,同一次比较立刻报出
**三处**、且方向正确:

```
MISMATCH cfo:     db-only=['wht_due']  page-only=[]
MISMATCH finance: db-only=['wht_due']  page-only=[]
MISMATCH hr:      db-only=[]           page-only=['wht_due']
```

改回之后 `mismatches: 0`。**这是 fixture 45「两侧对同一个人给出同一个答案」
那条断言在渲染层的同形物。**

### 2.3 遮蔽视图上那条更难的分界(人力 Overview 用得上,记在这里)

一个只持 `module.hr.view` 的读者(临时角色,已回滚):

| 观察 | 值 |
|---|---|
| `operations_now` 可见行 | 0(三支 HR 臂**可见但为零**,其余 31 支**缺席**) |
| `hr_alerts` 可见行 | 7 |
| `employees_masked.monthly_salary` | **6 行全为 NULL(遮蔽)** |
| `employees_masked.monthly_salary_set` | **6 行全可读** |
| `gl_control_reconciliation(CURRENT_DATE)` | `PERMISSION_DENIED\|module.finance.view` —— **按名拒绝,不是一个自信的 0.00** |

> ★ 第三、四行是**「必须由权限分,不能由值分」的证据** ★
> 值那一侧**分不出来**:无权读者拿到的是 `NULL`,而"这个人没录工资"也是 `NULL`。
> 所以两页都是**先判权限,再决定查不查**。

## 3 · ★ 一处实测出来的缺陷:两支【在库里活着、在屏幕上不存在】★

搬家时逐支对账,发现视图有 **34** 支而首页只有 **32** 块牌子:

| 支 | 状态 |
|---|---|
| `promise_overdue` | 谓词在 · i18n 键在 · fixture 111 数着它 · **fixture 138 正面断言它** · 门牌规格写在 `dashboard-arm-inventory.md` 第 273 行 · **屏幕上没有** |
| `wht_due` | 同上(规格在第 274 行);**而且 `app/finance/wht/actions.ts:28` 写着「首页那一支 `wht_due` 的谓词刚刚变了」并为它 `revalidatePath('/')`** —— 代码相信那块牌子存在 |

**五处已经对齐,唯独渲染那一处漏了,而没有任何一样东西看着渲染那一侧:**
fixture 111 钉的是**视图**的支列表(它管不到 TypeScript);
check-i18n 钉的是**键**的后缀集合(它只保证有一句翻译,不保证有人渲染)。
**两道检查各自盯着一半,中间那一格谁都没有看。**

### 修的是「漏得掉」这件事本身

* 清单只有一份:`lib/reminders.ts`。
* `scripts/check-reminder-arms.mjs` 进了 `npm run build`,把它与
  `db/views/operations_now.sql` 的 `item_type` 字面量**逐支**对齐,多一支少一支
  都当场红并点名。
* **故障注入四次,全部红→绿:** ① 删一支 → 点名 `wht_due`;② 加一支不存在的
  → 点名 `zzz_not_in_view`;③ 把名字的字符集从 `[a-z0-9_]+` 写窄成 `[a-z_]+`
  → **两边同时丢掉三支带数字的臂,集合仍然相等,印一个绿勾(只是数字从 34
  变成 32)**;④ 因此加了一道独立计数(数 `AS item_type` 出现几次)——
  再注入 ③,当场红并说出「解析器的字符集写窄了」。
  **③ 是这条检查最值钱的一次注入:它证明"一个恒绿的比较"能长在哪里。**

## 4 · 界面:为什么不是把那 35 块牌子搬过来

### 4.1 旧样子,量过的

35 块**一样大**的牌子(34 支 + HR 一块),每块一个 `text-3xl` 的数字。
而 live **34 支里只有 12 支有行**,共 **42 件事**:

| 支 | 件数 | 等最久(天) |
|---|---|---|
| `allocation_stale` | 8 | 61 |
| `metal_quote_stale` | 7 | 36 |
| `fx_rate_gap` | 6 | 37 |
| `output_unsold_aging` | 5 | **86** |
| `po_awaiting_receipt` | 5 | 30 |
| `margin_cost_not_allocated` | 4 | 31 |
| `free_time_expiring` | 2 | 20 |
| `container_documents_late` | 1 | 15 |
| `container_no_arrival` | 1 | 14 |
| `credit_over_limit` | 1 | **61** |
| `invoice_overdue` | 1 | 5 |
| `work_order_overdue` | 1 | 19 |

**22 支为零。** 也就是说屏幕上三分之二的面积、以及三分之二的大号数字,
说的都是「没有事」。**Tim 指的就是这个。**

### 4.2 四条改法,以及各自的理由

1. **零不再是一块牌子。** 只有真的在等的支画成块;为零的支收进底下一行,
   **把名字全列出来**。
   > **零没有被藏掉,它被降了重量** —— 这两件事不一样,而它们的差别就是
   > 这一页有没有在骗人。
2. **排序是【等了多久】,不是清单顺序。** 最久的在最上面。
   `days_waiting` 是视图自己算的(`CURRENT_DATE - item_date`),
   **首页从来没有 `select` 过它**。于是这个数的基准是**数据库的当天**,
   不是渲染进程所在时区的今天。
3. **块的大小跟着它的分量走。** 一支等着 8 件事的块比等着 1 件的块高 ——
   这正是"一样大"要治的病。每块最多列 **8** 件(首页是 5:
   首页是路过,这一页是专程来看的地方,**同一个数在两种处境下不是同一个判断**)。
4. ★ **那个 `text-3xl` 的灰色「受限」没有了。** ★
   `app/components/ui/refusal.tsx` 的抬头点名过它:「一个 `text-xs` 的药丸放进
   `3xl` 的位置读起来像一枚走丢的标签」,并写着「**本刀不动它 …… 记在这里,
   给转换到那一页的那一刀。**」**那一处就是首页的 `tileBox`,而这一刀就是那一刀。**
   处置:大号数字位整个不存在了,受限回到它该有的尺度 —— 一枚 `<Refusal>` 药丸,
   与全站其余四十处同一种画法,而且**药丸里带着具名的权限码**。

### 4.3 三堆,永远分得开

| 一节 | 什么 | 为什么单独一节 |
|---|---|---|
| **正在等** | 有行的支,按等待时长排 | 这一页的正文 |
| **此刻没有在等** | 看得见、而此刻为零的支,**名字全列** | 「真的零」 |
| **需要其它模块的权限** | 看不见的支,`<Refusal>` 药丸 + 权限码 | 「你看不见」 |

**后两节永远不合并。** 合并就是把「我看得见,它此刻没有事」与「我看不见」
说成同一句话 —— OPS-14 与 D5 反复在治的正是这个。

### 4.4 `hr_alerts` 自成一节

它有一个别的支都没有的维度:**严重度**(`expired` / `critical` / `warning`)。
硬塞进按天数排的清单就要把三档压成一个天数,而「准证已经过期」与
「证书 60 天后到期」不是同一件事的两个刻度
(EQP-2c 那句「两支而不是一支带等级」讲的是同一条道理,方向相反:
`hr_alerts` 的等级**在库里就是一列**,不该在这里被抹平)。

`days_remaining` 可以为 `NULL`(`salary_not_set` 没有期限)——
**印一个 0 天就是把「没有期限」说成「今天到期」**,所以那一格整个不画。

## 5 · FUNCTION 复核:34 支里有两支【不该是提醒】

按 `dashboard-arm-inventory.md` 自己那条判据复核:

> **必须是一个等待状态,不是一个状态。……若没有任何人力所能及的动作能让这一行
> 消失,它就不是一支。**

**32 支通过。两支没有:**

| 支 | 为什么不通过 | 它是什么 | 家应该在 |
|---|---|---|---|
| `work_order_variance_beyond` | 它是**关于一炉已经跑完的活的事实**。调查不改变那两个数;**唯一能让灯灭的动作是把阈值调高,而那一克料都没动** | 一个**发现**,不是一个队列 | **运营 Overview**:「本期有几炉超阈、合计差多少」 |
| `output_unsold_aging` | 补救是「卖掉它」,而卖不是想做就做得成的动作;**改一下产出日同样能让它安静** | **存货的一个状态** | **库存 Overview**:「成品里多少公斤 / 多少钱压了 60 天以上」 |

> **本刀没有撤掉它们。** 撤一支要动视图(一次迁移)+ fixture 111 的 `v_expected`
> + i18n 的后缀集合,**而它们要去的那两页正好都在本刀没建的五页里** ——
> 先撤会造出一个信号无家可归的空窗。
> **返回条件写在 `docs/module-overview-basis.md` §6:** 建运营 / 库存 Overview 的
> 那一刀把对应那一支一起搬过去,并按规矩把它那一行移进「考虑过又排除」。

**另外六支带着一个【已知隐患】,不是缺陷,原样点名保留:**
`safety_stock_below` · `output_unsold_aging` · `work_order_overdue` ·
`work_order_variance_beyond` · `equipment_service_due` · `equipment_service_approaching`
—— 它们落地的那张页面上**都能通过改一个阈值 / 一个日期让灯安静,而一件事都没做**。
这是判据之外的事,**不是不给链接的理由**(逐支的理由写在 `lib/reminders.ts` 各条注释里)。

## 6 · 菜单:工具从四条变成五条

顺序:**任务 · 日历 · 单位换算 · 提醒 · 定价**。
提醒排在定价**之前**,因为定价是这份菜单里唯一一条**自己还带着孩子**的条目
(它那一页列出公式 / 计价器 / 金属行情),把一条平的条目插到它后面会读成
它的第四个孩子。

**注册表判据【刻意】恒真(`{ all: [] }`),与 `/tools/calendar` 逐字同理** ——
这一页没有自己的权限模型,挡人的是每一支。给这一条挂一个模块码,就等于替 34 支
**各不相同**的判据挑一个代表:挑谁都错。

> **「菜单有没有地方假设它是四条」—— 查过了,没有。**
> `ModuleBar` 逐条渲染、`ScrollPanel` 自带「还有 N 条」、
> `lib/moduleAccess.ts` 的分组是按 `MODULE_GROUPS` 表算的。
> 唯一值得记一笔的是 `MODULE_GROUPS.tools` 里那个**空的** `tools.group.pricing`
> (CONV-0 ②a 之后没有条目属于它)—— 渲染层的「空组不渲染」把它滤掉,
> 所以工具仍然画成平铺的五条。**这一条是读出来的,也被冒烟走过。**
