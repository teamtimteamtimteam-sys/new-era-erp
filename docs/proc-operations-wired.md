# 零 · ★★ 本刀最要紧的一条:深度放电今天根本跑不了 ★★

**而挡住它的不是 `NO_OUTPUTS`。**

盘问阶段量到的两件事:

* `inbound_safety_states.charged_not_discharged` 的 **`may_be_fed = false`**;
* `guard_processing_input` 对任何带着不可投料状态的投料抛
  `INPUT_SAFETY_STATE_NOT_FEEDABLE`。

> **于是这道闸拒绝投喂的,恰恰是深度放电存在的全部理由那一种料。**
> 一块没放过电的电池是唯一需要放电的东西,而它不许被投进任何东西。
> **两条拒绝互相指着对方** —— 与 PROC-BUILD-1 的 fu1 修掉的那个死锁同一个形状。

**这条发现改变了本刀的形状。** 按 brief 原本的写法(建字典 + 放松 `NO_OUTPUTS`),
深度放电**仍然跑不了**,而那样的一刀会报告成功却什么都没演示。

**根因:`may_be_fed` 答的是一个问错了的问题。** 它今天的意思是"可不可以投给
【任何】工序",而它真正的意思是"可不可以投给【转化型】工序"。
深度放电的全部目的就是**受理**充电状态并把它清掉。

# 一 · 这一刀是 1B-i,不是整个 1B —— 三刀,不是一刀缩了水

判据是**一刀演示一件事**:

| 刀 | 内容 | 演示的那一件事 |
|---|---|---|
| **1B-i(本刀)** | 工序字典 + `operation_type_code` + 逐工序安全受理 + 直通式工序 | **深度放电真的跑得起来** |
| **1B-ii** | M4(产出批安全状态)+ 在制品可见性 | 自产中间物也过得了那道闸 |
| **1B-iii** | R6 采购时的判断 | 判断与实际都记得下,差异看得见 |

**为什么这三件分得开:**

* **M4 不是改一道守卫,是【一张还不存在的表】。** 安全状态今天**只有进料批有** ——
  没有 `output_batch_safety_states`,所以那道闸不是"不问产出批",是**问不了**。
  它要一张表、一道适用性守卫、一个录入界面、一个回填裁定 —— 第二件可演示的事。
  **而 1B-i 不需要它**:Tim 的路线里整包与模组是**到货时就带电的**,
  所以放电跑在**进料批**上。
* **R6 碰不到加工单。** 判断在采购订单行,实际在进料批,两条路都不经过
  `commit_processing_run`。而且 `grn_discrepancies` **已经是那个形状** ——
  它已经把预期与实际配对,并且**缺一侧时给 NULL 而不是 false**
  (`assay_beyond_tolerance` / `declared_delta_qty` 两处都是)。扩它一列即可,
  不要建第二套差异机制。

# 二 · 那个死锁怎么解的:逐工序的受理清单

`operation_type_safety_states` —— 与两张形态表**同形**的 N×M 关系。

> ## ★ 不变式:只许收紧,不许默认放宽 ★
>
> * **没有工序类型** → `may_be_fed` 仍然是答案,**今天的行为一个字不变**;
> * **有工序类型** → **只有明写在清单里的才受理,没写的一律拒**,
>   哪怕它 `may_be_fed = true`。
>
> 也就是说:**声明一道工序只会把闸收紧;任何放宽都必须是一行明写的数据。**

**这条不变式是 Tim 的硬要求,而 fixture 159 的 F1/F2 两臂分别钉住它的两半。**
两次故障注入实测它是承重的:

* **注入"设了工序就放行"(默认放宽)→ 159F2 报红;**
* **注入"状态改变型一律放行"(按 kind 的旁路)→ 159F3 报红。**

后者尤其要紧:一个按 kind 放行的实现会让**一块鼓包漏液的电池进放电机**,
而放电机解决不了它。**这是全系统唯一一道失败后果是【起火】而不是【数字算错】的闸。**

## 五道工序受理什么(R2 的座次)

| 工序 | 种类 | 受理的安全状态 |
|---|---|---|
| 深度放电 | 状态改变型 | **未放电(并解决它)** · 已放电 |
| 人工拆解 | 转化型 | 已放电 |
| 自动极片线 | 转化型 | 已放电 |
| 极片粉料线 | 转化型 | 已放电 |
| 整电池粉料线 | 转化型 | 已放电 · **未放电** · **变形损坏** |

**整电池粉料线受理未放电与损坏,是 R2 明写的**(它专收"放不了电的整包/模组/
3C 电池/损坏电池")—— 那正是它与极片粉料线是**两台设备**的理由。

> ### 【鼓包漏液今天一道工序都没有受理,而那是刻意的】
> R2 点名"损坏电池",**没有点名鼓包漏液**。漏液是与变形不同的一种危害,
> 而这是那道起火闸 —— **不确定时站在拒绝那一侧**。
> 于是这种料今天没有路线。**它等 Tim 的一句裁定,不等一个猜测。**

# 三 · 直通式工序:放松 `NO_OUTPUTS` 是这件事里最小的一块

**只放松那一个检查会【毁掉批次】。** 逐条:

| 只放松 `NO_OUTPUTS` 会怎样 | 本刀怎么做 |
|---|---|
| 投料循环 `drain_stock` + 扣 `remaining_qty` → **100 kg 的批次归零**,货还在院子里 | **不扣库存**,料【穿过】工序 |
| `loss_qty = COALESCE(p_loss_qty, 100 - 0)` = **100 kg 损耗** | `loss_qty = 0`(**真的是 0**:放电不带走质量) |
| 质量账读成"投了 100 出来 0" | `total_input = total_output = 通过量` |
| 成本分摊无处可落 | **按名拒绝**(见第五节) |

**投入腿照记** —— 那是【通过量】,记的是"这批料走过这道工序",不是"被吃掉了"。
设备用量与工时因此仍然读得到它。

## R3 的"改状态"落在哪

`operation_types.resulting_safety_state_code` +
`operation_type_safety_states.resolves`。提交一张状态改变型加工单时:
**被解决的那些状态从批次上删掉,再写上结果状态。**

> **不删的话,一批放完电的货会永远带着"未放电",于是下一道工序仍然拒绝它 ——
> 那个死锁只是换了个位置复发。** fixture 158 D4/E 两臂钉住这一条。

## 【已测量】没有任何视图会因此说出假话(Tim 的下游问题 1)

| 读者 | 口径 | 直通式跑过之后它显示什么 |
|---|---|---|
| `equipment_usage` | **读表头,不重算腿**(它的文件头原话) | 投入 100 / 产出 100 / 损耗 0 —— **真话** |
| `equipment_service_status` | 读表头 `total_input` | 累计通过量,真话 |
| `processing_runs_masked` | 原样透出三列 | 真话 |
| `processing_run_loss_breakdown` | `loss_qty` 与分类之和 | 0 与 0,**差额 0** —— 真话 |
| `processing_metal_recovery_all` | 从腿聚合 | **一行 `recovery_blocked_by = 'output_not_measured'`** |

> **最后一行是本刀唯一一处措辞上的不准确,写下来而不是悄悄改掉:**
> 一炉放电**按定义就没有产出**,所以"产出没测量"读起来像"有人忘了化验",
> 而正确的说法是"**不适用**"。**它不是假话,是话没说准**;
> 而这个仓库为"空的两种意思"付过很多次账。
> **归 1B-ii 顺手修**(那一刀本来就要动回收率那一侧),不在本刀扩大范围。

# 四 · 什么拦得住一张【真】的加工单不填工序 —— 今天:没有东西

`processing_runs.operation_type_code` **可空**。

* **界面必填**(下拉,不预选 —— 预选一道工序等于替人断言这一炉在跑哪台机器);
* **数据库不拦。**

**这句话照直说,而不是发明一条约束。** 一条 `NOT NULL` 会把线上 13 张历史单
**就地冻住**,而它们是测试残留 —— **绝不给它们猜一个工序**(猜出来的工序与真的
工序长得一模一样,而它会流进设备用量、回收率、工单实绩)。

一条 `NOT VALID` 的 `CHECK` 可以只管新行,但那要一次裁定:"**从今天起加工单
必须说出工序**"。**那是产线跑起来那天的事。** 记为具名缺口。

# 五 · 成本:★ 停下来报告 —— Tim 的裁定与线上一条不变式撞上了 ★

**Tim 裁定:状态改变型工序的成本【资本化回它自己的投料批】。**
按令先测量、后动手,而测量的结果是**不能照着做**:

> ## `inbound_batches.unit_price` 是【应付之锚】
>
> * 表头原话:**「应付 = quantity × unit_price,**改价即改欠款**」**;
> * `db/views/ap_open_items.sql` 是**实时**这么算的:
>   `round(ib.quantity * ib.unit_price, 2) - 已结 - 已用定金`;
> * 这一列还被 `trg_inbound_batches_price_guard` 守着,
>   只能经 `set_inbound_unit_price()` 改动,而那条路会写 `price_history`
>   并把耗过它的加工单标记过期。
>
> **所以把我们自己的电费加到 `unit_price` 上,会当场增加我们【欠供应商】的钱。**
> 供应商没有因为我们放电而多一分债权。而走 `reprice_inbound_batch` 那条路,
> 等于把一笔加工成本**记成一次重新议价**——一条假账,外加一串虚假的过期标记。

**本刀因此【不】实现资本化,并按 Tim 的明令停下来报告。**

## 但本刀堵住了那个【静默】

今天对一张零产出腿的加工单:

* 按**价值**基准 → `NO_METAL_VALUE`(它已经会拒);
* 按**重量**基准 → `v_total_basis = 0`,`NULLIF` 之后除法得 NULL,
  **没有腿可更新,于是它什么都不做、还返回成功**。

**一次"报告成功却什么都没分摊"的调用,正是本仓库反复付账的那种假绿灯。**
所以本刀让它**按名拒绝**(`ALLOCATION_STATE_CHANGING_UNRESOLVED`),
把那个开着的会计问题说出来 —— **记下缺口,不替它作答**。
fixture 159F7 钉住它;注入"把这条拒绝拿掉"→ 报红。

> ### ★ 这一节【已经过期】—— PROC-COST-1(2026-08-31)把那条拒绝换掉了 ★
>
> **`ALLOCATION_STATE_CHANGING_UNRESOLVED` 不再存在**,
> `guard_allocation_not_state_changing` 也已经退役(删掉,而不是留着不被调用 ——
> 一个永远不被调用的守卫读起来像是还有一道闸在那里)。
> 成本现在**资本化回投料批**:借 `1200` / 贷 `5xxx`,载体是
> `batch_processing_cost_allocations`。**fixture 159 F7 跟着改了**:
> 它钉的从"按名拒绝"换成"那笔钱确实落在了那批料身上" ——
> 它要防的那种实现(什么都没做、还返回成功)一个字没变。
>
> 上面这一段**保留不删**,因为它记着那次停下来的理由,而那个理由是对的:
> 一条占位的拒绝,好过一个替 Tim 作答的实现。
> 全部去处见 **`docs/proc-cost-capitalisation.md`**。

## 要 Tim 裁的那一条 —— **已裁,已建(PROC-COST-1)**

需要的是一个**与 `unit_price` 分开的成本载体**:应付**不读**它,存货估值**读**它。
那是新结构 + 一次会计裁定(借方落在哪个科目),外加 Tim 已经点名的四件:

**只许落在这一炉真的投料批上**、以及**单位成本变了之后每一个读者都要读到新数**。
~~**本刀一件都没建**~~ —— 它们全部依赖那个还不存在的载体。

> **PROC-COST-1 把这五件都建了**,一件一支 fixture(160 的 F1–F5),

# 七 · 遮蔽表加一列 = 三件事,而主刀只做了一件(fu1)

`processing_runs` 是一张**遮蔽表**(列级授权 + `_masked` 伴生视图)。
主刀加了列,**忘了另外两件**。线上实测(改之前):

```
has_column_privilege('authenticated','processing_runs','operation_type_code','SELECT') = false
同一张表上 equipment_id                                                              = true
```

**这一列存在,但每一个登录用户都读不到它** —— 界面上那个工序会永远显示成空,
**而且不会有任何报错**。`fu1` 补了列级授权与 `_masked` 视图。

> **要问的不是"这一列敏不敏感",而是"这张表【是不是】遮蔽表"** ——
> 后者是一个可以查的事实(有没有 `_masked` 伴生),前者是一个判断,而判断会漏。
