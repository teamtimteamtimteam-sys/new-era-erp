* **C(勾选 → 批量动作),2 页。** 它要的**不是行内编辑** —— 它的格子里只有勾选框,

## ② 编辑故事的六个答案(委托 ③a–f),每一条连着理由

### a · 行级编辑状态:在编辑什么,能不能同时编两行?

**一次一行是默认;全行同时是显式的第二种模式。两者【共用同一个状态形状】——
`Record<行键, 草稿>`,而「一次一行」就是这个 Record 被约束到【至多一个键】。**

**理由:** 仓库今天对这个问题有**两个互相矛盾的答案**,而且两个都是对的 ——
`LeaveTypesEditor` / `ScaleEditor` 用 `editing: string | null`(**两行同时编辑
在构造上不可能**),`MySelfAssessmentPanel` / `QuoteLinesEditor` / `AttendanceGrid`
用 `Record<id, 值>`(**每一行开局就能改**)。
两者的分界不是口味,是**这张表是不是账簿**:
一本账簿是被【逐行修正】的,而一张自评表是**一次坐下来填完的**。
正因为状态形状同一,这不是两个组件;正因为约束是显式的,它也不是一个含糊的默认值。

### b · 脏值追踪:读者怎么知道这一行有未保存的改动?

**把草稿与【由当前这一行现算出来的草稿】比一次。永远不存 `dirty` 布尔。**
界面上两处:有改动的行第一格挂一枚「未保存」,以及**没有改动时「保存」是禁用的**。

**理由:** 一个 `dirty` 布尔是**第二个真相来源**,它可以和它所描述的那些值不一致;
一次比较不会。而草稿与原行本来就都在手边,所以这次比较是免费的。
(今天零处追踪脏值:三张 A 的「保存」只在 `pending` 时禁用,「取消」直接丢弃不问。)

### c · 保存粒度;失败时那一行保留打好的字还是回滚?

**整行保存。失败时【保留】打好的字,行【留在编辑态】,而且【不刷新】。**

**理由:** 这不是一条新裁定 —— **两张 A 今天就是这么做的**
(`if (r.error) setError(r.error)`,不清 `editing`/`draft`,`router.refresh()`
只在成功那一支)。本刀只是把它写下来,那是最便宜的一种决定。
☞ **为什么失败时【禁止】刷新,一句话连着理由:**
**从服务端重画这一行,会把人正要去改的那些输入毁掉。**
(一条带着理由的规矩活得下来;一条不带理由的规矩会被后人「顺手整理」掉。)
**逐格保存被否掉:** 写库那一侧收的是整行 patch,逐格意味着一次编辑要 N 次往返。

### d · ★ 正在编辑第 3 行时点了排序 / 翻页 ★

**在类型上禁掉:可编辑的表【不能】声明排序,也【不能】声明分页 ——
`sorting?: never` / `pageSize?: never`,写上去【编译不过】。**

**理由,而它是本刀最要紧的一条:** CONV-1 点名这是「没有人设计过的交互」。
本刀逐个量过那 10 张:**没有一张有用户可控的排序或分页。**
(`/hr/reviews` 与 `/pricing/calculator` 读 `searchParams`,但那是**筛选**。)
也就是说那是一个**零个真实例子**的交互 —— 而照着零个例子做设计,
正是 PAGE-0 与 CONV-1 各自付过一次账的那件事。

> ☞ **它带来一个比任何提示都硬的后果:委托里那条「**绝不允许静默丢弃打好的字**」
> 从此是【构造上成立】的,而不是靠谁记得。** 那条规矩不再需要任何人执行它。
> 将来真有一页同时需要编辑与排序,**那是一个真实的例子**,到那天再设计。

### e · 脏着离开这一页 —— **IDLE-DRAFT 覆盖不了,这是一条写下来的限制**

**本刀【不给网格留草稿】。** 只做一件事:脏着时挂 `beforeunload`
(管**关标签页与刷新**)。**站内 `<Link>` 跳走会丢掉半行输入 —— 声明过的限制。**

**理由,四条机械上的,不是口味:** `useFormDraft`
① 靠 `new FormData(form)` 取值 —— 网格**没有 `<form>` 元素**;
② 靠往 `form.elements.namedItem(name)` 写 `el.value` 恢复 ——
网格的输入是 **React 受控的**,直接写 DOM 会在下一次渲染被丢掉,**永远到不了 draft**;
③ 按 `name` 属性认字段 —— 网格的输入没有 name;
④ 它的 `subject` 是**一条**记录的 `updated_at` —— 一张网格有 N 行 N 个指纹,
那个陈旧性判据**没有一个单一的值可以落**。
(顺带量过:全仓库 `beforeunload` 0 处、`confirm(` 0 处 —— 今天没有任何导航拦截。)

**为什么不做站内拦截:** Next 16 的 App Router 没有提供稳定的导航拦截器,
为此去 monkey-patch `history` 是这个仓库不做的那类事。

> ### ★★【一条记录在案的例外:本系统里唯一一次【说不出理由】的拒绝】★★
>
> **浏览器自己拥有那个对话框的措辞,我们改不动它。** 也就是说,在一个
> **处处按名拒绝、而且拒绝必须说明理由**的系统里,这一处拒绝是**哑的**。
>
> **Tim 的裁定是照收,理由写在这里:把打好的字悄悄弄丢,比一次哑的拒绝更坏,
> 而哑的那个至少看得见。**
>
> ☞ 后来的人:**这是一条带着理由的例外,不是一次疏漏** ——
> 也**不能**被引用成「再来一个哑拒绝」的先例。

## ③ ★ FORK DECISION:`EditableTable` 是 `DataTable` 的【姊妹件】,不是重复 ★

**没有扩展 `DataTable`,另起了 `app/components/ui/editable-table.tsx`。**

**理由:** `DataTable` 的列描述符是 `render: (row: T) => ReactNode` ——
**那是一个纯只读契约**。它是一个函数,它**没有地方存放**「这一行正在被编辑」、
「这一行有一次 pending 的保存」、「这一行上一次保存报了什么错」。硬塞只有两条路,
两条都更坏:让页面把编辑状态提到外面再从闭包里捞回来(等于把状态机摊给每一页);
或者给 `DataTable` 加第二套分支(**让只读那条路也一起变复杂,而走只读那条路的有 70 页,
走编辑的只有 3 页**)。

**复用了什么(一件都没有重写):** `ListPage` 外壳 · `RefusalBlock` / `RefusalPage` ·
**notices 槽** · `PhoneTreatment` **这个类型本身**(从 `data-table.tsx` import)·
以及那道手机闸 —— `scripts/check-datatable-phone.mjs` 现在**同时**检查两个组件,
判据只有一份。

> 它们服务两种契约,而这个仓库为「一个组件伺候两个主人」付过五次账。

## ④ 手机:**编辑发生在展开区里,不在格子里**

委托问:「一行【能不能】在展开器里被编辑,还是编辑需要另一套手机方案?
如果诚实的答案是『暂时只支持桌面』,就明说。」

**答案是:能,而且在手机上那是【唯一】的编辑处。不是桌面专用。**

| | 桌面(≥640px) | 手机(390px) |
|---|---|---|
| 只读 | 全部列在表里 | priority 列在表里,其余进展开区(与 CONV-1 同形) |
| **编辑中** | **在格子里就地编辑** | **格子仍是只读的**;一进编辑态**自动展开那一行**,把**每一个可编辑字段**画成展开区里带标签的一竖列(`dt`=表头,`dd`=输入),**整宽、有标签** |
| 动作钮 | 动作列 | **展开区末尾**(`min-h-11`,够得着) |

**为什么不是「把 `<input>` 塞进格子」:** 390px 上表是 `table-fixed`、列宽平分,
一个输入框会被压到几十像素宽;而 priority 列**留在上面那一行**正是为了让人
**认清自己在改哪一行** —— 展开区里那一竖列没有主语的话,人不知道在编辑谁。
**这也是为什么「一列 priority 都没有」在这里同样是一条按名拒绝**
(`EDITABLETABLE_NO_PHONE_COLUMNS`):展开区会失去主语。

**动作列在手机上【不画】** —— 而这不是省事,是**转换前那三页溢出的直接原因**
