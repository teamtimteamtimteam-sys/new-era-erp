### 2.2 处理：**只有裁剪一件事**

★ Tim 的裁定：**不要过度柔化，主体必须认得出 —— 看得见森林与海。**
所以判据是**测量**，不是审美：压到够用，然后停手。逐项照直写：

| 参数 | 值 | 由什么决定 |
| --- | --- | --- |
| 裁剪 | 原图上 **950 行**（2279×950） | **测量驱动**，见 2.3 |
| 对比度压缩 | **无**（不动） | 测量说不需要 |
| 去饱和 | **无**（不动） | 测量说不需要 |
| **模糊** | **无，一点都没用** | 见下 |
| 遮罩（scrim）峰值 | **α = 0.88** | **测量驱动**，见 2.4 |
| 遮罩最外一档 | α = 0.07 | ★ **这一个是眼睛挑的** |

> **★ 为什么一点模糊都没用 ★**
> 字标的对比度**来自遮罩，不来自把主体糊掉**。模糊确实能抬高局部最暗值
> （它把暗像素和亮邻居平均掉），但那是**用毁掉主体的方式**换对比度 ——
> 而主体正是这条裁定要保住的东西。遮罩能在**不动主体一根像素**的前提下
> 达到同一个数字，所以模糊没有存在的理由。
>
> **只有 α=0.07 那一档是挑的。** 它让照片在卡片投影底下沉一点点；
> **把它改成 0 不会破坏任何一条实测要求。** 其余每一个数都能复算。

### 2.3 裁剪为什么是测量驱动的

按行测亮度剖面，最陡的落差（= 地平线）在原图 **26.5%**（第 338 行）。
字标带落在**视口 12–30%** → 经 `.layer` 的 `inset:-10%` 换算 → **图像 18.3–33.3%**。

**不裁的话，字标带会横跨地平线、压在深蓝的海上** —— 那里最暗的像素 L=0.0166，
**比字标本身还暗**；遮罩要压到 α=0.92 才够，而那样海与天空会一起被洗掉。
裁到上 950 行之后，地平线落到 **35.6%**，于是：

* 字标带（18.3–33.3%）**整个落在天空上** —— 遮罩只要 0.88；
* **海（35.6–45%）与林冠（45% 以下）都在遮罩【外面】**，原样看得见。

这正是「主体要认得出」与「字标要够 3:1」两条**同时**成立的那个裁法。

`object-position: 50% 0%`（顶对齐）同样是测量驱动的：`cover` 在**宽而矮**的视口上
要裁掉纵向，默认居中会把视口顶端映射到图像更深处（海、甚至林冠），
字标带就不再落在天空上。顶对齐之后，任何视口下字标带映射到的图像行**只会更靠上** ——
**保证因此是单向成立的**，不依赖某一个视口尺寸。

### 2.4 ★ 一个必须照直说的发现：Ocean 在任何照片上都扛不住 3:1 ★

`--brand-ocean #008EBC` 的相对亮度 **L = 0.2298**。要让底色比它**亮** 3:1，
底色的 L 必须 **≥ 0.7893** —— 换算成 sRGB 约 **230 以上，接近白**。

而这张照片：**最亮的一朵云** L = 0.9001 → 对 Ocean 只有 **3.40:1**；
天空本身 L ≈ 0.36 → **约 1.5:1**；未裁时字标带最暗的像素 L = 0.0166 → 比字标**还暗**。

> **这张照片没有任何一处能【原样】扛住 Ocean 的 3:1。**
> **这不是这张照片的问题，是品牌主色本身的性质** ——
> BRAND-1 §3.2 已经为「主色扛不动白字」记过同一件事的另一面。
> 结论：**字标底下必须有一层接近白的遮罩，这是算术，不是品味。**
> 想让字标在照片上更响而不加遮罩，只能换字标的颜色 —— 那是改品牌，不是改这一页。

实测（对**真正发出去的那个 AVIF** 量，连压缩噪点一起算）：

```
α=0.78 → 2.96:1     α=0.82 → 3.10:1     α=0.86 → 3.20:1
```

取 **0.88**，给色彩配置与不同分辨率留余量。

**遮罩是纵向线性渐变，不是径向。** 径向在字标两端的**角上**会掉出平台区，
而字标是一条横贯整幅宽度的文字 —— 保证必须对**整条宽度**成立。
纵向渐变里不透明度只依赖 y，于是「这条带子上处处 ≥3:1」是一句
**可以直接验证、也可以直接反驳**的话。

停止点：`0.88 @0%` → `0.88 @31%` → `0.34 @41%` → `0.07 @50%` → `0.07 @100%`。
31% 之后迅速让开，**海与林因此回到画面上**。

**遮罩仍然不参与视差**（会动的只有照片那一层），所以对比度地板依旧是一个**不变量**。

### 2.5 换图仍然只改一处

`app/login/BrandField.tsx` 里的 `PHOTO` 常量。两档尺寸用 `<picture>` 的 `media` 显式指定，
**不用 `srcset`+`sizes`**：这一层是 `object-fit:cover` 的满幅底图，在竖屏手机上会被放大到
视口高度的 2.4 倍宽 —— 浏览器按 `sizes` 估出来的宽度和真正渲染的宽度差一个数量级，
选出来必然偏小。`media` 是确定的。

### ★ 那条逼出来的不变量，原样有效 ★

> ★ **底图上只放字标，一个字都不放。凡是要被读的，都在不透明的卡片上。** ★

**换成照片之后这条不变量的价值反而更大**：照片的明暗随裁剪、随视口、随视差变，

## 4 · variant C,以及三处**刻意的**偏离

沿用:宽松密度、品牌实心按钮、浅色填充片式的拒绝态、卡片式版面。三处偏离,都有理由:

| # | sampler 里的 C | /login | 为什么 |
| --- | --- | --- | --- |
| ① | 卡片 `shadow-md` | `shadow-lg` | 它浮在一块**有起伏的底**上,不是白纸上;差一档就分不开 |
| ② | 输入与按钮 `h-8`(32px) | `h-11`(44px) | 手机上的**主操作**要够得着。44px 是 Apple HIG 与 WCAG 2.5.5 都指的那个数 |
| ③ | 焦点环 `ring-ring/50` | 实心 `--brand-ocean`,`ring-2` + offset | **实测半透明那一档对白底只有 1.6:1**,达不到 1.4.11 的 3:1。实心是 3.75:1 |

③ 值得单独记一句:vendored 进来的 shadcn 组件写着 `outline-none`,
**它把浏览器默认焦点框换掉了** —— 而 FE-0 记着「默认焦点框完好」是这个前端为数不多的可及性资产。
在 /login 上那个资产**是被替换掉的**,替代品经过实测(3.75:1)。别的页面没动。

## 5 · Google Sans:**只管这一页**,以及一个必须先知道的事实

### 怎么作用于本页

`next/font/google` 的 `Google_Sans` 在**构建期**取回并自托管(运行时不打 Google 的服务器)。
作用域靠两样东西**同时**成立:

1. `app/login/page.tsx` 里 `<main className={googleSans.variable} style={{ fontFamily: 'var(--font-google-sans)' }}>` —— 只有这棵子树继承;
2. `app/globals.css` 的 `body { font-family: Arial, Helvetica, sans-serif }` **一个字节没动** —— 全站仍然是 Arial。

**构建产物层面的证据**(不是靠命名纪律):那个 Google Sans 的 CSS 分块
被 **exactly 2 个页面清单**引用 —— `app/login` 与 `app/brand-sampler`。**其余 217 个页面清单里没有它。**

### ★ 先知道这件事,再决定要不要推广 ★

实测构建产物:**75 个 `Google Sans` 的 `@font-face` 块、25 个 woff2 分片,
覆盖 CJK(U+4E00–9FFF)的:0 个。** Google Sans 有 25 个 subset,**没有 `chinese-simplified`**。

**而这一页的文案默认是中文。** 于是「把 /login 换成 Google Sans」实际改掉的字形是:

* 标题里的 `EVoltrya OS`、
* **人自己打进去的那个邮箱地址**、
* 按钮上英文 locale 时的 `Sign in`。

**中文一个字都没变** —— 它落到 fallback 链里的系统字体(Mac 上 PingFang SC、Windows 上微软雅黑)。
这不是退化:body 现在是 Arial,中文本来就落到同一批系统字体。

> **推广到全站要付什么:**
> 一次改 187 个页面的样子(R3 当初就是为这个不让 BRAND-1 动 body);
> 而**换来的是英文与数字的字形**,**中文那一半原样不动**。
> Tim 应当在**看过这一页**之后、并且**知道上面这句话**之后,再决定要不要推广 ——
> 不要在以为那是一次「换字体」的前提下推广。
>
> 真要推广,做法是把 `body { font-family: Arial… }` 换成品牌 token 链,
> 并且**同时**为中文选一个明写的字体 —— 那是**两个**决定,不是一个。

字体账:latin 分片是**可变字重**,400/500/700 共用同一个文件 —— **35 KB,一次,之后走缓存**。
另外 24 个分片(希腊、西里尔、天城文、希伯来、泰、高棉、符号、emoji…)磁盘上共 905 KB,
但 `unicode-range` 决定了:**页面上没有那些字符,浏览器一个都不下载**。

## 6 · 状态:一个都没少,而且**多了两个真话**

| `data-login-state` | 到达方式 | 说什么 |
| --- | --- | --- |
| `clean` | 直接来登录 | 什么提示都没有(**这是对的**,SESSION-1) |
| `invalid` | `?error=invalid` | 「邮箱或密码错误」+「请检查邮箱有没有打错,以及密码的大小写。」 |
| **`unconfirmed`** | `?error=unconfirmed` | 「这个邮箱还没有完成确认」+「**你的密码没有问题** —— 是账号还差最后一步。请打开发给你的邀请邮件,点里面的确认链接;找不到那封邮件,就请管理员重发一次。」 |
| **`throttled`** | `?error=throttled` | 「尝试太频繁了,请过几分钟再试」+「为了不让别人靠猜试出密码,系统把这个邮箱的登录尝试暂时挡住了。等几分钟再试一次即可 —— **你的账号没有被锁死**。」 |
| `ended` | `?reason=ended` | 「你的登录已经结束」+「重新登录即可继续。上一页里打过的内容没有被保存。」 |
| `ended` + 拒绝 | 两者并存 | **会话结束排在前面** —— 「你为什么在这里」是先发生的那件事 |

### 为什么加后两个

`app/login/actions.ts` 此前把 `signInWithPassword` 的**每一种**失败塞进同一条分支:

```ts
const qs = new URLSearchParams({ error: 'invalid' })   // ← 原文
```

于是**一个密码完全正确的人**被告知密码错了。
**这不是假设:Choo Er TEH 的账号尚未确认邮箱,而她是审批链的第一级。**
一句说错原因的判词,会让人**一直去改那个本来就对的东西**。

这条规矩本仓库已经写过两遍,都在别的层 —— `lib/permissions.ts:37`(查询失败 ≠ 没有权限)、
`lib/supabase/middleware.ts`(判断不出 ≠ 没有会话)。**这是同一句话的第三处落点。**

判据用 auth-js 的 **`error.code`**(一个约定好的闭集),不用 `message`(那是给人读的英文散文,随时会改)。
限流额外认 `status === 429`,因为它可能由 auth 前面的网关给。

> ★ **认不出来的一律退回 `invalid`,不许现编一个原因。**
> 万一哪天上游不再送 `code`,这里退回的是**那句最弱、但仍然为真的话** ——
> 代价照直写:那时 Choo Er 那一类人会重新看到一句没用的话,**但不会看到一句谎话**。

## 7 · R7 · 可及性:每一条都验过**服务器真的发出去的字节**

| 落地前(实测基线) | 现在 |
| --- | --- |
| 两个 `<label>` **都没有 `htmlFor`**(FE-0:全仓库 713 个 label 里 474 个没关联,这两个在其中) | `for="email"` / `for="password"`,配 `id` |
| 两个 input **都没有 `autoComplete`** | `username` / `current-password` —— 密码管理器认的就是这一对 |
| 错误只是一个 `<div>`,**没有 role、没有焦点** | `role="alert"` + **把焦点移过去** |
| **没有提交态** | 按钮 `disabled` + `aria-busy` + 名字换成「登录中…」 |

**关于「错误被念出来」——这里有一个很常见的假绿,点名记下:**
登录失败在本系统里是一次**重定向**,浏览器加载的是**一份新文档**。
而 live region **在文档加载时就已经存在**的内容,读屏软件通常**不念**(它播报的是「后来变化的东西」)。
**所以光挂 `aria-live`/`role="alert"` 是不够的。** 做法用 GOV.UK 的 error-summary 那一套:
`tabIndex={-1}` + 挂载后 `focus()` —— 焦点移过去,内容必然被念到。
`tabIndex={-1}` 保证它**不进 Tab 顺序**:键盘用户不该为了走到邮箱框而先按过一条通知。

**两类话画法不同,因为它们不是一回事:**
拒绝是 `role="alert"` 并抢焦点;会话结束是 `role="status"`,**不抢焦点** —— 它是背景交代。

**★ 未确认与限流时【不】标 `aria-invalid` ★**
那个人**打进去的值是对的**。把框标成 invalid,读屏软件会念「无效」——
**那是同一句谎话换了一层壳**,正是这一刀要修掉的东西。只有 `invalid` 那一种才标。

**颜色不是唯一信号:**判词写在**标题的字面**里,填充色只是第二重提示;
正文一律用 `--brand-text`,于是对比度**不依赖语气色**(12.25:1 / 12.52:1)。

### 一个会误导下一个人的实测细节

**React 19.2.4 把 `autoComplete` / `inputMode` / `enterKeyHint` / `autoCapitalize` 原样按驼峰写进 HTML**
(实测 `renderToStaticMarkup`:`tabIndex`→`tabindex`,但 `autoComplete` 不变)。
HTML 的属性名**大小写不敏感**,浏览器解析时会小写掉 —— **所以这是对的,不是 bug**。
但 `grep 'autocomplete='` 会得到一个**假阴性**。已上线的 `/set-password` 也是同样的写法。

## 8 · 视差:**不引 motion.dev**

R5 要的是:两个自定义属性,由一个经 rAF 节流的 `pointermove` 写在 `.page` 上,
每一层带一个 `--d`(位移上限),全部位移交给 `transform` 走合成器。**约 40 行,零运行时。**

motion.dev 会为「动两个 div」加进一个新依赖(约 30 KB gzip)和一层客户端边界。
**它真正值钱的东西 —— 弹簧物理、layout animation、编排序列、退出动画 ——
恰恰是 R5 明令禁止的那些**(「绝不是跟着光标跑的物件,绝不抢走表单的注意力」)。
**一个什么都没换来的依赖,就是一个该拒绝的依赖。**

阻尼是怎么来的:`pointermove` 每帧写一次变量,`transition: transform 260ms` 让层追着新值走 ——
**反复被打断的 transition 就是一个 lerp**。弹簧能做得更漂亮,但这里不需要更漂亮。

> **留给以后的人:**如果哪天真要做全站的动效编排,**那一刀去付这个依赖的账、并且自己论证它**。
> 别拿这一页当先例 —— 这一页的结论是「这里不需要」,不是「永远不需要」。

**降级是两侧各自成立的**,不是靠一侧记得停:

* CSS 侧:`@media (prefers-reduced-motion: reduce) { .layer { transform: none !important } }`
* JS 侧:`matchMedia` 两道闸 —— `(hover: hover) and (pointer: fine)` 与 `(prefers-reduced-motion: reduce)`,
  都监听 `change`;关掉时**把变量归零**(否则会停在最后一次鼠标位置上,那是一个「冻住的偏移」,比不动更奇怪)。

**手机上不是「视差很小」,是这个交互根本不存在** —— 没有精确指针就连监听都不挂。

## 9 · 窄屏:说清楚**不一样在哪**,而不是指望桌面版缩下去

* 高度用 **`100svh`**(先写 `100vh` 兜底)。iOS 的 `100vh` 把地址栏算进去,首屏底部会被裁掉、滚动时还会抽动。
* 卡片 `width:100%` + `max-width:26rem`,外面 1rem 的边距 —— 在 320px 宽上也不会顶到边。
* 字标 `clamp(9.5rem, 42vw, 14.5rem)`:下限保证它在最小的手机上仍然认得出,上限保证它在大屏上不变成招牌。
* 纵向留白 `2.5rem → 4rem`(≥640px),手机上不浪费首屏。
* 输入框 `text-base`(16px):**低于 16px 时 iOS 会在聚焦时自动放大整页**,那是这一屏最烦人的一个小毛病。
* 输入与按钮 44px 高(见 §4 ②)。
* `inputmode="email"` / `autocapitalize="none"` / `autocorrect="off"` / `spellcheck="false"` / `enterkeyhint`。
* 底图用 `position:absolute` 铺满,**不用 `background-attachment: fixed`**(iOS 上要么不生效要么很卡)。
* 视差不挂(见 §8)。
* 底图的渐变按**百分比**定位,所以竖屏是**重新构图**,不是把横屏裁一条。

### ★ 照片这一项，是「主体要认得出」那条裁定的价钱 ★

LOGIN-1 报告过：**处理过**的 1280 底图只要 2.3–4.5 KB（AVIF），因为压对比度会把

```
重度处理（LOGIN-1 的做法，已作废）   1280 → 2.3–4.5 KB
不做处理（fu1 的裁定，现行）          1280 →   52 KB     1920 → 101 KB
```

**换算成一句话：让主体保持认得出，在手机上每次登录多付约 52 KB。**
这是一个**明码标价的取舍**，不是一次疏忽 —— 把它写在这里，是为了将来

（另外那 199 KB 的语言包不是：见下。）

### 那 199 KB 仍然不值得，而且仍然不是这一刀造成的

两套完整语言包，中文与英文全量，在**人还没登录**之前就下载完。
实测 **189 个页面清单**引用同一个分块 —— **全站每一页都在付**，
`/login` 只是最刺眼的那一处。修它要按 locale 切分，牵动 187 个页面，**是另一刀**。

## 12 · fu1 修掉的两个缺陷，以及一个顺带抓到的

### 12.1 登录页画着应用外壳

Tim 的截图上，`/login` 顶上有：产品名、当前登录的邮箱、通知铃、语言切换、
登出按钮，以及整条模块导航。

**为什么会这样：`app/layout.tsx`（根布局）无条件渲染 `<TopNav />` 与 `<IdleWatcher />`。**
它是**根**布局，所以每一条路由都套着它，`/login` 也不例外。

但真正的原因还要再往下一层：**TopNav 自己【早就】写着「确立地没登录 → 不画」**
（源码注释原话：「登录页本来就没有导航」）。所以对一个真正登出的人，它本来就是空的。
它之所以出现，是因为**那个人其实是登录着的** —— 也就是 12.2 那个缺陷。
**两个缺陷同一个根。**

处置**两道都做**，因为「因为不会发生所以不用管」不是一条结构：

1. **12.2 的重定向**：登录着的人根本到不了这一页；
2. **根布局结构性排除**：`isPublicPath(pathname)` 为真时不渲染外壳。
   认证**判断不出**时 TopNav 会画一条说明横幅，那一条在登录页上同样不该出现；
   而重定向哪天回归了，外壳也不该跟着回来。

pathname 从哪来：**服务端组件拿不到当前路径**（RSC 没有这个 API）。
中间件把它放进 `x-pathname` 请求头，根布局读它。
**为什么不用路由组**：那才是 Next 的标准做法，但要把 200 多个路由目录整个搬进
`(chrome)/`，一次与本刀无关的巨大改动，收益完全一样。
**为什么不在客户端判**：客户端组件返回 null 只是不挂载，TopNav 的服务端取数
（getUser、权限查询）照样会跑，导航数据照样进 RSC 负载 —— **那不叫「没有外壳」**。

**影响面**：`PUBLIC_PATHS` 今天只有 `/login`，所以只改这一页。
`/set-password` 与 `/welcome` 不在其中，照旧有外壳（对的：那两页的人已经有会话）。
对登出状态的人，屏幕上**没有任何变化**（TopNav 本来就返回 null）。
真正变掉的只有两种人：登录着的（现在根本到不了）与认证判断不出的
（不再在登录页上看到那条横幅）。

### 12.2 登录着的人被再问一次「请登录」

同一张截图就是证据：顶栏写着 `admin@swm-os.test` 并提供「登出」，
而页面正中要**同一个人**登录。**两句话互相矛盾，其中一句必然是假的。**

**判据放在中间件**（`lib/supabase/middleware.ts`），理由三条：

1. 中间件**已经**问过 auth 了。放在页面里就是同一个请求里问**第二次** ——
   实测有效会话那一次要 **2.3 秒**。为一句判断给每次登录页访问加一趟往返，不划算。
2. 「登录着 / 确立地没登录 / 判断不出」这个三分**只在那里成立过一次**（七情形实测表）。
   在页面里重做一遍，就是把那张表重新实现一遍；一旦实现得不一样
   （比如把 `AuthRetryableFetchError` 当成「没登录」），一次瞬时认证故障
   就会变成「把人送进应用」或「把人挡在门外」。
3. 重定向发生在**渲染之前**，登录页的 HTML 一个字节都不会生成。

**条件带 `!idleExpired`**：空闲超时的人 `user` 仍然非空（cookie 还在）。
把他送进应用，下一跳又会被判过期弹回 `/login` —— 两跳才停，中间那跳毫无意义。

**SESSION-1 那条刻意的沉默原样保住**：没登录的人干净地打开 `/login` 走不到这条分支
（`user` 为 null），页面照旧**什么都不说**。

**`?next=` 的判据不重写。** 它此前在 `page.tsx` 与 `actions.ts` 里各有一份
「逐字相同」的拷贝 —— **逐字相同要靠人守，而那正是它迟早会不同的原因**。
现在三处（页面、动作、中间件）共用 `lib/loginRoute.ts` 里的同一个函数。

> ★ **顺带堵上一个洞**：原判据是 `startsWith('/') && !startsWith('//')`，
> 漏掉了 `/\evil.com` —— **浏览器解析 URL 时把反斜杠当斜杠**，那个串等价于
> `//evil.com`，一个协议相对的外站地址。判据放行，浏览器跳出去。
> 这一刀把判据搬进了中间件，洞变得更好够得着，所以顺手堵上。已实测：
> `?next=/\evil.com` 现在落到 `/suppliers`。

### 12.3 ★ 顺带抓到的：AVIF 被认证闸口挡住了 ★

底图换成 AVIF 之后，`proxy.ts` 的 matcher 排除清单里**没有 `avif`**：

```
GET /brand/login-field-1280.avif
  → 中间件认为这是受保护路径 → 307 到 /login?next=%2Fbrand%2F…
```

**而请求这张图的人，恰恰是【还没登录】的那些人 —— 登录页的全部观众。**
`<picture>` 一旦按 `type` 选中 AVIF 那一支就**不会再回退到 `<img>`**，
所以屏幕上不是「退化成 WebP」，是**整块底图空白**。

> **它是怎么被抓到的，值得写下来。**
> 断言写的是 `r.ok`，而 `fetch` 默认**跟随重定向** —— 那条 307 被跟到 `/login`，
> 拿回一份 200 的 HTML，**断言绿了**。
> 真正戳破它的是**量字节**：两个不同尺寸的 AVIF 都回了 20 KB，
> 而那正好是登录页 HTML 的大小。
> **一条只看状态码的断言，证明不了拿到的是一张图。**

处置：把 `avif` 加进 matcher 的排除清单，与 `svg|png|jpg|jpeg|gif|webp` 并列。

### 12.4 冒烟为此改了两处（一处必然，一处是为了不丢覆盖）

**冒烟全程带着 admin 会话走路由**，所以 12.2 落地之后 `/login` 对它必然是 307。
第一轮跑出来就是这一条红的 —— **那是对的，它抓到了一次真的行为变化。**

1. `EXPECTED['/login'] = [307]`。**精确写 307，不写 `[200,307]`** ——
   这个文件自己的规矩:「两个都行会静默放过一个开始乱重定向的守卫」。
   在这里 200 就是缺陷:那意味着一个登录着的人又被要求登录一次。

2. ★ **新增一条【不带 cookie】的探针** ★
   只改第一条是不够的:那条钉的是**带会话**的答案，
   而登录页真正的观众是**没有会话**的人 —— 那一半状态门一个字都说不上。
   只改期望值，就等于**把 /login 的 200 路径的唯一自动守卫拿掉了**：
   一个彻底坏掉的登录页(500、空白、或者把所有人都重定向走)照样能让整轮冒烟绿着。

   探针一次断言三件事，各对应一种坏法:
   ① `200` 且有 `name="password"` —— 表单还在;
   ② **没有** `<header>` —— 应用外壳没有回到这一屏;
   ③ `data-login-state="clean"` 且没有 `role="alert"` —— SESSION-1 那条刻意的沉默还在。
