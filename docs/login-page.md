## 2 · 底图：品牌渐变。**照片是【被否决的】，不是【欠着的】**（LOGIN-1-fu2，2026-09-02）

★★★ **不要「把照片补回来」把这一页「做完」。** ★★★
这一节此前两次改口：LOGIN-1 说照片是「明写的未达成」，fu1 说「已达成」。
**fu2 的状态是第三种，也是终态：撤销。** 底图就是渐变，后面【没有】一张待办的照片。

### 2.1 为什么撤

Tim 看过线上真页面后撤掉了它，两条理由都在截图里看得见：

1. **颜色打架。** 照片压倒性地绿，而卡片与主按钮是 Hawaiian Ocean 蓝 ——
   两个主色都不肯让步。这是一个**配色判断**，不是缺陷；渐变用的是品牌自己的两个主色，
   与按钮同源，所以不会打架。
2. **它没有铺满**，上下露出浅色带。**这一条是真缺陷**，根因见 2.2。

加上一条量得出来的：**渐变更快**。照片实测桌面 +101 KB、手机 +52 KB；渐变 **0 字节**。

`app/login/BrandField.tsx` 里那个 `PHOTO` 常量**被删掉了，而不是设成 `null`** ——
一个 `const PHOTO = null` 读起来像「等着被填」，而那正是本刀要排除的误解。
可替换的那层结构留着（底图是什么只由那一个文件决定），但它的内容就是渐变。

**授权原件从来没有进过仓库**：fu1 只提交了处理后的 AVIF/WebP 四个文件，
原件一直在 `~/Downloads/`。fu2 把那四个文件 `git rm` 掉了，`public/brand/` 现在只剩
字标与 sphere 两个 SVG。

### 2.2 ★ 浅色带的根因：给过扫层写了 width/height ★

值得写下来，因为它看起来完全无害：

```css
.layer { position: absolute; inset: -10%; }   /* 想要 120%×120% 的过扫 */
.photo { width: 100%; height: 100%; }         /* ← 就是这一行 */
```

对一个四边 `inset` 都写了的绝对定位元素来说，**一旦 `width` 不是 `auto`，
`left` 胜出而 `right` 被忽略**（`height`/`top`/`bottom` 同理）。
于是那一层的盒子从 `-10%` 只铺到 `+90%`：**右边和下边各露出 10% 没被盖住**，
底下的 `--brand-bg` 透出来。顶部那条则是遮罩把天空洗白的结果。

> **规矩：`.layer` 的子元素不许写 `width` / `height`。** 过扫靠 `inset` 给，盒子自己算。
> 这条规矩现在写在 `login.module.css` 的 `.layer` 抬头上，就在会犯错的地方。

### 2.3 覆盖：三道保险，而且是**结构性**的

1. `.field` 自己有 `background-color: var(--brand-bg)`、`inset: 0` —— **整个视口必被涂到**；
2. `.wash` / `.glow` 的盒子是 `inset: -10%`（120%×120%），**且没有写 width/height**；
3. `.veil` 是 `inset: 0`，径向渐变**最后一个停止点之后颜色继续延伸**，四角不留缝。

过扫余量:该轴的 10%。（历史:视差时期还要盖住最大 26px 的位移，**该轴视口 ≥ 260px**；
视差已撤除，见 §8，这条约束不再有约束对象，但余量本身留着防舍入与缩放下的边缘缝隙。）实测：

| --- | ---: | ---: | :-: |
| 桌面 1440×900 | 144px | 90px | ✓ |
| 手机竖 390×844 | 39px | 84px | ✓ |

## 3 · 对比度：**量出来的，不是看出来的**（fu2 已按【磨砂合成】重测）

★ fu1 的那组数字全部建立在「卡片是不透明的」之上。卡片一旦半透明，
底图就跑到卡上每一段文字的后面去了 —— 所以每一项都**重新量过**，
量的是**合成之后**的颜色，不是 token。

方法：解析 `login.module.css` 里的渐变与 `--login-card-glass`（**读，不是抄**），
在**所有视口**下求「卡片能盖住的底图最暗点」，再按 α 合成，然后算比值。

* 卡后底图最暗点（全视口最坏）：**#DCF0F7**（出现在手机竖屏）
* 玻璃卡面最坏合成色：**#FAFDFE**（不再是 #FFFFFF）
* 实际发出去的 α：**219/255 = 0.8588**（源码写 0.86，压缩器序列化成 `#ffffffdb`）

| 元素 | 需要 | fu1（不透明） | **fu2（磨砂后）** | |
| --- | ---: | ---: | ---: | :-: |
| 标语 `--brand-text` | 4.5 | 14.13 | **13.82** | ✓ |
| 标签 / 正文 `--brand-text` | 4.5 | 14.13 | **13.82** | ✓ |
| **卡内脚注 `--brand-muted-text`** ★约束项 | 4.5 | 4.83 | **4.72** | ✓ |
| 输入框边框（fu2 换了值，见下） | 3.0 | **1.97** ✗ | **3.52** | ✓ |
| 焦点环 `--brand-ocean` | 3.0 | 3.75 | **3.67** | ✓ |
| 按钮文字 `#FFFFFF` on `--brand-ocean-fill` | 4.5 | 4.53 | **4.53** | ✓ |
| 拒绝片正文 on `mix(destructive 12%)` | 4.5 | 12.25 | **12.25** | ✓ |
| 说明片正文 on `mix(ocean 10%)` | 4.5 | 12.52 | **12.52** | ✓ |
| 字标 `--brand-ocean`（在底图上，不在卡上） | 3.0 | — | **3.30** | ✓ |

### ★ 三项【不受磨砂影响】，而这值得说清楚 ★

按钮、拒绝片、说明片的数字**一个都没动**，因为它们**自带不透明底**：
按钮是 `bg-primary`（实心 `--brand-ocean-fill`），两种片是
`color-mix(…, var(--brand-surface))`，而 `--brand-surface` 是 `#FFFFFF` 不透明。
半透明的是**卡片本身**，不是画在卡片上的这些实心块。
（所以 fu2 的任务说明里「按钮 4.53:1 也依赖卡片不透明」这一条**不成立** —— 照直记在这里。）

### ★ 顺带发现并修掉的：输入框边框本来就不合格 ★

shadcn 的 `border-input` 接的是 `--brand-border-strong` `#AEBAC9`，
在**不透明白底**上实测 **1.97:1** —— 也就是说**它在磨砂之前就破着**，
而 WCAG 1.4.11 对「识别输入框所必需的视觉信息」要求 **3:1**。
磨砂把它又压到 1.93:1，所以这一刀不能装作没看见。

处置：`color-mix(in srgb, var(--brand-text) 55%, var(--brand-bg))` = `#7A889C`，
玻璃卡面上 **3.52:1** ✓。（直接用 `--brand-muted-text` 是 4.72:1，对一条边框太重。）
**只改 /login 的输入框**，不动全局 token。

### 那条不变量，原样有效

> ★ **底图上只放字标，一个字都不放。凡是要被读的，都在卡片上。** ★

磨砂之后这条规矩**更要紧**了：卡片不再是一块与底图无关的白纸，
它上面每一段文字的对比度**都取决于底图**。规矩把「要读的东西」限制在
一个**可以整体求解**的面上 —— 于是解一个 α 就把全部文字一次解完。


## 4 · variant C,以及三处**刻意的**偏离

沿用:宽松密度、品牌实心按钮、浅色填充片式的拒绝态、卡片式版面。三处偏离,都有理由:

| # | sampler 里的 C | /login | 为什么 |
| --- | --- | --- | --- |
| ① | 卡片 `shadow-md` | `shadow-lg` | 它浮在一块**有起伏的底**上,不是白纸上;差一档就分不开 |
| ② | 输入与按钮 `h-8`(32px) | `h-11`(44px) | 手机上的**主操作**要够得着。44px 是 Apple HIG 与 WCAG 2.5.5 都指的那个数 |
| ③ | 焦点环 `ring-ring/50` | 实心 `--brand-ocean`,`ring-2` + offset | **实测半透明那一档对白底只有 1.6:1**,达不到 1.4.11 的 3:1。实心是 3.75:1 |

③ 值得单独记一句:vendored 进来的 shadcn 组件写着 `outline-none`,
**它把浏览器默认焦点框换掉了** —— 而 FE-0 记着「默认焦点框完好」是这个前端为数不多的可及性资产。
在 /login 上那个资产**是被替换掉的**,替代品经过实测(3.75:1)。别的页面没动。

## 5 · Google Sans:**只管这一页**,以及一个必须先知道的事实

### 怎么作用于本页

`next/font/google` 的 `Google_Sans` 在**构建期**取回并自托管(运行时不打 Google 的服务器)。
作用域靠两样东西**同时**成立:

1. `app/login/page.tsx` 里 `<main className={googleSans.variable} style={{ fontFamily: 'var(--font-google-sans)' }}>` —— 只有这棵子树继承;
2. `app/globals.css` 的 `body { font-family: Arial, Helvetica, sans-serif }` **一个字节没动** —— 全站仍然是 Arial。

**构建产物层面的证据**(不是靠命名纪律):那个 Google Sans 的 CSS 分块
被 **exactly 2 个页面清单**引用 —— `app/login` 与 `app/brand-sampler`。**其余 217 个页面清单里没有它。**

### ★ 先知道这件事,再决定要不要推广 ★

实测构建产物:**75 个 `Google Sans` 的 `@font-face` 块、25 个 woff2 分片,
覆盖 CJK(U+4E00–9FFF)的:0 个。** Google Sans 有 25 个 subset,**没有 `chinese-simplified`**。

**而这一页的文案默认是中文。** 于是「把 /login 换成 Google Sans」实际改掉的字形是:

* 标题里的 `EVoltrya OS`、
* **人自己打进去的那个邮箱地址**、
* 按钮上英文 locale 时的 `Sign in`。

**中文一个字都没变** —— 它落到 fallback 链里的系统字体(Mac 上 PingFang SC、Windows 上微软雅黑)。
这不是退化:body 现在是 Arial,中文本来就落到同一批系统字体。

> **推广到全站要付什么:**
> 一次改 187 个页面的样子(R3 当初就是为这个不让 BRAND-1 动 body);
> 而**换来的是英文与数字的字形**,**中文那一半原样不动**。
> Tim 应当在**看过这一页**之后、并且**知道上面这句话**之后,再决定要不要推广 ——
> 不要在以为那是一次「换字体」的前提下推广。
>
> 真要推广,做法是把 `body { font-family: Arial… }` 换成品牌 token 链,
> 并且**同时**为中文选一个明写的字体 —— 那是**两个**决定,不是一个。

字体账:latin 分片是**可变字重**,400/500/700 共用同一个文件 —— **35 KB,一次,之后走缓存**。
另外 24 个分片(希腊、西里尔、天城文、希伯来、泰、高棉、符号、emoji…)磁盘上共 905 KB,
但 `unicode-range` 决定了:**页面上没有那些字符,浏览器一个都不下载**。

## 6 · 状态:一个都没少,而且**多了两个真话**

| `data-login-state` | 到达方式 | 说什么 |
| --- | --- | --- |
| `clean` | 直接来登录 | 什么提示都没有(**这是对的**,SESSION-1) |
| `invalid` | `?error=invalid` | 「邮箱或密码错误」+「请检查邮箱有没有打错,以及密码的大小写。」 |
| **`unconfirmed`** | `?error=unconfirmed` | 「这个邮箱还没有完成确认」+「**你的密码没有问题** —— 是账号还差最后一步。请打开发给你的邀请邮件,点里面的确认链接;找不到那封邮件,就请管理员重发一次。」 |
| **`throttled`** | `?error=throttled` | 「尝试太频繁了,请过几分钟再试」+「为了不让别人靠猜试出密码,系统把这个邮箱的登录尝试暂时挡住了。等几分钟再试一次即可 —— **你的账号没有被锁死**。」 |
| `ended` | `?reason=ended` | 「你的登录已经结束」+「重新登录即可继续。上一页里打过的内容没有被保存。」 |
| `ended` + 拒绝 | 两者并存 | **会话结束排在前面** —— 「你为什么在这里」是先发生的那件事 |

### 为什么加后两个

`app/login/actions.ts` 此前把 `signInWithPassword` 的**每一种**失败塞进同一条分支:

```ts
const qs = new URLSearchParams({ error: 'invalid' })   // ← 原文
```

于是**一个密码完全正确的人**被告知密码错了。
**这不是假设:Choo Er TEH 的账号尚未确认邮箱,而她是审批链的第一级。**
一句说错原因的判词,会让人**一直去改那个本来就对的东西**。

这条规矩本仓库已经写过两遍,都在别的层 —— `lib/permissions.ts:37`(查询失败 ≠ 没有权限)、
`lib/supabase/middleware.ts`(判断不出 ≠ 没有会话)。**这是同一句话的第三处落点。**

判据用 auth-js 的 **`error.code`**(一个约定好的闭集),不用 `message`(那是给人读的英文散文,随时会改)。
限流额外认 `status === 429`,因为它可能由 auth 前面的网关给。

> ★ **认不出来的一律退回 `invalid`,不许现编一个原因。**
> 万一哪天上游不再送 `code`,这里退回的是**那句最弱、但仍然为真的话** ——
> 代价照直写:那时 Choo Er 那一类人会重新看到一句没用的话,**但不会看到一句谎话**。

## 7 · R7 · 可及性:每一条都验过**服务器真的发出去的字节**

| 落地前(实测基线) | 现在 |
| --- | --- |
| 两个 `<label>` **都没有 `htmlFor`**(FE-0:全仓库 713 个 label 里 474 个没关联,这两个在其中) | `for="email"` / `for="password"`,配 `id` |
| 两个 input **都没有 `autoComplete`** | `username` / `current-password` —— 密码管理器认的就是这一对 |
| 错误只是一个 `<div>`,**没有 role、没有焦点** | `role="alert"` + **把焦点移过去** |
| **没有提交态** | 按钮 `disabled` + `aria-busy` + 名字换成「登录中…」 |

**关于「错误被念出来」——这里有一个很常见的假绿,点名记下:**
登录失败在本系统里是一次**重定向**,浏览器加载的是**一份新文档**。
而 live region **在文档加载时就已经存在**的内容,读屏软件通常**不念**(它播报的是「后来变化的东西」)。
**所以光挂 `aria-live`/`role="alert"` 是不够的。** 做法用 GOV.UK 的 error-summary 那一套:
`tabIndex={-1}` + 挂载后 `focus()` —— 焦点移过去,内容必然被念到。
`tabIndex={-1}` 保证它**不进 Tab 顺序**:键盘用户不该为了走到邮箱框而先按过一条通知。

**两类话画法不同,因为它们不是一回事:**
拒绝是 `role="alert"` 并抢焦点;会话结束是 `role="status"`,**不抢焦点** —— 它是背景交代。

**★ 未确认与限流时【不】标 `aria-invalid` ★**
那个人**打进去的值是对的**。把框标成 invalid,读屏软件会念「无效」——
**那是同一句谎话换了一层壳**,正是这一刀要修掉的东西。只有 `invalid` 那一种才标。

**颜色不是唯一信号:**判词写在**标题的字面**里,填充色只是第二重提示;
正文一律用 `--brand-text`,于是对比度**不依赖语气色**(12.25:1 / 12.52:1)。

### 一个会误导下一个人的实测细节

**React 19.2.4 把 `autoComplete` / `inputMode` / `enterKeyHint` / `autoCapitalize` 原样按驼峰写进 HTML**
(实测 `renderToStaticMarkup`:`tabIndex`→`tabindex`,但 `autoComplete` 不变)。
HTML 的属性名**大小写不敏感**,浏览器解析时会小写掉 —— **所以这是对的,不是 bug**。
但 `grep 'autocomplete='` 会得到一个**假阴性**。已上线的 `/set-password` 也是同样的写法。

## 8 · 视差:**建过、量过、撤掉了**

> ★ **结论先写在最前面:`/login` 现在没有视差,而且【不要再加回来】。** ★
> 撤除时间 PDF-1(2026-09-02),决定人 Tim,依据是下面这个实测数字。

### 8.1 它曾经是什么

两个自定义属性 `--px` / `--py`(−1…1)由一个经 rAF 节流的 `pointermove`
写在 `.page` 上;每一层带一个 `--d`(位移上限),位移 = `--px × --d`,
全部交给 `transform` 走合成器。约 40 行,零依赖(**当时也没有引 motion.dev,
理由见 §8.4 —— 那一条结论现在依然成立**)。

| 层 | `--d` | 每个轴的行程(两个极端之间) |
| --- | ---: | --- |
| `.wash` | 14px | −14px … +14px,**全程 28px** |
| `.glow` | 26px | −26px … +26px,**全程 52px** |
| `.veil` | — | 不参与位移(对比度地板是不变量) |

### 8.2 ★ 为什么撤掉:**它在屏幕上几乎什么都没发生** ★

实测(1440×900,把两个极端的同一点作差):

```
全屏最大色差 ΔE76 = 1.049   (#f7fbfe → #f3fafd,在 66%,55%)
参考:ΔE ≈ 1.0 是【并排比对、大色块、理想光照】下勉强能察觉的门槛
```

层确实在动,**颜色几乎没变**,于是人看不出有东西在动。而且 ΔE 1.0 那个门槛还是
**静态并排比对**测出来的;鼠标移动时是同一块区域缓慢变化,比并排比对更难察觉。
Tim 之前说「看不见」不是错觉,也不是屏幕的问题。

**根因在底图,不在幅度。** 视差之所以读得出来,靠的是「层移动时,同一个屏幕位置
露出**不同的内容**」。一块近乎均匀的径向渐变**没有内容可以露** —— 移 28px 和移 0px,
那个位置的颜色几乎一样。照片时期它是有东西可动的,但照片已经撤了(§2)。

> 同一个原因也解释了卡片那条 `backdrop-filter: blur(12px)`:实测模糊前后
> 卡片覆盖区内最大色差 **ΔE76 = 0.0495** —— 平滑渐变**没有细节可模糊**。
> 两处是同一件事的两个症状。

### 8.3 ★ 两条「救活它」的路,都被否了 —— 别再走一遍 ★

* **加大幅度**:ΔE 与位移在这种平滑渐变上近似线性,要到 ΔE≈3(明确可见)
  需要大约 **3 倍**,即 `.wash --d ≈ 42px`、`.glow --d ≈ 78px`。
  而过扫余量目前是该轴 **10%**,78px 要求该轴视口 ≥ 780px —— **手机会露边**,
  那正是 fu1 那个「浅色带」缺陷的样子(§2.2)。要走这条路就得同时加大
  `.layer` 的 `inset`,而那会把过扫这条保险一起改掉。
* **让渐变更「有内容」**:把色块做小、做多、对比拉高,视差就有东西可露 ——
  但那与 R2 要的「柔和地浮出来」正相反。

于是:留着一段看不见的动效 + 一个客户端边界 + 一个 `pointermove` 监听,
换来的是 ΔE 1.049。**删。**

## 12 · fu1 修掉的两个缺陷，以及一个顺带抓到的

### 12.1 登录页画着应用外壳

Tim 的截图上，`/login` 顶上有：产品名、当前登录的邮箱、通知铃、语言切换、
登出按钮，以及整条模块导航。

**为什么会这样：`app/layout.tsx`（根布局）无条件渲染 `<TopNav />` 与 `<IdleWatcher />`。**
它是**根**布局，所以每一条路由都套着它，`/login` 也不例外。

但真正的原因还要再往下一层：**TopNav 自己【早就】写着「确立地没登录 → 不画」**
（源码注释原话：「登录页本来就没有导航」）。所以对一个真正登出的人，它本来就是空的。
它之所以出现，是因为**那个人其实是登录着的** —— 也就是 12.2 那个缺陷。
**两个缺陷同一个根。**

处置**两道都做**，因为「因为不会发生所以不用管」不是一条结构：

1. **12.2 的重定向**：登录着的人根本到不了这一页；
2. **根布局结构性排除**：`isPublicPath(pathname)` 为真时不渲染外壳。
   认证**判断不出**时 TopNav 会画一条说明横幅，那一条在登录页上同样不该出现；
   而重定向哪天回归了，外壳也不该跟着回来。

pathname 从哪来：**服务端组件拿不到当前路径**（RSC 没有这个 API）。
中间件把它放进 `x-pathname` 请求头，根布局读它。
**为什么不用路由组**：那才是 Next 的标准做法，但要把 200 多个路由目录整个搬进
`(chrome)/`，一次与本刀无关的巨大改动，收益完全一样。
**为什么不在客户端判**：客户端组件返回 null 只是不挂载，TopNav 的服务端取数
（getUser、权限查询）照样会跑，导航数据照样进 RSC 负载 —— **那不叫「没有外壳」**。

**影响面**：`PUBLIC_PATHS` 今天只有 `/login`，所以只改这一页。
`/set-password` 与 `/welcome` 不在其中，照旧有外壳（对的：那两页的人已经有会话）。
对登出状态的人，屏幕上**没有任何变化**（TopNav 本来就返回 null）。
真正变掉的只有两种人：登录着的（现在根本到不了）与认证判断不出的
（不再在登录页上看到那条横幅）。

### 12.2 登录着的人被再问一次「请登录」

同一张截图就是证据：顶栏写着 `admin@swm-os.test` 并提供「登出」，
而页面正中要**同一个人**登录。**两句话互相矛盾，其中一句必然是假的。**

**判据放在中间件**（`lib/supabase/middleware.ts`），理由三条：

1. 中间件**已经**问过 auth 了。放在页面里就是同一个请求里问**第二次** ——
   实测有效会话那一次要 **2.3 秒**。为一句判断给每次登录页访问加一趟往返，不划算。
2. 「登录着 / 确立地没登录 / 判断不出」这个三分**只在那里成立过一次**（七情形实测表）。
   在页面里重做一遍，就是把那张表重新实现一遍；一旦实现得不一样
   （比如把 `AuthRetryableFetchError` 当成「没登录」），一次瞬时认证故障
   就会变成「把人送进应用」或「把人挡在门外」。
3. 重定向发生在**渲染之前**，登录页的 HTML 一个字节都不会生成。

**条件带 `!idleExpired`**：空闲超时的人 `user` 仍然非空（cookie 还在）。
把他送进应用，下一跳又会被判过期弹回 `/login` —— 两跳才停，中间那跳毫无意义。

**SESSION-1 那条刻意的沉默原样保住**：没登录的人干净地打开 `/login` 走不到这条分支
（`user` 为 null），页面照旧**什么都不说**。

**`?next=` 的判据不重写。** 它此前在 `page.tsx` 与 `actions.ts` 里各有一份
「逐字相同」的拷贝 —— **逐字相同要靠人守，而那正是它迟早会不同的原因**。
现在三处（页面、动作、中间件）共用 `lib/loginRoute.ts` 里的同一个函数。

> ★ **顺带堵上一个洞**：原判据是 `startsWith('/') && !startsWith('//')`，
> 漏掉了 `/\evil.com` —— **浏览器解析 URL 时把反斜杠当斜杠**，那个串等价于
> `//evil.com`，一个协议相对的外站地址。判据放行，浏览器跳出去。
> 这一刀把判据搬进了中间件，洞变得更好够得着，所以顺手堵上。已实测：
> `?next=/\evil.com` 现在落到 `/suppliers`。

### 12.3 ★ 顺带抓到的：AVIF 被认证闸口挡住了 ★

底图换成 AVIF 之后，`proxy.ts` 的 matcher 排除清单里**没有 `avif`**：

```
GET /brand/login-field-1280.avif
  → 中间件认为这是受保护路径 → 307 到 /login?next=%2Fbrand%2F…
```

**而请求这张图的人，恰恰是【还没登录】的那些人 —— 登录页的全部观众。**
`<picture>` 一旦按 `type` 选中 AVIF 那一支就**不会再回退到 `<img>`**，
所以屏幕上不是「退化成 WebP」，是**整块底图空白**。

> **它是怎么被抓到的，值得写下来。**
> 断言写的是 `r.ok`，而 `fetch` 默认**跟随重定向** —— 那条 307 被跟到 `/login`，
> 拿回一份 200 的 HTML，**断言绿了**。
> 真正戳破它的是**量字节**：两个不同尺寸的 AVIF 都回了 20 KB，
> 而那正好是登录页 HTML 的大小。
> **一条只看状态码的断言，证明不了拿到的是一张图。**

处置：把 `avif` 加进 matcher 的排除清单，与 `svg|png|jpg|jpeg|gif|webp` 并列。

> ★ **fu2：照片撤了，而这条排除【留着】—— 刻意的，不是漏删。** ★
> 今天 `public/` 下**一个 `.avif` 都没有**，所以它此刻**没有消费者**。
> 但这份清单表达的不是「我们现在有哪些图」，而是
> **「哪些静态图片类型【永远】不该被认证闸口拦下」** —— `avif` 属于这一类，
> 与 `svg`/`png`/`jpg`/`webp` 并列，与今天有没有用它无关。
> 删掉它是那种**看起来是清理、实际是把陷阱重新装上**的改动：
> 下一个往 `public/` 放 `.avif` 的人（favicon、图标、任何图）会原样再踩一遍，
> 而这个 bug 的表现是**空白**加上**状态码断言仍然绿着**，极难看出来。

### 12.4 冒烟为此改了两处（一处必然，一处是为了不丢覆盖）

**冒烟全程带着 admin 会话走路由**，所以 12.2 落地之后 `/login` 对它必然是 307。
第一轮跑出来就是这一条红的 —— **那是对的，它抓到了一次真的行为变化。**

1. `EXPECTED['/login'] = [307]`。**精确写 307，不写 `[200,307]`** ——
   这个文件自己的规矩:「两个都行会静默放过一个开始乱重定向的守卫」。
   在这里 200 就是缺陷:那意味着一个登录着的人又被要求登录一次。

2. ★ **新增一条【不带 cookie】的探针** ★
   只改第一条是不够的:那条钉的是**带会话**的答案，
   而登录页真正的观众是**没有会话**的人 —— 那一半状态门一个字都说不上。
   只改期望值，就等于**把 /login 的 200 路径的唯一自动守卫拿掉了**：
   一个彻底坏掉的登录页(500、空白、或者把所有人都重定向走)照样能让整轮冒烟绿着。

   探针一次断言三件事，各对应一种坏法:
   ① `200` 且有 `name="password"` —— 表单还在;
   ② **没有** `<header>` —— 应用外壳没有回到这一屏;
   ③ `data-login-state="clean"` 且没有 `role="alert"` —— SESSION-1 那条刻意的沉默还在。

## 13 · 磨砂玻璃：**上限是算出来的，实际值是 Tim 定的**

R3 要卡片变成半透明 + backdrop-blur，好让渐变**隐约**透出来。
R4 要求这个值**由测量决定**；Tim 补的那条要求它**faint —— 一丝，不是很透**。
两条一起，答案是一个区间加一个选择，所以两个数都记下来。

### 13.1 AA 允许到哪（上限）

卡片一旦半透明，底图就跑到卡上每一段文字后面。最弱的一项是卡内脚注
`--brand-muted-text`（不透明白底上 4.83:1，AA 要 4.5 —— 余量本来就只有 0.33）。

以「全视口下卡片能盖住的底图最暗点」`#DCF0F7` 求解：

```
α=1.00 → 4.83:1      α=0.86 → 4.72:1      α=0.70 → 4.60:1
α=0.58 → 4.51:1  ← AA 允许的【最大透明度】，余量只剩 0.01
```

**上限是 α = 0.58。**

### 13.2 实际取多少（以及是谁决定的）

Tim：**「一丝磨砂，渐变勉强可感，不是可读」**，并且明说
**「如果 AA 允许的最大透明度比效果需要的更多，就用少于最大值的」**。
于是用色差量「有多明显」：

| α | 脚注对比 | 与纯白的 ΔE | 卡面上的色调变化 ΔE | 观感 |
| ---: | ---: | ---: | ---: | --- |
| 0.92 | 4.76 | 0.81 | 0.62 | 看不出来 |
| **0.86** | **4.72** | **1.42** | **1.09** | **★ 一丝** |
| 0.80 | 4.67 | 2.03 | 1.55 | 一丝（偏多） |
| 0.70 | 4.60 | 3.04 | 2.32 | 明显 |
| 0.58 | 4.51 | 4.26 | 3.24 | 明显（且贴着 AA） |

**取 α = 0.86。** ΔE≈1 是勉强能察觉的门槛，1.42 刚好在门槛之上：
**看得出是玻璃，读不出底下是什么** —— 正是「a hint」。

> ★ **决定这个值的是 Tim 的克制，不是对比度地板。** ★
> 地板允许到 0.58，我们停在 0.86 —— **比允许值保守 0.28**。
> 脚注因此有 4.72:1，比 AA 多 0.22 的余量，而不是 0.01。

（实际发出去的是 `#ffffffdb` = 219/255 = **0.8588**：压缩器把 rgba 序列化成了
带 alpha 的十六进制。差 0.0012，对比度上分辨不出，但记一句免得下次有人对不上账。）

### 13.3 ★ 照直说：那条 blur 目前【什么都没做】★

实测：半径 12px，模糊前后在卡片覆盖区内的**最大色差 ΔE76 = 0.0495**。

渐变太平滑 —— 12px 邻域里本来就几乎是同一个颜色，**没有细节可供模糊**。
**玻璃感全部来自那 14% 的透明度，不是来自模糊。**

它留着，因为 R3 点名要 backdrop-blur，而且底图哪天再有细节时它就位了。
但如果哪天要为低端手机省合成开销（`backdrop-filter` 会强制一个独立的合成层），
**这是可以第一个删掉的东西** —— 删了它，屏幕上的差别是 ΔE 0.05。

### 13.4 背景色为什么走 inline style

shadcn 的 `Card` 自带 `bg-card`（不透明白）。它和 CSS Module 的 `.card` 都是
**单类选择器**，谁赢取决于样式表顺序 —— 那不是可以依赖的东西。
所以背景由 JSX 上的 `style` 给（inline 必胜），**值仍然是 CSS 里那个 token**
（`--login-card-glass`），不是就地挑的数。模糊留在 module 里，没有冲突。

## 14 · 标语：排版规则是**结构性**的，不是调出来的

卡片标题从「登录 EVoltrya OS」+「锂电池回收 ERP 系统」换成公司标语：

```
Powering tomorrow,
recovering today.
```

Tim 的理由：**字标就在正上方，已经说了这是哪个系统** —— 旧标题在重复它。

### 14.1 两行是写死的，不是折出来的

两个 `<span>`，断点就在逗号处。折行会随字号 / 语言 / 窄屏变化，**可能断在词中间**。

### 14.2 右边缘齐平、左边缘参差 —— 而且它**不依赖字号**

```css
.slogan      { width: fit-content; margin-left: auto; }
.sloganLine1 { display: block; text-align: left;  }
.sloganLine2 { display: block; text-align: right; }
```

* `width: fit-content` → 容器宽度 = **较宽的那一行**；
* `margin-left: auto` → 容器右边缘 = **卡片内容区的右边缘**，
  也就是输入框与按钮结束的那条线（`<h1>` 与 `<form>` 是**同一个内容盒的兄弟**，
  已在服务端 HTML 里核对过，不是眼估的）；
* 第一行左对齐、第二行右对齐（Tim 定的）。

**为什么这样就能齐平**：实测 —— 用 fontTools 量 Google Sans 的字宽 ——

```
「Powering tomorrow,」 9.2390 em
「recovering today.」  7.9320 em     → 第一行宽 14.1%
```

第一行是较宽的那一行，所以 `fit-content` 取的是它的宽度：
第一行左对齐即**自然填满容器**、右边缘齐平；第二行右对齐，右边缘同样齐平。
**两行的右边缘因此都精确等于卡片内容边缘。**
★ 换字号两行等比缩放，第一行仍然是较宽的那一行 —— **这条性质与字号无关**。

### 14.3 更小、更轻、行距更紧

原来是 `text-2xl`（24px）+ `font-bold`；现在 **20px / 500 / 行高 1.15**。
它是一句品牌语，不是功能标题，而且现在占两行。

### 14.4 不翻译 —— 怎么落实的

两个语言包里**逐字相同的英文**，键名 `login.sloganLine1` / `sloganLine2`。

* **为什么仍然放在语言包里，而不是写死在页面上**：`check-i18n` 只认翻译函数的
  调用点 —— 页面上一个裸字符串它管不着，于是下一个人不会在那里看到它，
  也就不知道有过这个决定。放进来并且两边相同，是把「不翻译」这件事
  **写进语言包本身**：想翻译中文那一份的人，会先读到键上面那段注释。
* **为什么是两个键，不是一个带换行的串**：断点属于排版（14.2），不属于文案。
  语言包只负责**说什么**。
* `check-i18n` 对「两个 locale 值相同」**没有规则**，所以这样不会红。

### 14.5 换标题必须连着换字标的 alt

此前 `<h1>` 是「登录 EVoltrya OS」，公司名已经被念过一遍，所以字标 `alt=""`（装饰）。
**换成标语之后，整页文字里再没有出现过公司名** —— 字标若仍是装饰，
读屏用户就**不知道这是哪个系统的登录页**。
所以 `alt` 改回 `"EVoltrya"`。**这两件事是一件事，不能只做一半。**
