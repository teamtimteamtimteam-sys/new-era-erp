## PART B · 216 条 route 到底是多少个功能(STEP 2a)

### B1 口径:一条能审计的规则

FE-0 交底 **110 个地址骨架**,并明说 110 是**折叠后的上界,不是功能数**。
grilling 确认 stem 不是对的单位:它两个方向都错 ——
`/processing/orders` 与 `/processing/wip` 是一条工作流的两块面板(**多算**),
而 `/settings` 一个 stem 底下藏着互不相干的三件事(**少算**)。

**采用的判据(Tim 已批准,可复核):**

> **一个「功能」= 它能作为菜单里的【一行】出现,而不会有人问"哪一个?"。**

按这条规则从 110 个 stem 折叠,**每一次折叠都记账**:

| 折叠 | stem 数 → 功能数 | 省下 |
|---|---|---|
| `finance/bank` + `import` + `statements` + `statements/[id]/reconcile` | 4 → 1 | −3 |
| `finance/fx` + `fx/bulk` | 2 → 1 | −1 |
| `hr/leave` + `balances`/`calendar`/`grants`/`holidays`/`types` | 6 → 1 | −5 |
| `hr/reviews` + `cycles` + `scale` | 3 → 1 | −2 |
| `inventory/reports` + `ledger`/`safety`/`snapshot`/`violations` | 5 → 1 | −4 |
| `settings/permissions` + `roles` + `reference` | 3 → 1 | −2 |
| `pricing` + `formulas` + `calculator` | 3 → 1 | −2 |
| `metal-prices` + `metal-prices/bulk` | 2 → 1 | −1 |
| `inbound` + `receive` + `receive/done` + `[id]/assays` | 4 → 1 | −3 |
| `output` + `[id]/assays` | 2 → 1 | −1 |
| `stocktakes` + `[id]/review` | 2 → 1 | −1 |
| `purchasing/orders` + `[id]/amend` | 2 → 1 | −1 |
| `sales/orders` + `[id]/amend` | 2 → 1 | −1 |

| `login` + `welcome` + `set-password` | 3 → 1 | −2 |
| **合计** | | **−31** |

**110 − 31 = 79。**

### B2 答案:一个主数字、一个区间、和产生它们的规则

| | 数 | 它是什么 |
|---|---|---|
| **主数字** | **79 个功能** | 按上面那条判据折叠 110 个 stem,折叠账目逐条列在上表 |
| **区间** | **62 – 95** | 下界:把财务的应收族、应付族、期末族各折成一行(再 −17);上界:只做无争议的折叠(`/new`、`/edit` 那一类) |
| **硬上界** | **110** | FE-0 的 stem 数,即"一次折叠都不再做" |
| 无界面端点 | **29** | `route.ts(x)`,PDF 与导出。**不是功能**,是功能的输出口 |

**为什么给区间而不是一个数**:折叠"财务/应收 + 发票 + 贷记单"这类判断,
取决于二级菜单**允不允许有第三层**。那正是 PART E 要 Tim 拍的板 ——
**功能数与外壳深度是同一个决定的两面**,先定外壳,79 才会收敛成一个数。

## PART D · 二级长什么样,以及每一条是 DERIVED 还是 JUDGED(STEP 2b)

### D1 先说一条决定性的测量

**权限只有模块一级,没有任何子模块码。** 实测 `db/tables/permissions.sql`:
14 个 `module.<x>.view/.edit` + 8 个横切的 `data.*` / `action.*`,
**子模块权限码:0 个。**

> **后果,照直说:二级分组【不可能】从权限推导出来。**
> 推导只能来自两个地方:**URL 的现有嵌套**,或**页面所读的表之间的关系**。
> 因此**绝大多数二级是 JUDGED,需要 Tim 逐条过目。**

`docs/exec-views-plan.md:122` 已经独立撞上过同一堵墙:
拆 `module.pricing.view` "会撞上 `lib/modules.ts` **一个模块一个权限码**的结构 ——
那不是加一行,是改导航/模块机器本身"。
