# 物料的受控废物分类:建了什么,以及【下一步会撞上什么】(MAT-1,2026-08-12)

建的只有一件事:`materials.waste_classification_code` + 一张 `waste_classifications`
字典(RUNTIME CONFIG,加一种分类是加一行)。种子两行,是 Doc 1 里 Tim 自己用的词 ——
**重点物料 / 非重点物料**,每一行把理由写在 `notes` 上。

**既有物料全部 NULL,而且不回填。** NULL 的意思是"没有人分过类",不是"非受控"。
`db/fixtures/53` 的 A 臂钉住这一条:三种状态在同一个查询里各自可辨,而一个把 NULL
当成非受控的实现会得到 1/2/0,并且能通过其它每一条断言。

---

## 一 · 它与 CMP-1 的收货拦截怎么接 —— **报告,本刀不建**

### 今天的拦截长什么样

`guard_supplier_qualification`(在 `db/tables/inbound_batches.sql` 里)在 INSERT 时:

```
supplier_compliance  →  certificate_types (disposition = 'block')
                     →  valid_until < CURRENT_DATE
                     →  SUPPLIER_QUALIFICATION_EXPIRED
```

**它一个字都没提物料。** 它问的是"这个供应商有没有一张过期的、处置为 block 的证书",
而不是"这个供应商有没有资格收【这一类】货"。

### 有了分类之后能表达什么,而今天表达不了

> **"这家供应商是有证的,但不是【这一类】物料的证。"**

今天这句话在系统里说不出来 —— 一张 Basel 证会同时为这家供应商的每一批货背书,
不管来的是重点物料还是一箱包装材料。

### 要做需要什么(三选一,不是同一件事)

| 形状 | 加在哪 | 代价 / 后果 |
|---|---|---|
| **(a) 证书类型带范围** | `certificate_types` 加一列,声明这一类证书【覆盖哪些分类】 | 最省事,但它断言的是"所有 Basel 证覆盖的范围都一样"—— 而范围是**签发机关写在那张证上的**,不是证书类型的属性。第一张范围不同的证就会把这个模型顶穿 |
| **(b) 每张证带范围** | `supplier_compliance` 加一列(或一张子表) | 与现实对得上:范围是**那一张证**的属性。代价是录入多一步,而且旧证的范围一律 NULL —— 又一次"未声明不是无限制"的判断 |
| **(c) 不做范围,只做提示** | 看板/收货页提示"这批是重点物料,请人工核对证书范围" | 不假装知道系统不知道的事。适合在 Tim 真正见过几张证之前 |

### 报告的结论(不是决定)

**倾向 (b),但不该在见过实际证书之前定。** 理由是 (a) 的失败模式很难看:它会让一张
范围较窄的证**看起来覆盖了它并不覆盖的物料**,而这正是拦截存在的理由的反面 ——
一个安静的假阴性,比没有拦截更坏。

而在决定之前,**(c) 是可以先做的**,并且不会把 (b) 的路堵住。

**还有一个必须一并回答的问题,否则 (b) 会长出第二个 NULL 陷阱:** 一张
**没有声明范围**的旧证,在新规则下算"覆盖一切"还是"覆盖不了任何东西"?
按这个仓库的一贯答案,两者都不对 —— 它应该是**第三种状态**,既不放行也不静默拦截,
而是让人去看那张证。这与 MAT-1 里 NULL 的处理是同一条。

## 二 · **本刀不做的事**,以及为什么现在做等于猜

| 不做 | 为什么 |
|---|---|
| **Basel 代码**(如 A1180 / B1110) | 另一套编码体系,有自己的清单与结构。它回答的是"这批货在公约的名录里是哪一条",不是"我们把它当作哪一类"。挤进同一列会得到一个"有时是分类、有时是代码"的字段 |
| **UN 编号**(危险品运输编号) | 又一套,且服务于**运输**而不是**处置**。同一批货可以有 UN 编号而不是受控废物,反之亦然 |
| **HS 编码**(海关税则) | 第三套,服务于**关税**。它随目的国的税则版本变化,而受控分类不随 |
| **法域差异** | 同一批货在新加坡 / 欧盟 / 中国的分类**可以不同**。真要做,正确形状多半是"每个法域一条分类",而不是物料上的一个值 —— 那是一张关联表,不是一个字段 |

**共同的理由:这四件都取决于 Tim 第一票跨境货实际走哪条路。** 现在录进来,是拿着
一副已经看过底牌的样子在猜 —— 而猜出来的编码会被下一个人当成**查过的事实**,
那比空着坏得多(FIN-26 对"编造的出处"下过同样的判断)。

`docs/compliance-scoping.md` 已经把这些按**事务范围 / 主数据范围 / 日历范围**分过类;
Basel/TFS 那一族是**事务范围**(一票货一套单据,有自己的生命周期),
而本刀落的是**主数据范围**里最小的那一格。两者不该混为一个字段。

## 三 · 与既有 `category` / `chemistry` 的关系(已核对,不重复)

| 列 | 它回答的问题 | 谁在用 |
|---|---|---|
| `category` | **它在我们的流程里是哪一种东西**(进料-电池 / 产出-黑粉 / 耗材辅料) | 物料列表的筛选、导出 |
| `chemistry` | **正极化学体系**(NMC / LFP / …) | 同上 |
| `waste_classification_code`(本刀) | **监管怎么看它** | 目前只有显示;将来是收货拦截的另一半 |

三者**同时成立而互不蕴含**:一种非受控的进料电池,与一种受控的进料电池,
`category` 与 `chemistry` 可以一模一样 —— fixture 53 的 A 臂就是这样构造的
(三个物料的 category/chemistry 完全相同,只有分类不同)。

**顺带记一个既有事实:`materials.category` 是自由文本,没有 CHECK 也没有外键。**
界面给了 7 个选项,而线上已经有 `NiH` 与 `black_mass` 两个不在选项表里的值。
本刀的分类列**用外键**,正是不想重演这件事 —— 自由文本的分类在第一次手滑之后
会变成两种拼法,而合规判断读不出"这两个其实是一个"。
