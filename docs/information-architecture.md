## 2 · 建成的结构

### 2.1 三份清单,各回答一个问题(`lib/modules.ts`)

| | 是什么 | 谁读它 |
|---|---|---|
| `MODULES` | **九个一级模块**,Tim 给的顺序 | 顶栏 |
| `SCOPES` | **15 个权限范围** | 页面守卫 `requireModule(MOD.x)`,178 处 |
| `FUNCTIONS` | **每一个二级条目**(77 条,其中 11 条跨属主) | 顶栏二级、手机抽屉、财务子导航、dock |

★ **为什么必须分开**:九模块方案把 suppliers / materials / stocktakes / customers /
inbound / output / pricing 从一级模块降成二级条目,**但它们的权限码一个都没有降级** ——

### 2.2 一级模块【没有 permission 字段】—— 可进性是推导的

一个模块进不进得去 = **它名下有没有任何一条二级条目进得去**
(`lib/moduleAccess.ts` 的 `entries.some(...allows...)`)。

写第二份谓词就是第二份定义,而它与二级条目的判据之间没有任何东西保证同步。

**它顺手把 M6 变成了一件不需要特判的事**:盘点是库存名下的一条二级条目,
它进得去,所以库存这个一级就进得去。不需要 `widen`、不需要新码、不需要一行特判。
而进去之后看到的是一张**逐条诚实**的菜单,不是一个打得开却零行的库存页
(NAV-REG-1 为物流记下的那个陷阱)。

## 3 · 面包屑:深路由的判据是【算出来的】

> **深度 = 路径段里,不是动态段 `[…]`、不是路由组 `(…)`、也不是叶子动作词
> `new`/`edit` 的那些段的个数。深 ⟺ 深度 ≥ 3。**

三条排除各有理由:一个 id 不是架构里的一层(它是同一层上的一行);路由组根本不
出现在 URL 里;`new`/`edit` 是**对当前这一层的动作**,不是更深的一层
(`/hr/employees/new` 读起来是"员工 · 新建",不是"人力 › 员工 › 新建")。

实测落在 190 条路由上:深度 1 → 45 · 2 → 121 · **3 → 22 · 4 → 1**,
**深的一共 23 条 —— 与 Tim 的 D4 和勘察 PART F/3b 的 22+1 逐条对上。**

清单由 `scripts/gen-deep-routes.mjs` 生成到 `lib/deepRoutes.generated.ts`,
`npm run build` 比对,过期就红。**为什么不手写那 23 条**:勘察 E2/4 记着
`finance/Subnav` 两份清单的漂移隐患 —— 一份手写的深路由清单是同一个形状,
加一页的人不会想到来改它,于是那一页永远没有面包屑,而没有任何东西会说出来。
(本刀落地时它就响了一次:新增两页之后比对当场变红。)

面包屑的三截也是机械拼的:模块名(不是链接)› 注册表里最长前缀那条二级条目 ›
剩下的每一段一句 `breadcrumb.<段>`。**动态段整段跳过**,与判定深浅时跳过 `[id]`
是同一条理由。那 21 个段名的两语文案由 `check-i18n` 的 MANIFEST 从生成文件**现读** ——
加一条带新段的深路由,少一句文案就构建变红。

**实测**:`/inventory/reports/snapshot` → `Inventory › Reports › Snapshot`;
`/inventory` → **不画**(一个字节都没有)。

## 4 · dock

### 4.1 存在哪,为什么

`public.user_dock`:**一人一行**,`hrefs text[]`,FK 指向 `auth.users`(级联删除),
四条 RLS 策略全部锁在 `user_id = auth.uid()` —— **别人读不到,管理员也读不到。**

★ **为什么是"一行 + 一个数组",而不是"一人多行"** ★ 因为要分得开**三种**状态:

| 库里 | 意思 | 屏幕 |
|---|---|---|
| **没有这一行** | 从来没有动过 | 画按权限的默认 |
| **有行、数组为空** | **本人清空了** | 就画空的,**不补回默认** |
| 有行、数组非空 | 这是他排的 | 画这些 |

一人多行表达不了中间那一种:零行既是"没动过"也是"清空了"。
**"缺席 ≠ 空"是这个仓库反复付账的那条区别**,这里从模式层面就分开。

**为什么不是 cookie / localStorage**:系统里已有的唯一一项偏好(语言)存在 cookie 里,
那是**每台设备一份**。Tim 在手机上和桌面上用同一套 dock。

### 4.2 一项进不去的时候(Tim 的 4b)—— 三态,实测

| 状态 | 屏幕上 | 可点 | 有移除按钮 |
|---|---|---|---|
| `open` | 标签 | ✅ | 编辑态下有 |
| `restricted` | 「员工 · 受限」 | **❌** | **✅**(他得能自己清掉) |
| `gone`(地址已不在注册表里) | 「/some-retired-feature · 已下架」 | **❌** | **✅** |

**可见性在【渲染时】算,不在【存的时候】算** —— 存的只有地址,每次渲染重新问注册表。
所以权限被收走的第二天,那一项自己就变成「受限」,不需要谁去跑一次清理。
写侧**故意不判权限**:写侧一挡,渲染侧就会有人觉得不必再判 —— 那才是危险的地方。

### 4.3 默认(4c)

按**权限**取一份候选清单里的前 8 条。Tim 的原话是"按角色",落成"按权限" ——
效果相同(权限就是角色带来的东西),但**一个人可以同时持有几个角色**,按权限
根本不会遇到"两个角色的默认怎么合";而且渲染顶栏时权限**已经查过了**(React cache)。

实测:**live 的 11 个角色,每一个的默认 dock 都非空** —— 连一个零模块权限的
`employee` 也有一条(金属行情,它的读策略是 `USING(true)`)。

### 4.4 一处实测出来的迟钝,以及为什么它值得修

服务端动作写完之后要 `revalidatePath('/', 'layout')` —— 而外壳在**每一页**上,
所以整棵树要重画。实测(稳定别名,按下「×」之后逐秒采样):

| 1s | 2s | 4s | 8s |
|---|---|---|---|
| 没变 | 没变 | 没变 | **变了** |

也就是说:人按了移除,**屏幕上五秒钟什么都没发生**,而库里其实已经写完了。
**一个按下去没反应的控件读起来就是坏的。** 加了 `useOptimistic`:那一格立刻变,
真值到了再对齐,失败时 React 自己回滚、错误由 `role="alert"` 说出来。
**存的是什么一个字没变,变的是等待期间屏幕说的是哪一句话。**

### 4.5 它不是第二套导航(4d)

加项只能从注册表里已有的条目加(服务端动作对着 `FUNCTIONS` 核,核不上就拒绝),
所以 dock 里**不可能出现顶栏到不了的功能**。

## 5 · 淡底与磨砂(R1–R3)

### R1 · 内部页面的底色

`body { background: var(--brand-bg) }` = **#F1F9FE**,品牌指南白纸黑字给的 BACKGROUND。

| 文字 | on #FFFFFF(之前) | **on #F1F9FE(现在)** |
|---|---|---|
| `--foreground` #171717(正文,187 页在用) | 17.93:1 | **16.84:1** ✓ |
| `--brand-text` #182B4B | 14.13:1 | **13.27:1** ✓ |
| `text-gray-600`(全站次级文字最常用的一档) | 7.56:1 | **7.10:1** ✓ |
| `text-gray-500` | 4.83:1 | **4.54:1** ✓(最险的一档) |

**每一档都掉了一点点,没有一档掉出 AA。** 125 处 `bg-white` 的卡片与表格原样保留,
它们现在是**浮在淡底上的白面**。

### R2 · 磨砂只给浮动层

顶栏 · dock · 下拉 · 抽屉。**表格不磨砂,卡片与面板这一刀也不磨砂**(Tim 的裁定)。

### R3 · 值是怎么定的,以及【是哪一条约束定的】

顶栏是 sticky 的,页面内容从它底下滚过去 —— 所以对比度必须对着**合成色**量,
不是对着 token 量。最坏的真实底:`bg-gray-900` #111827(全站最深的面,62 处)。

| 玻璃上的文字 | AA(4.5:1)允许的**最低不透明度** |
|---|---|
| `--brand-text` #182B4B | 0.526 |
| **`--brand-muted-glass` #55657D** | **0.868 ← 就是这一条定的值** |

**AA 允许的最大透明度是不透明度 0.868。本刀取 0.90 —— 比允许的最大值更不透明,
也就是更淡的玻璃**,富余 3.2 个百分点。这正是 R3 要的 "a hint of glass"。

合成之后的实测:

| 底 | 合成色 | `--brand-text` | `--brand-muted-glass` |
|---|---|---|---|
| 最坏 #111827 | #E7E8E9 | **11.52:1** ✓ | **4.83:1** ✓ |
| 正常(淡底 #F1F9FE) | #FEFEFF | **14.02:1** ✓ | **5.88:1** ✓ |

**顺手修掉的一处**:「· 受限」此前用 `text-gray-400`(#9ca3af,on white **2.51:1**),
而 D5 的全部内容是**那个名字要读得出来**。现在它用 `--brand-muted-glass`,
最坏 4.83:1。一条读不清的具名限制,和一处缺席差得不多。

模糊 `blur(10px)`。与 `/login` 那条不同,这里底下是**页面内容**(文字、表格线、
色块),有真的细节可以糊 —— login 那条实测 ΔE76 只有 0.0495,因为它底下是平滑渐变。

### 12.1 ① 浮层的玻璃太透 —— 而【真正的病是模糊一帧都没生效】

Tim 报的是"菜单太透,底下的字能读"。能读是真的,**但透明度只是从犯。**

**实测(稳定别名,admin 会话,1440×900。做法:把菜单自己的字藏起来只留玻璃,
截图量整块菜单区域最亮/最暗合成像素之比 = 底下那一页透过来的对比度。)**

| | 读透对比度 |
|---|---|
| 菜单开在 `/finance/invoices` 的密表上 | **1.260:1** ← 能读 |
| 菜单开在 `/tasks` 的看板上(Tim 看到的那一屏) | **1.216:1** ← 能读 |

1.2:1 的**锐利**文字读得出来。而它锐利,是因为那 10px 模糊**一帧都没生效**。

**根因:下拉是顶栏的后代,而顶栏自己就是一个 Backdrop Root。**
`backdrop-filter` 的滤镜源只到"最近的 Backdrop Root 之内、画在它背后的东西";
带 `backdrop-filter` 的元素自己就开一个 Backdrop Root。下拉从顶栏**底下**垂出去,
那一块是空的。**判据(逐像素相减,把下拉自己的底色与内容全部去掉只留滤镜):
平均差 0.000,最大差 0 —— 一个字节都没变。**

**同一个根因还砸了手机抽屉,而那一处更严重。**
带 `backdrop-filter` 的元素同时是 `fixed` 后代的**包含块**。抽屉写的是
`fixed inset-0`,对齐的于是是顶栏不是视口。**实测 390×844:抽屉 94px 高、
面板 105px 高、里面 583px 内容** —— 九个模块挤在一条缝里,而 IA-BUILD-1 的
抬头写的是"一张全高的抽屉"。**这个缺陷此前没有任何人报过。**

**修法**:顶栏自己不再带 `backdrop-filter`,玻璃改由一个铺满它的子元素
`.nav-glass-underlay`(`absolute inset-0; z-index:-1`)来画。顶栏于是既不是
Backdrop Root 也不是包含块,而看上去逐像素不变。

**每一个浮动层的值(它们【共用一个 token】`.nav-glass`,所以只改了一处)**

| 层 | 改前 | 改后 | 模糊改前 | 模糊改后 |
|---|---|---|---|---|
| 顶栏 `<header>` | 白 0.90 | 白 **0.94**(移到 `.nav-glass-underlay`) | 生效 | 生效 |
| 模块下拉 `[role=menu]` | 白 0.90 | 白 **0.94** | **失效** | **生效** |
| 手机抽屉面板 | 白 0.90 | 白 **0.94** | **失效** | **生效** |
| dock(桌面竖栏 / 手机底栏) | 白 0.90 | 白 **0.94** | 生效 | 生效 |
| 表格列菜单 `ui/data-table.tsx:231` | 白 0.90 | 白 **0.94** | 生效(不在顶栏里) | 生效 |
| sampler 面板 `brand-sampler/Base1.tsx:196` | 白 0.90 | 白 **0.94** | 生效 | 生效 |

**六层共用一个 token,所以是改了一次。** 模糊半径两边都是 `blur(10px)`,没动。

**把 0.216 与 0.018 分开说 —— 因为 Tim 要的是"大幅降低透明度",
而实测说透明度不是主因:**

| | 读透(最坏情形,`/finance/invoices` 密表) |
|---|---|
| 0.90 + 模糊失效(今天) | 1.260:1 |
| 0.90 + 模糊生效 | **1.044:1** ← 光修模糊就到这 |
| **0.94 + 模糊生效(本刀)** | **1.026:1** |
| 0.96 + 模糊生效 | 1.017:1 |

**修模糊拿走 0.216,收透明度只拿走 0.018。** 仍然收到 0.94,理由有二:
Tim 要"浮层必须**遮住**它浮着的东西";而模糊糊得掉细笔画、糊不掉一整片暗色
(全站最深的 `bg-gray-900 #111827` 有 62 处),那一片只能靠不透明度压。
**没有再往上收到 0.96**,因为那时读透只剩 1.017:1,底下那层就**看不出来**了 ——
Tim 的原话是 "perceptible, NEVER legible",看不出来是把另一头做过了头。

**菜单自己的字对着最坏合成色(实测,不是推算)**

| | 最坏合成 | `--brand-text` | `--brand-muted-glass` |
|---|---|---|---|
| 0.90 / 模糊失效 | `rgb(229,229,229)` | 11.22:1 | 4.70:1 |
| **0.94 / 模糊生效** | `rgb(252,252,252)` | **13.77:1** | **5.78:1** |

### 12.3 ③ 长菜单现在自己说它还有下文

**实测**:财务菜单 **1249px 内容装在 628px 里**(1440×900,admin),
**16 条完全在视野之外**,而屏幕上没有任何东西说这件事。

**选的不是渐隐,也不能只靠滚动条。** 第一版只做了滚动条,实测把它否了:
量 `offsetWidth − clientWidth`,在 headless Chrome 152 / macOS 上是 **0px**;
拿一张最小页面单独试三种写法(无样式 / `::-webkit-scrollbar{width:10px}` /
`scrollbar-width:thin`)**三种都是 0** —— 这台机器上的 Chrome 无条件用覆盖式
滚动条,CSS 掰不动。**一个演示不出来的信号不算修好。**

**最终的修法:我们自己画一行字**(`ModuleBar.tsx` 的 `MoreBelow`),
贴在滚动容器底边,说的是**条数**不是"往下滚"——条数可核对,手势不可核对;
数的是**完全落在视野外**的行(逐个量 `offsetTop`,不按平均行高估算,
因为分组标题/缩进项/普通项高度并不相同);**滚到底就消失**(那时它是假的)。

| | 实测 |
|---|---|
| 桌面 1440×900,财务菜单 | 「↓ 16 more below」;滚到底 → **消失 ✓** |
| 390×844 抽屉里展开财务 | 面板 788px 装 1835px、34 行 → 「↓ 19 more below」 |

`::-webkit-scrollbar` 的样式**留着当增强**(桌面版 Chrome/Safari 上通常会把
覆盖式换成常驻式),但**那是通行说法不是本刀量到的事实**,所以它不承重。

### 12.4 ④ dock 搬到左边一条竖栏

桌面 = 左竖栏(与顶栏分开:一条管结构,一条管个人);手机 = 仍是底栏。
两边都可收起,**收起状态跟着人走**(`user_dock.collapsed`,不是 cookie)。
布局在 `app/layout.tsx`:`<TopNav>` 之下开一个 flex 行,
`<DockRail>` 与内容列是两个兄弟(取数从 `TopNav` 搬进了 `DockRail.tsx`)。

**★ 那一列 boolean 逼出来的二义,以及它本来会吃掉谁的 dock ★**
`user_dock` 靠 hrefs 区分三态,而 hrefs 此前是 `NOT NULL DEFAULT '{}'`。
**只要为了记一个 `collapsed` 就得建行,那一行的 hrefs 会拿到 `'{}'` = "本人清空了"。**
于是:一个人只是把 dock 收起来,系统就认为他把 dock 清空了,
展开之后看到一条空栏,而他自己排的那几项**再也回不来**。
迁移因此把 hrefs 改成**可空并去掉默认值**:`NULL` = 从没动过,`'{}'` = 清空了。
连带 `resetDock` 从 `DELETE` 整行改成 `UPDATE SET hrefs = NULL` ——
否则"恢复默认 dock"会顺手把收起/展开的选择也抹掉,而那是两件事。
(线上 `user_dock` 当时 **0 行**,所以这条陷阱伤到的是第一个收起 dock 的人,不是存量数据。)

**实测(本地 production build,admin 会话)**

| | 竖栏宽 | 内容宽(1440) |
|---|---|---|
| 展开 | **192px** | 1248px |
| 收起 | **48px** | 1392px |

**宽表在它旁边怎么样(`/finance/invoices`,该表最小宽约 866px,
且这一页【没有】自己的横向滚动容器 —— FE-0 记的 134 页之一):**

| 视口 | 展开(192px) | 收起(48px) |
|---|---|---|
| 1440 | 表 1184px,**不横向滚** | 表 1328px,**不横向滚** |
| 1024 | **整页横向滚 +66px** | 不横向滚 |
| 768 | **整页横向滚 +322px** | 整页横向滚 +178px |

**照直说:竖栏把"开始横向滚"的门槛从约 914px 抬到了约 1058px。**
横向滚起来时竖栏是 flex 流里的一项,会跟着滚出屏幕左侧。
**收起来能拿回 144px,而这正是"可收起"存在的理由之一。**
1440 及以上两种状态都不横向滚。

**收起态不是消失**:桌面留一条 48px 图标竖栏(每项 `title` + `aria-label` 是
与展开态**逐字相同**的全名;受限/已下架照样画成灰图标 + title 里那句话,
不是拿掉 —— 4b 在收起态同样成立);手机留一条把手(26px)。
`lucide-react` 此前全仓库 0 处引用,本刀是第一处读者。

**跟着人走,实测**:收起 → 换页仍是收起 → **换一个全新的浏览器上下文
(同一个人、另一台"设备")仍然是收起**;并且 dock 里 8 项一项没少、
`data-dock-default=1` —— **收起没有被读成"清空"。**

手机底栏:展开 37px / 收起 26px,`body` 给它留的 `padding-bottom` 是 52px,
两种状态都盖不住最后一行。

### 12.5 ⑤ /login 标语两行各自向中间收 8%

用**百分比**而不是固定 px,正是为了 Tim 点名要查的那件事
("窄卡上两条缩进会吃掉小得多的宽度"):百分比对着内容盒算,**卡片越窄缩进越小**。

`text-align` 在盒子上看不出来):
