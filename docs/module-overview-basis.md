# 模块 Overview 的依据 —— 七页共用的那一条

**CONV-7 ②(2026-09-04)。本刀建了两页:`/finance` 与 `/hr`。另外五页【没有建】。**
这份文件是那五页的规格。先读 §1,它是全部形状的来源。

---

## 0 · 一句话

> **二级菜单答「这里有什么」;账簿答「某一种单据有哪些行」;提醒答「什么在等我」。**
> **Overview 答那个没有人在答的问题:这个模块【此刻是什么状态】——**
> **而它只装那些【横跨若干张子页面、任何一张自己都说不出来】的事实。**

---

## 1 · ★ 那个决定一切的问题,和它的答案 ★

Tim 的问题,逐字:

> **一旦二级菜单已经列出了每一张子页面,Overview 还能提供什么导航之外的东西?**

而他同时下了一条不可协商的裁定:

> **绝对不能是模块内子页面的卡片排列。**

**他的理由必须原样保留,因为它才是形状的来源:**
`/pricing` 就是它三个孩子的卡片排列,而那是**对的** —— `/pricing` 是一张**二级页**,
它的全部职责就是把三个孩子递出来。**一级模块不同:它的二级菜单已经把每一页列了一遍。**
Overview 再用卡片复述一次,就是同一份清单的**第三遍**,不添一个字。
所以 **`/pricing` 可以看,但它不是先例**;而既有的那几张 Overview 也不是
(`/finance` 与 `/operation` 此前是 `<ModuleLanding>` —— 恰恰就是被禁的那一种)。

### 答案

**这个答案不是本刀发明的,它是从这个仓库自己写下的一条规矩里领出来的。**
`docs/dashboard-arm-inventory.md` 给 `operations_now` 划界时写着:

> `operations_now` 只答一个问题:**什么正在等一个人**。……它不是一张指标视图,
> 不是一份报表,也不是放合计的地方 —— **一个仅仅是【有意思】的数,属于那个模块
> 自己的页面。**

**那一页从来没有存在过。** 那句话指着一个空位指了整个 Phase 6。
CONV-7 ① 把【在等的事】整块搬去 `/tools/reminders` 之后,剩下的正是这一类,
而它们需要一个家。**提醒装【在等的事】;Overview 装【为真的事】。**

### 判据只有一条,而它是可执行的

一个事实能上 Overview,当且仅当:

> **它横跨这个模块的若干张子页面,而其中任何一张自己都说不出来。**

这条判据**不是一句叮嘱,它被编译器执行**:`<Figure>` 的 `basis.spans` 是**必填的**,
内容是「它跨了哪几页」。**填不出来,就说明某一张子页面自己就答得了它 —— 那它属于
那一页,不属于这里。** 这一格挡掉的正是一张 Overview 退化时会最先长出来的东西:
「未过账分录数」「本月发票张数」「员工总数」——它们各自都有一张页面在说。

做法照的是 `ChartCard` 的先例(**说不出出处就画不出来**):它把 `basis` 设成必填,
于是一张说不出自己基准的图**写不出来**。这里是同一招,多要一格。

## 2 · 形状:一页三到四条【陈述】,不是一排卡片

* **单位是一条陈述**,不是一块牌子:标题 + 一句带数的话 + 三行出处(+ 可选一条链接)。
* **条数在个位数**,而**数量本身是判断的一部分** —— 十条陈述的 Overview 说明
  §1 那条判据没有被真的执行。本刀两页各三条。
* **顺序有意义**:能框住下面所有数的那一条放最上面
  (财务是「账本开着的期间」—— 不知道封到哪天,底下每个数都读不成)。
* **没有图**。CHART-1 的裁定照旧:数据不够就拒绝画。真要图,用 `ChartCard`,
  它自带「太少就不画」那一支。

### `<Figure>` 的三种状态 —— 而第三种是这一套里最要紧的

| 状态 | 什么时候 | 屏幕上 |
|---|---|---|
| `ok` | 说得出 | 那句话 |
| `restricted` | 你看不见 | **具名的**「受限(权限码)」—— D5,走 `<Refusal>`,不是空白、更不是零 |
| `unanswerable` | **依据不在** | 「答不上来 — <为什么>」,`why` **必填** |

> ★ **`unanswerable` 不是空态,它是一句陈述。** ★
> 「答不上来」与「答案是零」在屏幕上必须分得开。这不是本刀的新主张,它是这个
> 仓库反复付账的同一条区别的**第五处**:
> `gl_control_reconciliation` 对早于今天的存货那一支拒绝回答(**「照答会返回一个
> 自信的 0.00」**)· CHART-1 的「数据太少就拒绝画」· METAL-1 的 `no_reference` ·
> `lib/permissions.ts` 的「受限的 null ≠ 本来就没有的 null」· AGENTS.md 的
> 「失败 ≠ 空集」。

## 3 · 与另外三样东西的分界 —— 写死,否则会互相复制

| 它 | 答 | Overview 【不】做的事 |
|---|---|---|
| 二级菜单 | 这个模块有哪些页 | 不重列子页面。**一条都不列。** |
| 账簿 / 列表页 | 某一种单据有哪些行 | 不摘录行。要行就去那一页。 |
| `/tools/reminders` | 什么在等一个人 | **不画任何一条提醒。** |
| `/finance/month-end` | 这个月还差哪几步 | 不列步骤,不复制那七个信号。 |

**「提醒 vs Overview」这条分界在人力上是可检验的:** `hr_alerts` 的每一条都是
「有人得去办,办完就消失」,所以它**整块**属于提醒页;而「在册几个人、
上一期薪资是哪个月」办不掉,它是状态,所以它属于 Overview。
**一条信号只能有一个家。** 两处都画就是两份必然漂开的实现。

## 4 · 数据的规矩(与全站同一套,不给 Overview 豁免)

1. **每个数说出自己的基准** —— `<Figure>` 的三格出处强制。
   `source` 那一格是**一句人话**,不是表名、不是函数名(CONV-0 ②c 已经为
   「图上印着 `ar_aging_asof(as_of)`」改过一次口径)。
2. **空态说出为什么空** —— 走 `unanswerable`,`why` 必填。
3. **受限画成具名的限制**(D5),永远不是空白、不是零。
4. **每一次查询过 `mustRows` / `mustOne` / `mustCount`** —— 失败必须是失败。
   (旧的 `/hr` 用的是 `?? []`:一次 RLS 拒绝会渲染成「0 人在职」。)
5. **先判权限,再决定查不查。** 从空结果倒推「你没权限」是 OPS-14/15 那条老病;
   在遮蔽视图上它还多错一层 —— 无权读者拿到的是 **null 而不是空集**,
   于是「没权限」与「这个人没录」长得一模一样。**必须由权限分,不能由值分。**
6. **不发明系统没有的指标。** 最有用的那个数如果需要一张还不存在的表,
   **说出来,然后建那一半做得到的** —— 不要造一个近似值。
7. **成本要量。** 一条陈述背后的读数是要量的(本刀:`gl_control_reconciliation`
   **实测 508ms**)。Overview 是【专程打开的】页,它比首页宽松 —— 而
   `operations_now` 那条「无界扫描由每个用户每次访问买单」的界限之所以严,
   正因为它长在首页上。**写下来的成本必须是量出来的成本。**

8. ★ **「今天」必须是【业务时区】的今天 —— 用 `businessToday()`,永远不要
   `new Date().toISOString().slice(0,10)`。** 后者是 **UTC** 的今天,在 SGT
   早上八点之前它**早一天**。这不是学术问题:`gl_control_reconciliation` 对
   **早于今天**的存货腿**按名拒绝回答**,所以财务 Overview 第一版在新加坡的
   每个凌晨都会把两条本来平得上的腿画成「答不上来」。
   **它是浏览器实测抓到的**(直接问库用的是 `CURRENT_DATE`,库在业务时区,
   四条腿全平;而渲染出来的同一页 `reconRefusals = 2`)——
   **读代码读不出来,只在一天里某几个小时出现。**

## 5 · 本刀建的两页,以及为什么是这两页

**Tim 的话:「只对财务成立的形状不是那个形状。」** 所以选的是**最不像的一对**:

| | `/finance` | `/hr` |
|---|---|---|
| 主题 | 钱 | 人 |
| 二级条目 | **32 条**,还有六个第三级分组 | **11 条**,平铺 |
| 每个数的单位 | 金额 | 人、天、月 |
| 本刀之前它是什么 | **`<ModuleLanding>` —— 恰恰是被禁的那种卡片墙** | **一块 `hr_alerts` 待办看板** |
| 所以这一刀在做 | **替换**一个错的形状 | 在 ① 掏空它之后**从零重建** |
| 旁边有没有对手 | 有:`/finance/month-end`,分界必须写死 | 有:提醒页,分界必须写死 |
| 页内有没有 D5 | 没有(整页同一个码) | **有,而且是真的** ↓ |

> ★ **人力那一格 D5 是实测出来的,不是构造的** ★
> `module.hr.view` = admin · auditor · gm · hr;`data.view_pay` = admin · cfo · finance · hr。
> **`auditor` 与 `gm` 进得来这一页,而没有 `data.view_pay`。**
> 于是「月固定工资总额」对他们画成具名的「受限(data.view_pay)」。
> 这是整套权限模型里少有的一处**同一页、不同人看到不同格数**,而它此前
> 没有被任何一页表达过。

### 两页各三条陈述

**`/finance`** ① 账本开着的期间 · ② 总账 ↔ 明细账(四条腿,含未解释差额)· ③ 净头寸
**`/hr`** ① 队伍的构成 · ② 考勤与薪资的周期 · ③ 月固定工资总额

**②(财务)为什么是这一条,而不是「损益对得上资产负债」:**
`gl_control_reconciliation` 的抬头写着理由 —— 损益与资产负债**读同一份推导**,
拿它们互相印证是 OPS-17 抓到的那个病(两边一起错,旗子永远绿)。
这一条的两侧**来自两套完全不同的表**(总账 vs 单据),
而它的 `unexplained_base` **没有兜底桶**,所以它动得开。
**它是财务模块里唯一一处「对不上就真的会红」的地方,而没有任何一张子页面在说它。**

## 8 · 一条给下一个人的话

**如果某个模块最有用的 Overview 需要系统没有的数据 —— 说出来,建做得到的那一半。**

## 9.3 §6 那条返回条件:`work_order_variance_beyond` 【没有】搬

§6 写着「建运营 Overview 的那一刀,把对应那一支一起搬过去」。**本刀没有搬,
而这是一个有意识的取舍,不是遗漏。** 代价与理由:

* 搬一支要动 `operations_now`(一次视图迁移)+ fixture 111 的 `v_expected`
  + i18n 的后缀集合;而本刀已经带着一支**删表**的迁移(`user_dock`),
  再叠一支视图迁移会让这一刀的破窗从"什么都不坏"变成要逐项论证。
* ★ **而"两处都画"这件事本刀【避开了】** ★:运营 Overview 那一条说的是
  **「有计划的工单条目里有几条与计划不一致、差得最远的是哪一条」** ——
  它**不读那个阈值**(阈值住在 `processing_settings`,复制它就是第二份实现),
  所以它与提醒页那一支**粒度与主语都不同**:那一支说「这一炉超阈了,去看看」,
  这一条说「这个模块此刻偏得多开」。**不构成 §3 禁止的那种两份实现。**

**返回条件原样保留,而且现在更便宜了**(那一页已经在了,只剩视图与 fixture 那一半):
撤那一支 = 把它那一行移进 `dashboard-arm-inventory.md` 的「考虑过又排除」并写下理由,
**不是删掉**。`output_unsold_aging` 的家仍然是库存 Overview,而那一页仍未建。
