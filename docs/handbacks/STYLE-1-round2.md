## 4 · 量的时候撞见的三件事(全部实测,已写进规格 §7)

### 4.1 ★ C 的表头线写的是 `border-b-2`,在取样页上**渲染出来是 1px**

实测那条线:`border-bottom-width: **1px**`,颜色 `rgb(0,142,188)` = `#008EBC`。
**颜色赢了,粗细输了。**

**机制(查实,不是猜):** `app/components/ui/table.tsx:26` 的 `TableHeader` 带着
`[&_tr]:border-b`,编译成一条**后代选择器**(特指度 0,1,1);
行自己的 `border-b-2` 是普通类(0,1,0)。**特指度高的那条 1px 赢了。**
(`cn()` 已把行上的 `border-b` 合并掉 —— 行的 class 串里只剩 `border-b-2`,它仍然输。)

> ★★ **而已上线的那条路是对的:** `data-table.tsx:391` 用的是**裸 `<thead>`**,
> 不经过 `TableHeader`,**实测渲染 2px `#008EBC`**。
> **所以标准值是 2px,`<DataTable>`(98 个文件在用)今天已经对了;
> 那个 1px 只出现在 `table.tsx` 这条路上,而它至今仍在 `GUARDED` 里、禁止使用。**
>
> ☞ **这一条只有实测量得出来。** 读 class 串会读到 `border-b-2`,
> 然后写下一个**从来没有在屏幕上出现过的 2px**。
> 这正是委托书要求「把推算换成测量」的价值所在。

## 4A · ★★ 量具自己的两条缺陷 —— 它们花掉了一次完整的 141 条读数 ★★

**这一节写在漂移数字前面,因为它比那些数字更值得下一个人读。**

### 4A.1 发生了什么

`--mode=drift` 第一跑:桌面 141 条**全部量完**,手机那一半跑到第 10 条,
然后**34 分钟一行输出都没有**。诊断(按 AGENTS.md 那三条判据,逐条量):

| 判据 | 实测 |
|---|---|
| 日志还在长吗 | **不长**(mtime 停在 34 分钟前) |
| 进程还在吗 | **全都在**,`ppid` 正常,不是孤儿 |
| 有 `*_EXIT=` 那一行吗 | 没有 |
| ★ **chrome 的调试端口应答吗** | ★ **`curl -m 8 /json/version` → `CURL_OWN_EXIT=28`,`http=000`** |

**结论:chrome 整个卡死了 —— 不是那一页,是浏览器。**
(这正是 `scripts/survey-phone.mjs` 抬头记着的那一课:「一次长扫描最终会把渲染器
卡死……一个失败形态会冒充成发现的探针,比没有探针更坏」。**我读过那句话,
然后在自己的量具里重犯了它。**)

### 4A.2 ★ 缺陷一:一句 `catch {}` 把【浏览器死了】吞成了【还没就绪】

```js
for (let i = 0; i < 120; i++) {
    await sleep(500)
    try { … const r = await S('Runtime.evaluate', …); if (r.result.value) break }
    catch {}          // ← 这一行
}
```

CDP 的默认超时是 60 秒。渲染器一卡死,**每一圈都抛,每一次都被这行吞掉** ——
120 圈 × 60 秒 = **一条路由卡两个小时,而日志上一个字都不会多**。

> ★★ **它不是"假装成一个发现",是假装成【进度】。** ★★
> 屏幕上看到的是「phone 10/141 …」,和一支正在慢慢干活的脚本**完全一样**。
>
> 本仓库对这个形状有明文规矩 —— **「一次失败不是一个空集」**、不许 `?? []`、
> `.catch(() => …)` 是 `check-error-swallowing` 明令要抓的东西。
> **而我把它写进了一支【用来证明别的东西没瞎】的量具里。**

**改法:** 连续三次拿不到答复就**当场抛**,就绪轮询的超时压到 15 秒(它要的是
快速失败,不是等满一分钟),整条路由再加一个 45 秒的墙钟上限。

### 4A.3 ★ 缺陷二:只在收尾写一次盘 —— 于是一杀,141 条完好的读数一条不剩

JSON 只在**两个视口都跑完之后**写。手机那一半卡死,一杀,
**桌面那 141 条(15 分钟、零失败)一条都没留下。**

**改法:** 每 10 条路由、每次失败、每个视口跑完,各落一次盘。
**一支要跑半小时的普查,它的中间结果必须在盘上。**

### 4A.4 ★ 恢复要分两级 —— 而"换标签页"这一级【单独是不够的】

`survey-phone.mjs` 的处置是「换一个标签页」。**这一次那不够:**
卡死的是**整个浏览器**,`Target.createTarget` 本身就超时。
所以恢复是两级:**先换标签页;换不动就重开 chrome。**
另加**主动回收**:每 25 条路由换一次标签页,不等它卡了再换。

### 4A.5 ★★ 故障注入:三条恢复路径都【看着它红过】,不是推的 ★★

跑一次 `--limit=20`,在第 10 条路由处 **`pkill -9` 掉 chrome**,实测:

**而且那条被杀掉的路由留下了痕迹**:JSON 里 `desktop total 20 · ok 19 · failed 1`。
**一条量不到的路由必须是【未测量】,不能悄悄消失** —— 否则它与"这一页没有控件"
在读数上完全一样。

**落盘那一条也当场验了:** 注入跑到第 10 条时,盘上**已经有一份 548KB 的 JSON**
—— 也就是说这时候杀掉它,前 10 条不会丢。

> ☞ **这两条缺陷都不是任何断言发现的。** 覆盖断言全绿(它们量的是读数内容,
> 不是量具活着没有),致盲也全对。**发现它们的是「日志 34 分钟没动」这个观察,
> 以及随后那条 `curl -m 8`。** 与 STYLE-0 那三处缺陷同一条:
> **真正的缺陷是靠把输出读回去抓到的,不是靠断言。**
