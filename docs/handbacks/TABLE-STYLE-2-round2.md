## 3 · ★★ tableC 碰上一张【没有列头】的表会怎样 —— 答案是【它自己降级得很干净】★★

### 3.1 逐段拆开看:五段里三段与列头无关

| tableC 的段 | 内容 | 依赖列头吗 | 无列头时 |
|---|---|---|---|
| `root` | `border-collapse text-sm` | **否** | **生效** —— 而且它是**行高的来源**(STYLE-1 §2.4 那 1.07px) |
| `headRow` | `border-b-2 border-ocean` | **是** | **没有元素可挂** |
| `headCell` | `px-3 py-2.5 text-[15px] font-medium` | **是** | **没有元素可挂** |
| `cell` | `px-3 py-2.5 text-[15px]` | **否** | **生效** |
| `bodyRow` | `border-b border-brand-border` | **否** | **生效** |

**五段里三段照常生效,两段只是【没有目标】—— 不是冲突,不是回退,是没有那个元素。**

### 3.2 决定:**照原样用,不造"无列头变体",也不给它加一行列头**

**理由一(硬的):** variant C 的定义是「**素表 + Hawaiian Ocean 表头线**」。
把表头拿掉,剩下的是「**素表**」——**那本身就是一个完整、自洽的东西**:
行与行之间 1px 分隔线、格子之间没有竖线、行没有斑马纹。它不需要一个新变体去描述。

**理由二(更硬的):** `variant-c-spec.md §6` 自己立的规矩是
「**取样页里没有的元素类型,它没有标准 —— 说出这句话是诚实的结果,
而不是一个应当拿一个我挑的数去填的洞**」。
取样页里**没有**无列头表格。**造一个"无列头变体 C",就是拿我挑的数去填那个洞。**

**理由三:** 加一行列头 = 委托书 §2 明写的「**that is the conversion this class was ruled out of,
arriving by another door**」。

### 3.3 ★ 而它有一个【看得见的代价】,量出来了,登记在这里

**实测(三张穿好的表,390px 与 1280px 读数一致):**

```
格子边框   1/1/1/1  →  0/0/0/0        ← 整圈灰格子没了
行底线     0        →  1px rgb(202,213,224)（--brand-border）
```

☞ **于是一张无列头的表【失去了它的外框,而且顶上没有任何一条线】** ——
有列头的表靠那条 2px Hawaiian Ocean 线收口,无列头的表**第一行就那么开始了**。

**我没有替它补一条线**,理由见 §3.2 的理由二。**但这确实是一处"标准没说"的地方**,
所以照 `variant-c-spec.md §2A.1` 的先例**摆在这里,不替 Tim 决定**:

> ### 候选例外(未裁):**无列头的表要不要一条顶线?**
> * 现状:**没有**。四张穿好的表,顶上都是空的。
> * 支持"不加":C 就是素表;每一张的上文都自带收口 —— ① 有 `<h1>` + 一句说明,
>   ③ 有 `<h3>`,④ 有 `<h2>` + `border-t pt-6`,② 整个泡在一个红色告警框里。
> * 支持"加":那条 2px 线是 C **最显眼**的特征,而这一类表**永远看不到它**。
> * ☞ **要裁,请裁一个值;我不挑。**
