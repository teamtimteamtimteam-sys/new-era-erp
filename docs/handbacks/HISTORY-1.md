## §8 · Decisions I took without asking

1. **Where the bindings live:** one generated file, `db/views/zzz_change_log_triggers.sql`, not two lines in each of 238
   table mirrors. This follows the `zzz_function_grants.sql` precedent; `check_mirrors` compares trigger lists per
   table, not by file.
2. **Batching the trigger creation:** the migration creates all 495 new triggers in **one `DO` block, placed late**.
   The first dry run showed 626 s of statement-by-statement round trips while holding write locks on 238 tables.
3. **The restricted marker:** it is the JSON value `{"$restricted": true}`, inline in `old` / `new`. A genuinely null
   value stays null, and the screen draws the two differently. Rules resolve a field they need from the log image, then
   the live row, then the latest log row for that key. An unknown rule fails closed.
4. **`purchase_order_history` payment-term snapshots:** `old_payment_term` / `new_payment_term` are masked **whole**, not
   by the `fixed_amount_ccy` key inside them. I also added `old/new_fx_rate`, matching `purchase_orders_masked.fx_rate`,
   to the columns HISTORY-0 named.
5. **Account-event order:** record first, then call auth. On an auth failure, a `*_FAILED` row is logged and the error
   is shown. If `ACCOUNT_CREATE` can't be recorded, the new account is deleted and the user is told nothing was left
   behind.
6. **The permission check on the redaction function:** `change_log_redact_employee` checks `action.anonymise_employee`
   itself, as well as having EXECUTE revoked.
7. **Fresh installs:** the new code is **not** added to the fresh-install `role_permissions` bootstrap. The file says
   new codes go to admin only by migration, and `cfo` isn't a bootstrap role. On a fresh install, the admin grants it.
8. **Paging:** "Newest" and "Older" only, not "Newer". Keyset paging backwards would need a second cursor, and the brief
   asked for newest-first, 50 per page.
9. **The actor cell:** it is drawn from the reader function's own email and employee name, not `ActorName`. The row must
   show both the account and the employee (Q26); `ActorName` shows one of the two.
10. **Shared date input:** `/settings/deleted`'s two date boxes now use the new `DateFilterInput`, with no visible change.
    The native-date ratchet only allows the count to go down; it went 135 → 134 (`scripts/date-format-baseline.json`).
11. **`EXPECTED_TABLES`:** 241 → 242 in `scripts/check-document-registry.mjs` (adds `change_log`).
12. **The known-issues entry for reader cost:** `HISTORY1-READER-SCALE`, as well as the two the brief asked for.
13. **Fixture style:** the masking arms of fixture 234 insert synthetic `change_log` rows directly. They test the
    **reader**; the capture is tested separately by arms A–F.
