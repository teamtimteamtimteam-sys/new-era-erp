## §7 · ★★ 本刀唯一动到的既有断言 —— `fixtures/120` 的 F5(d),**而承诺一个字没变**

**它在 `--offline` 那一相就红了,而红得对:**

```
FIXTURE 120F5 失败:进入 F5(d)—— **不该有任何函数或视图读 planned_in_service_date**
```

**原判据(2026-09-08 落地)**:扫全库函数体与视图定义,**出现这一列的名字就算数,必须是 0 处**。
**那一天它是精确的** —— 因为当时唯一写这一列的地方是应用里一条直连 `.update()`,
**它不是函数,于是照不进目录里**。

☞ **而 C1 把那条直连写换成了一支函数。任何形状的函数门都会撞上一条纯文本扫描。**
**原判据不是错了 —— 是它的【实现】(文本包含)比它的【承诺】(没有规则【读】它)宽,
而那个差额以前恰好是 0。**

### 改法:**不放松承诺,而是把豁免钉死成三条**

| | |
|---|---|
| ① | 除 `set_asset_planned_in_service` 之外,**仍然是 0 处** —— 逐字同原判据 |
| ② ★ | **那支被豁免的函数自己也不许【读】它**:它拿的是整行(`v_a fixed_assets%ROWTYPE`),所以要读只能写成 `v_a.planned_in_service_date`。**禁掉那一个形状 = 它只能赋值,不能据此判断。** 将来谁加一句 `IF v_a.planned_in_service_date … THEN`,这一臂当场红 |
| ③ | **那支函数必须真的在** —— 一个指向空处的豁免会让 ① 与 ② 两条判据都变成空转,而那正是本仓库反复付账的「报告了却不拦」 |

★ **原文与它的日期原样留在文件里,更正另起一块**(本仓库的规矩)。
☞ **我没有把这当成"顺手放宽一条挡路的断言"** —— 一条断言挡住了裁定要的形状时,
要问的是「它的承诺变了吗」。**承诺没变:一个"打算"仍然不许产生"已经发生"才该有的后果。**
