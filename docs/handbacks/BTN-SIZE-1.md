### ★★ 但机制不是委托书说的那条,而这一条要紧

委托书:「they render at 30px today **with border-width 0**, and the shared Button's base
string carries `border border-transparent`, which adds 1px top and bottom」。

`border border-[color:var(--brand-border)]`,**不是 0**。

**真正的机制是【换了个来源定高】:**
· 改前 = 20px 行盒 + `py-1`(4+4) + 边框(1+1) = **30px**
· 改后 = `size="default"` 的 **`h-8` 直接把高度钉成 32px**(`box-sizing: border-box`,边框画在里面)

★ **两条路得数相同、道理不同。** r3 在**排序钮**上量到的那个 +2px 才是委托书说的那条机制
(**那一颗的 `border-width` 确实是 0**)。
☞ ★★★ **这对 `BTN-TRIGGER-1` 那 33 处直接有用:判据不是「转过去就 +2」,
是「先量这一颗今天的 `border-width`,以及它的高度今天是谁给的」。**
一个已经有 `h-*` 的裸控件转过去可能是 0;一个 `border-width: 0` 又没有 `h-*` 的才付那 2px。

### 9.1 ★★★ 一份委托书可以把一件【不存在的工具】当成既有事实交下来

委托书说「用 round 3 加的那个 `--urls=` 口子」。**那个口子不在仓库里。**
☞ 这是 `AGENTS.md`「委托书里的【数】来自上一份报告」那一条的**新形状**:

然后把差额补上并说出来 —— 而不是找一个够得着的替代品悄悄绕过去。

### 9.2 ★★★ 一条停止条件照字面读会与它自己的授权矛盾时,该写断言,不该写措辞

(e) 说「除那两个成员外一律不变」,而 A4 授权那两个成员长高 2px。
**一个盒子装着长高 2px 的孩子,按构造不可能保持原高。**
☞ 最省事的写法是「祖先当然会跟着动,不算」—— **而那是一句措辞,不是一个读数**,
`AGENTS.md` 记着「一条【已经触发】的停止条件被措辞读成一条【还有余量】的」。
★ **处置:把那句措辞拆成三条能被机器验的判据,再对它做一次故障注入。**
☞ 结果是同一个「通过」,但它现在**说得出自己为什么通过,也证明过自己会不通过**。

### 9.3 ★★ 一个「9」错了两次,而第二次比第一次值钱

委托书说 E6 有 9 个输入框。实测 10 个,**其中 4 个是原生 `<select>`**。
