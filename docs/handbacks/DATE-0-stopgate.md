# DATE-0 —— 停止闸:日期格式那一刀的勘察(2026-09-20)

> ### ★ 这份文件【没有写一行代码】。它到这里停住,等 Tim 的裁定。

**Tim 的要求逐字:** 系统里每一个日期都显示成 `01 Sep 2026` —— 日、月名、年。
**他的抱怨逐字:** 日期选择器显示 月/日/年,别处又是别的格式,**同一个日期在一次会话里读出三种样子。**

## 0 · 一句话的结论,以及那个决定刀口大小的答案

> ### ★★★ **这一刀是【两把刀】,而它们的价钱差一个数量级。**
>
> | | 是什么 | 大小 | 便宜吗 |
> |---|---|---|---|
> | **显示那一半** | 把打印出来的日期统一成 `01 Sep 2026` | **314 处 / 138 个文件** | ★ **便宜** —— 它是"加一个函数,再逐处调用" |
> | ★★ **选择器那一半** | 把录入日期的控件统一 | ★ **130 个 `<input type="date">` / 85 个文件** | ★★★ **不便宜,而且它【不是一次格式改动】** |

### ★★★ 那个决定性的问题,答案是【不能】

> **`<input type="date">` 按 HTML 规范渲染成【操作系统 locale 的格式】,而那个格式
> 【CSS 够不到、JS 改不了】。** 它是浏览器画的 shadow DOM,没有任何一条标准 API
> 可以把 `9/1/2026` 变成 `01 Sep 2026`。

**实测这棵树用的就是它:**

```
type="date"            130 处 / 85 个文件
type="datetime-local"    4 处
type="month"             6 处
共享的日期控件组件        ★ 一个都没有(app/components/ui/ 下没有 date 相关文件)
日期库(date-fns/dayjs/…) ★ package.json 里一个都没有
```

☞ **所以"选择器也按 `01 Sep 2026`"这句要求,实际含义是:
在 85 个文件里把 130 个原生控件【整个换掉】,换成一个自己写的日历控件。**
那与"改一处打印格式"不是同一种活 —— 它要新写一个控件(键盘可达、屏幕阅读器可读、
手机上可用、中英双语月名、可清空、可键入)、再逐处替换、再逐处回归版式。

★★ **而它还要付一笔【本仓库已经反复付过】的账:** `docs/variant-c-spec.md` 与
INPUT-2/2b 整整两刀,就是在处理"原生控件的宽度由内容决定,换一次样式就是一次版式改动"。
**换掉控件本身,是那件事的最大号版本。**

❓ **Q2 — 「每一个日期」包不包括【时间戳】?** schema 里 `date` 列 **130 个**(76 张表),

## 3 · ★★ 分母,以及它是怎么数出来的

> 委托书要求:「**读它住的那个空间,不要 grep 一个函数名** —— 一个只认识一条路的扫描器
> 会为错的总体报出一个自信的数字。**说出你的分母,以及你是怎么数的。**」

### 3.1 量法

★ **不按函数名枚举,按 P 住的那个空间枚举** —— `db/tables/*.sql`(线上结构的镜像)里
**每一个 `date` / `timestamptz` 列名**。那是一个**闭合集合**:屏幕上的一个日期,
必然是其中某一列的值,或者由它算出来的。

```
schema 里的日期列名(闭合集合)  149   (date 91 · timestamptz 58 —— 按【去重后的列名】)
                                       ★ 按【列】数是 130 date + 379 timestamptz / 76 张表
app/ 下走过的源码文件             902
★ 命中的引用处                   1327
★ 带日期引用的文件                369
```

### 3.2 ★ 再切一刀:**这一处【是不是一次渲染】**

「1327」不是这一刀的分母 —— 它把「屏幕上印着一个日期」和「这个值只是被传下去/当过滤条件」
数进了同一格。**报那个数就是 FONT-3 那条「一个计数可以数进屏幕上根本没有字的那几格」。**

| 它是什么 | 处数 |
|---|--:|
| 不是渲染(赋值 / 传参) | 757 |
| ★ **RENDERED(住在一个 JSX 表达式里)** | ★ **257** |
| 不是渲染(`.ts` —— server action / route / helper) | 221 |
| ★ **INPUT value / min / max(选择器那一半,不是显示)** | ★ **35** |
| ★ **PDF 单元格** | ★ **30** |
| ★ **CSV 单元格** | ★ **27** |

> ### ★★ **印到人眼前的那一群 = 257 + 30 + 27 = 314 处 / 138 个文件。**
> **这就是「显示那一半」的分母。**

### 3.3 ⚠ 这支量具【看不见】什么 —— 不许把边界说宽

| # | 边界 | 方向 |
|--:|---|---|
| ① | 它按**列名**认日期。`const d = row.order_date` 之后用 `d`,下游那一处**它看不见** | ★ **会少数** |
| ② | 它按**同一行 ± 一行**的窗口判格式。JSX 把表达式拆得更开时会误判成"没格式化" | ★ **"没格式化"那一栏会多数** |
| ③ | 它只走 `app/`。`lib/` 与 `db/` 里拼出来的字符串不在内(`db/` 那一群单独在 §5 数过) | **会少数** |
| ④ | ★ **它不判屏幕上真的长什么样** —— 那要一次浏览器读数,**本刀没有做**(勘察不写代码) | — |

☞ **所以 314 是一个【量级正确、边界写明】的数,不是一个精确数。**
★ **而它已经足够回答这一刀真正的问题:这是一件三位数的活,不是两位数的。**

### 3.4 ★★ 这支量具自己犯过一次错,记下来比结论值钱

第一版的**分桶**那一层用 `{}` 作桶,而其中一个桶的名字**逐字**是 `toLocaleString` ——
那是 `Object.prototype` 上的一个方法。于是 `(a[k] || 0)` 取到的是那个**函数**,
`函数 + 1` 走字符串拼接,那一格印出来是:

```
function toLocaleString() { [native code] }11111111111111  toLocaleString
```

★ **读取那一层是对的(它确实数到了 14 处),坏的是分桶那一层** ——

## 5 · 存了什么 vs 显示什么 —— 边界在哪里,以及谁跨过它

> 委托书:「**存储格式不在范围内;把边界说清楚,并说明有没有东西把一个格式化过的日期当数据读回去。**」

### 5.1 边界

**存储那一侧是干净的,而且它不需要改:** 库里存的是 `date` / `timestamptz` 两种**真的日期类型**
(130 + 379 列),**没有一列是把日期存成文本的**。☞ **所以这一刀按构造碰不到存储格式。**

### 5.2 ★★ 而【有四条路】会把一个格式化过的日期当数据读回去 —— 逐条点名

| # | 那条路 | 处数 | ★ 格式变了会怎样 |
|--:|---|--:|---|
| ① | ★★ **`<input type="date">` 的 `value` / `min` / `max`** —— HTML 规范**要求** `YYYY-MM-DD` | **36** 处日期列直接喂它 | ★★ **控件【静默地】什么都不显示。** 规范说的是"值不合法就当空值",**不报错** |
| ② | ★ **URL 上的日期过滤** —— `lib/dateFilter.ts` 的 `isYmd()` 只认 `YYYY-MM-DD` | **20** 处 `parseDateRange` · **85** 处 `date_from`/`date_to` | ★★ **不合法就"不过滤"** —— 于是**列表悄悄给出全部行**,而不是报错。**一个算得出来的错答案** |
| ③ | **server action 从 FormData 里读日期字符串** | **34** 处 | 传给库的是一个库解析不了的串 → 拒绝(**这一条是响亮的**) |
| ④ | ★ **`/hr/leave/calendar` 的 `month` URL 键** —— `YYYY-MM`,页面自己拼的 | 1 处 | 同 ② |

★★ **①②④ 三条的失败方式都是【安静的】** —— 与 `AGENTS.md` 反复记的那一族逐字同形:
**「一次失败不是一个空集」**。☞ **所以这一刀最大的技术风险不是"格式改得不好看",
是"一个显示格式漏进了一条当数据用的路,而没有任何东西会红"。**

### 5.3 ★★ 数据库自己在铸日期字符串 —— 23 处,分四族

**改 app 一个字节都够不到它们。** 分族与建议见 §1.2 的 **Q7**。
★ 其中最要紧的一句再说一遍:**4 处把 `'[2026-09-20 14:33 unposted] '` 拼进 notes 列【存下来】** ——
那不是显示,**那是一次写入**,改了格式会让同一列里两种写法**永久共存**。

### 6.2 ★★ Tim 的常设要求:**后加的东西要自己落进规矩里** —— 做得到吗?

| | 做得到吗 | 机制 | 先例 |

★★★ **那个缺口,说准一点:**
今天屏幕上最常见的日期长相是 **`{row.order_date}`** —— 一个**什么都没写**的 JSX 表达式。
**一道棘轮拦得住"你写了一个不该写的东西",它拦不住"你什么都没写"。**
☞ 而"什么都没写"**正是这一刀要修的那 273 处的成因**。

**能把缺口关到多小(建议,按代价从低到高):**

1. ★ **一道棘轮**(上表前两行)—— **便宜、现成、有先例**。它保证**债不再长**。
2. ★★ **把日期从"一个字符串"变成"一个必须被格式化才印得出来的东西"** ——

   ★ 本仓库有一条同形的先例可以照抄理由:`lib/permissions.ts` 存在的全部理由就是
   「`null` 已经有主了,所以拒绝不能用 `null` 表示」——**让错误的写法【构造上不可能】,而不是靠记。**
3. **一次性把 273 处改完** —— 它解决今天,**不解决明天**。

➡️ **我的建议:这一刀做 1 + 3(棘轮 + 把今天的 273 处改完),把 2 登记成一条带理由的债。**
🔎 理由:2 是唯一治本的,但它把一件"改显示"的刀变成一件"改取数层"的刀 ——
