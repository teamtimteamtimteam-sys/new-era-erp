## §1 · 今天存在的「第二个人」—— 一共就这么多

**量法:** 线上 `pg_proc` 里,正文调用 `forbid_self_approval(` / `assert_segregated(` / `require_approver_for(` /
`approvals_enabled(` 的函数;再加 `approval_chain_gates()` 与 `approval_gate_intersections()` 的输出。
`finance_settings`:`approvals_enabled = t`,一级 `finance`、二级 `cfo`,门槛 `approval_threshold_base = 1000`(SGD)。

| 机制 | 管到哪些动作 | 说的是什么 |
|---|---|---|
| **分级审批**(`require_approver_for`) | **只有两条链**:采购单批准/驳回 · 报销单批准/驳回 | < SGD 1,000 财务批(CFO 也可以,「上级可批下级」);≥ 1,000 只有 CFO 批 |
| **不许自批**(`forbid_self_approval`,按人认) | 采购单 · 报销单 · 请假 · 医疗报销 · 绩效评估 · 工单下达 · 盘点过账 | 建单人不能批;请假/医疗/报销/评估还加一条:**被批的那个人**也不能批。唯一例外:CFO 本人的报销/医疗报销可以自批,但被标记(`self_decided`) |
| `SOD_PAYEE_AND_PAY` | 付款 | **建这个供应商的人**不能给这个供应商付款 |
| `SOD_POST_AND_CLOSE` | 锁期(`locked_before`) | 在被锁那段期间里**手工过过凭证的人**不能锁它 |
| `HANDOVER_SAME_PERSON` | 交接班 | 交班人与接班人不能是同一人 |
| 采购单金额上调 | 改采购单 | 金额往上改会**作废已有的批准**,要重批(`void_approval_on_amount_increase`) |

**除此以外的每一个动作,今天都是「一个人做完就生效」。**

## §4 · 你的答案会要求系统做什么 —— 先知道价钱再作答

**今天做得到的(填了就能配,不用新代码):**
* **换掉某一个权限码的持有人**:给谁加 / 撤角色,或改角色带的码。例如「只有 CFO 能锁期」= 把 `module.finance.edit` 的分配改掉 ——
  但注意一个码管着一整族动作(`module.finance.edit` 同时管付款、开票、手工凭证、月结……),**今天没法只拿走其中一件**。
* **改两级审批的角色与门槛**(采购单与报销单共用)。
* **在已有的七条「不许自批」链上**,谁批谁不批,由上面这两件决定。

**今天做不到、需要新建的:**
1. **所有带金额的单据共用【同一对】一级 / 二级角色和同一个门槛。** 若你在不同单据上填不同的审批人
   (例如「采购单 CFO 批、报销单财务批」),需要一个**按单据类型设置审批人**的配置 —— 今天不存在。
2. **一件事没有「待批」状态,就挂不上审批。** 表里写「目前没有待批这一步」的每一行(付款、费用、发票、凭证、
   工资过账与发放、资产处置、加工提交、进料定价、直接销售、发货……),要先给它造一个**申请 → 批准 → 执行**的生命周期
   (有一个等待的状态、把过账推迟到批准那一刻、拒绝的路径、屏幕)。付款申请那一刀已经在排队;其余每一种都是各自一刀。
3. **「做的人不能是批的人」之外的职责分离,今天只有 §1 那四条**(付款 vs 建供应商、锁期 vs 手工凭证、交接班、
   采购单改价作废批准)。你若填出新的「甲做了 X 就不能做 Y」(例如「录盘点数的人不能过账」「建供应商的人不能批准它」
   「过工资账的人不能付工资」),每一条都是一条新的检查,多半还要先让系统**记下是谁做了 X**
   (例如盘点行今天只记 `created_by`,没有「谁数的」)。
4. **一个权限码管一整族动作。** 若你在同一模块里对不同动作填不同的人(例如「财务能记付款但不能月结」),
   需要把那个码拆开 —— 这是权限模型的改动,不是配置。
5. **「做」与「看」今天不联动。** 仓库能填一个它看不见的价格(§2.8、§2.10 的 ★)。若你的答案是「谁看不见价格就不能定价」,
   那是一条新规则,要加在数据库里(不只是藏掉输入框)。
6. **没有持有人的角色**(HR、采购、销售、审计、员工)可以直接拿来用;「运营」已删除,要用得先恢复或另建。
