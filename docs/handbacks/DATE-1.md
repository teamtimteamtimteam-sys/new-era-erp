### ★★ 为什么 314 / 273 与我的数不可比 —— 这是本节最要紧的几行

DATE-0 的判据是「**这个日期【住在一个 JSX 表达式里】**」。本刀发现,
**这棵树最常见的日期显示不长那个样子:**

```
app/inbound/page.tsx:254          arrivalDate: b.arrival_date            ← ★ 要改的是这一行
app/inbound/InboundTable.tsx:124  render: (b) => b.arrivalDate ?? '—'    ← 印出来的是这一行
```

服务端那一页把日期**投影成一个别名字段**,客户端那张表再渲染那个别名。于是:

* 渲染那一行里**没有任何一个日期列名** → 按列名扫的判据**看不见它**;
* 投影那一行**不在任何 JSX 里** → 按「住在 JSX 表达式里」扫的判据把它记成
  **「不是渲染」**(DATE-0 那 757 处里就有它)。

> ### ☞ **而【要改的那一行就是投影那一行】。**
> 两支扫描器一个把它丢在分子外面、一个把它丢进"不是渲染"里,
> **而它是这一刀的主要工作量**(393 处里 **179 处**是这个形状)。

这不是"漏扫"。它是 AGENTS.md 那一条:**判据认了一个【属于别人的】性质** ——
它问「这个日期**印在哪儿**」,而该问的是「这个日期**在哪里变成给人看的字**」。
☞ **跨文件的别名(页面 → 表格组件)是文件内不动点按构造跨不过去的那一步**,
本刀也没有跨过去 —— 我是**换了计数的单位**,不是把那一步补上了。

### ★ 本刀自己那支量具犯过的四个错,照直记(它们比结论值钱)

1. ★★ **DATE-0 §3.4 那个坑,本刀原样踩了一次。** 它写着「下一支按名字分桶的扫描器会再犯一次」——

   `function toLocaleString() { [native code] }11111111111111` —— `{}` 作桶,
   桶名 `toLocaleString` 撞上 `Object.prototype`。修法 `Object.create(null)`。
   ☞ **一条写下来的预言,一刀之后成真。**
2. ★ **覆盖断言的第二条路是假的。** 计数器放在判据函数里,于是它数的是

   而 AST 一个字节都没少走。☞ 一条依赖第一条的第二条路,不是第二条路。
3. ★★ **判据把「提到日期这个词」当成了「值是一个日期」。** 第一版把
   `const openRow = rows.find(r => !r.ended_at)` 学成"携带日期",于是

4. ★ **审计戳的那个正则锚错了位置。** 写的是 `/^(<动词>)_at$/`,于是
   `self_assessment_submitted_at` / `import_permit_verified_at` /

   ☞ **错的不是那条规则,是那条规则的形状。** 改成按后缀匹配。

## §X · ★★ 本刀自己造出来的一个缺陷,以及它是怎么被抓到的

> ### **这一节写在最显眼的地方,因为它差点上线,而抓到它的不是任何一道断言。**

### 缺陷

`lib/dates.ts` 的 `formatDate(null)` 按设计返回 **`'—'`** —— 屏幕上要的正是这个。
而批量改写把它用在了**投影**上:

```
inServiceDate: formatDate(a.in_service_date, locale)        ← ✗
```

于是一个本来是 `null` 的字段变成了字符串 `'—'`,而 ★ **`'—'` 是真值**。
下游每一处 `x ? … : …` / `x ?? …` 当场翻边。实测的两处后果:

* `app/finance/assets/AssetActions.tsx` 那句「这台设备已经投用」的**拦阻信息,
  对【没有投用】的设备也显示了** —— ★ 那不是少了一句话,是**屏幕主动说了一句假话**,
  而且它**拦住了一个合法动作**(去投用这台设备);
* 同一个组件里 `useState(plannedInServiceDate ?? '')` 拿到 `'—'`,而那个 state
  喂的是一颗 `<input type="date">` —— ★★ **HTML 规范说值不合法就【当空值处理,不报错】**,
  控件就那么空着。☞ **那正是 §3 ARM 1 要防的那条路,而它绕过了 ARM 1**:
  格式化发生在**另一个文件**里,ARM 1 按构造看不见跨文件的那一步。

### 它是怎么被抓到的 —— ★ 被一个【看起来荒谬的读数】

`--mode=drift` 报 `/finance/assets` 的手机行高 **109.5 → 465.5(+356px)**,
而 ★ **那张表的列宽逐字未变**(`colW` 两侧完全相同,`shellW`/`shellScrollW` 也相同)。

> ★★ **一个"行高涨了 356px 而宽度一个像素没动"的读数,是一个【说不通】的读数。**
> 它与 DATE-0 §3.4 那个 `function toLocaleString() { [native code] }1111` 是同一族:
> **被荒谬抓到,不是被任何断言抓到。**
> ☞ 而 AGENTS.md 对那一族的评语逐字适用:
> **「假如那个桶名叫 `valueOf`,输出会是一个安静的数字,没有人会去看它。」**
> —— 这一次假如那两行的行高只涨了 3px,我不会去查。

### 判据(它就是本仓库 CLEANUP-A 那一条,换了个场景)

> ### **这个值的 `null` 是不是【已经有主】了?**
> 有主 = `null` 在表达一个**合法状态**(「这台设备还没投用」),而且**有人在读它**。
> 是的话,一个把 null 映射成显示串的格式化函数,就是
> **把「缺失」伪装成一个合法答案** —— 它会渲染成那个合法状态,
> 于是**没有任何人、任何时候会看见它**。

### 处置(三层,由外向内)

1. **规矩**:投影 / 传给组件当 prop 的 → **必须保 null**;直接印在 JSX 里的 → 不必。
   写进 `lib/dates.ts` 的抬头 —— **下一个伸手拿这支函数的人在那里读到它**。
2. **落地**:问 **TypeScript 的类型检查器**,只对**类型上真的可能是 null** 的那些加守卫。
   实测 **202 处投影里 34 处**可能是 null,全部改成 `v ? formatX(v, locale) : null`;
   其中 **6 处**消费端类型非空(作者已用 `as string` 断言过),兜底改 `'—'` ——
   **与改前的行为逐字相同**。
3. ★★ **一道闸**:`scripts/check-date-null-preserved.mjs`(进 `npm run build`,**实测 ~2s**)。
   **故障注入:把那一处缺陷原样装回去,它点名了 `app/finance/assets/page.tsx:156`**
   并说出了后果;还原后回绿。致盲注入 → `NULLPRES_OWN_EXIT=2`(说「我瞎了」,不说「干净」)。
   ⚠ **它够不着的那一半也写在它抬头上:一句 `as string` 能让它闭嘴** ——
   与 AGENTS.md「一句 cast 关掉的正是唯一看得见这一处的检查」逐字同形。
