### 2.4 ★★ 而第 7 张我【没有转】—— `AttendanceGrid` 是一张归错类的 B ★★

普查把它记成 **C(只读账簿)**,而 C 的判据是「`rows.map()` 出来的**只读**表」。
**照源码读它不是:**

* 它的行**不在 `<table>` 块里** —— `<tbody>` 里只有一行 `<LineRow …/>`,
  格子由 `LineRow` 这个子组件画。**TABLE-CONVERT-2 §2.4 早就量到过这一条**
  (「行画在 `<table>` 块外面:1 张,就是它」),而 §2.5 也预先说过
  「它读的是写法,不是行为」。**普查的扫描器看不进 `LineRow`,于是把
  7 个受控输入读成了 0 个,把一张录入网格读成了一张只读账簿。**
* `LineRow` 里有 **4 个受控 `useState`**(normal / restDay / holiday / note)
  与一颗逐行保存钮,提交走 `recordAttendance(row.lineId, …)`。
  **不带 `name`** —— 所以它不撞过滤器 ③,但它正是普查 §6.2 里 **B 类**的定义:
  「受控 React 输入,不走 `name` … ✅ 能转,**但要建草稿模型**」。

**为什么"建草稿模型"不能顺手在这一刀做:**
DataTable 自己画 `<tr>`,每个格子只是一个 `render(row)` 函数,**没有一个能装
每行状态的地方**。而组件把非 priority 列**画两遍**(桌面格一份、展开区一份)——
若把输入写进 `render`,同一个输入框会得到**两份互相独立的 state**:
在展开区里改了,桌面那一份不跟着变,而保存钮读到的是它闭包住的那一份。
今天之所以没有这个问题,**恰恰是因为 `LineRow` 持有那一份 state 并渲染两处**。
要转,就得把 state 提到网格级(`Record<lineId, draft>`)—— 那是**改编辑模型**,
不是换一张表的写法,而且它属于 **B-1 / B-2 那两刀**(EditableTable 从 4 个调用点
扩到 ~12 个)。在这里另造一套一次性的草稿模型,等于抢在那一刀前面给它定形。

☞ **处置:交回,不转。** 与 TABLE-CONVERT-2 §3.1 交回 `month-end:206` 同一个形状。
☞ **顺带更正一个数:C 类不是 43 张,是 42;B 类不是 10 张,是 11。**

### 7.1 ★ 头三次跑出来的读数是【错的】,而它长得像一条结论

处置是加一颗**水合自检钮**(点一下让一个计数器 +1),把两件事分开:

```
第 1–3 次   beat before: 0 → beat after: 0    ✗ 没水合
第 4 次     beat before: 0 → beat after: 1    ✓ 水合了,6 颗展开钮点开,读回 6 个 <dl>
```
