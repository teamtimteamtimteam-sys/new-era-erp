## 5 · colSpan 怎么在两个断点上各自算对,以及折走的合计去哪

### 5.1 ★ 难处不在"加一个 tfoot",在【colSpan 不能随断点变】

全仓 6 张手搓表为这一条把标签格**写了两份**(`trial-balance:234/242` ·
`payables:309/321` · `receivables:300/315` · `quotes:190/194`),两份的字一模一样,
分开的只是它跨几格。

**空态那一格躲得过去,是因为它只有【一格】** —— HTML 会把跨过头的 `colSpan` 截断,
一格跨多了在屏幕上看不出来。**实测:组件今天的空态两个断点【都跨多了】,而它一直是对的。**
**表尾躲不过去:它有两格以上,标签跨几格【决定了每一个合计落在哪一列】。**
跨多一格,合计整体右移一列 —— 而它仍然是一张排得整整齐齐的表。

### 5.2 组件怎么数(委托书点名要的那一条:用它已经会算的那个)

组件已经知道每个断点上哪几列看得见 —— `isPhoneCol(c) = phoneScroll || !!c.priority`,
空态与展开区都在用它。表尾照用同一个,**调用方一个数字都不写**:

```ts
const cut = 第一个带合计的列在 shownCols 里的下标          // 没有合计 → shownCols.length
desktopLead = cut + (selection ? 1 : 0)                  // 展开钮那格 sm:hidden,不算
phoneLead   = shownCols.slice(0, cut).filter(isPhoneCol).length
            + (selection ? 1 : 0) + (phoneScroll ? 0 : 1)
```

* **标签格写两份**(`sm:hidden` 一份、`hidden sm:table-cell` 一份),各带各的 `colSpan`
  —— 与那 6 张手搓表逐字同形,区别只在**这两个数是组件数出来的**。
* **合计格只写一份**,身上带 `!isPhoneCol(c) && 'hidden sm:table-cell'`,与表体格子同一条规矩。
* **基准从 `shownCols` 数,不从 `columns`** —— 列显隐关掉一列之后表头少一格,表尾必须跟着少。
  (展开区那一处 colSpan 当年就是为这件事从 `priorityCols` 改成 `shownCols.filter` 的。)

**量具怎么验:** 拿【表头实际渲染出来的格数】当基准,不写死数字 ——
桌面 5 格 / 手机 4 格(trial-balance 形状)、桌面 4 / 手机 3(PayrollGrid 形状),
表尾两侧各自与它相等。

### 5.3 ★ 一个合计的列在手机上被折走了,那个数去哪

**答案:叠进手机档的标签格,带上列名。不是省略。**

**这不是我挑的 —— 全仓有三处手写的同一个答案:**
`trial-balance:234`(借/贷两个合计叠进标签格,理由写着"借贷相不相等正是试算表的用处")·
`payables:309`(金额/已结)· `receivables:300`(金额/已结/已贷记)。
**合计跟着列一起消失,那张表在手机上就不再是那张表。**

☞ **为什么不是塞进展开区:** 展开区是**每一行自己的**(点开某一行才出现),
而表尾没有"行"可点。

**实测:** trial-balance 形状 390px 下,`D_120` 与 `C_80` 都出现在手机档看得见的格子里;
PayrollGrid 形状下 `G_7000` 同样在。注入③把这一段关掉,量具当场变红。

## 8 · 我自己拿的主意(逐条,连理由)

1. **`footer` 是一个【函数】,拿到的是「这一屏真的画出来的那些行」。**
   合计的数由调用方算,组件不加总。一张开了 `filter`/`pageSize` 的表,拿全体的合计
   配一屏的行,就是 A1 裁定骂的那种静默的谎 —— 把那几行交到调用方手里,
   **让"对得上"成为默认**。但**不设闸**:`balance-sheet` 的总资产是服务端算的,
   不是这几行的和,那也是对的。

2. **两条新的按名拒绝。** ① 合计挂在不存在的列 key 上 → `throw`(否则那个数
   **从屏幕上无声消失,而表看起来完全正常**);② 合计挂在**第一列**、前导标签没格子可待
   → `throw`(三张实表都是「标签 + 从某列起的合计」这个形状)。与组件已有的两条同一族。

3. **★ 底色与字重【不由组件裁】,从调用方的 `className` 来。**
   `table-style.ts` 抬头与 `variant-c-spec.md §6` 都明写:取样页里**没有** tfoot 合计行,
   **「它没有标准」而不是一个应当由我挑一个值去填的洞**。所以组件只给 `tableC.cell`
   (内边距/字号)与 `tableC.bodyRow`(分隔线),`bg-gray-100 font-bold` 那类由调用方写。

4. **组件开始 import `tableC`。** `table-style.ts` 抬头自己写着这是它的验收条件
   (「`data-table.tsx` 也能消费它」)。**只用在表尾,既有渲染路径一个字节没碰**(§6.1 逐字节证)。
   `app/components/ui/` 是 `check-component-library` 的 `LIBRARY_DIR`,不进 cellfont 计数 —— **实测 313 没动**。

5. **样例表补到两张**(§2.2)—— 致盲注入逼出来的,不是设计时想到的。

6. **`/me` 换成 `/inbound/<id>/edit`**(§6.2)。
