CHART-0(2026-09-02)。**本文件是只读勘察,一张图都没有建。**

Tim 已裁定图表要加,并且裁定"没有数据不是推迟的理由"(R2)。本文件回答的是

## 〇 · 先说三件把结论压弯了的事

**① 这套系统【已经有图】了 —— 两张,而且它们正是 R5 禁止的那种配色。**

第六次了:又一次勘察的第一句"全仓库没有任何图表"是错的。全文搜过
`<canvas>` / `<progress>` / `<meter>` / `role="progressbar"` / 内联 `width: ${}`,
authored `<svg>`(只有一个,是 TaskBoard 的铃铛图标,不是图):

| 位置 | 是什么 | 用的颜色 |
|---|---|---|
| `app/purchasing/orders/page.tsx:247` | 收货进度条(`receipt_pct`,超收封顶 100%),条后跟着数字 | `bg-gray-200` 槽 + `bg-green-500` 填 |
| `app/finance/bank/statements/[id]/reconcile/ReconcileWorkspace.tsx:346` | 对账进度条(已处理 / 总数) | `bg-gray-200` 槽 + `bg-green-500`/`bg-blue-500` 填 |

两条都是【横向比例条】,都在用 Tailwind 的默认色阶 ——
**R5 点名不要的"图表库默认调色板",在这里以另一种形式已经存在了。**
所以第一批工作里有一项与"新建图表"无关:**把这两条已经在用的图,换成品牌 token。**
它们是今天屏幕上唯一两处"用图形承载数字"的地方,不改的话,新图与旧图会是两套配色。

**② Tremor 已经不合适了,而理由不是口味,是两条硬的。**

`docs/frontend-scoping.md:620` 记的是"Tremor 做图表 —— 今天没有图表可换,
按新功能排期"。那是一条**建议**,不是已经落地的选型;`package.json` /
`package-lock.json` 里没有任何图表库(搜过 tremor / recharts / chart.js / nivo /
d3 / visx / echarts / plotly / victory / apexcharts,零命中)。

今天再看,Tremor 对不上这个栈:

| | 本仓库 | `@tremor/react@3.18.7` |
|---|---|---|
| React | **19.2.4** | peerDependencies `react: ^18.0.0` |
| Tailwind | **v4**(CSS 优先,`components.json` 的 `tailwind.config` 是空串) | v3 路子:要 `tailwind.config.js` 的 content glob + `tremor` 色名空间 |

两条各自都足以否掉它。对照:`recharts@3.10.1` 的 peer 明写 `^19.0.0`,
`@nivo/core@0.99.0` 也写了 `^19.0`。

**③ 但真正的问题不是选哪个库,是【这些页几乎都是服务端组件】。**
Recharts / Nivo / Tremor 全部是 client-only(要 `useEffect` + DOM 量尺寸)。
在一个服务端渲染的表格页上挂一张 Recharts,代价是这一页从此带一个
`'use client'` 边界与一份 JS。而 Tim 要的五种图(线/柱/饼或堆叠柱/面积/横条)
**全部可以用内联 SVG 直接在服务端画出来** —— 没有依赖、没有 hydration、
配色 100% 是我们自己的(R5 的"绝不要库的默认调色板"因此不是一条要守的纪律,
而是一个不可能发生的事)。
**唯一真的需要客户端的是 R5 点名的那件事:悬停 tooltip。** 那是一个很小的
客户端组件,挂在一张服务端画好的 SVG 上,不是把整张图搬到客户端。

> **建议(留给 Tim 裁):内联 SVG 自绘,不装图表库。** 若他要库,
> 那就是 Recharts(唯一一个明确支持 React 19 且不要 Tailwind v3 配置的),
> 但要接受 client 边界与"把它的默认配色全部覆盖掉"这两笔成本。

## 一 · "该不该有图"里,哪一半是量得出来的

Tim 问了这一条。分开如下,**下面第二节的每一格都只填量得出来的那一半**:

**量得出来的(本文件全部实测于线上,2026-09-02)**
- 这一页手上【已经有】的数据,够不够那张图的形状:
  时间序列要**日期维度 + 足够多的相异期数**;构成要**能加总成一个整体的分项**;
  分布要**桶**。
- 线上今天有多少行、跨多少个月/多少个相异日期。
- 那张图要读的数据,是**这一页已经取过的**,还是要**再打一次库**。
- 数据背后的权限码(R3 的受限态要用)。

**量不出来的(是判断,本文件明说是判断)**
- 有没有人真的想看它。
- **一张表是不是已经把这个问题答得更好了** —— 这一条是本勘察最常给出的答案。

**门槛(本文件采用,理由写在这里以便反驳)**:一条折线要有意义,
至少要 **8 个相异时间点**;少于 8 个,柱状图比折线诚实(折线会在两点之间
画出一段并不存在的"趋势")。**两个点连成的一条线不是趋势,是一条线段。**

## 四 · 每张图都要的两个状态(R3)

**空态**:一律是一句具名的话,不是一张画着零的图。
措辞跟已有的那一套走(`common.*` / `dashboard.restrictedHint` 的口气),
**并且要分开两种空**:

| | 屏幕上说 |
|---|---|
| 一行都没有 | 「还没有记录」——**不画坐标轴,不画零线** |
| 有行但不够画 | 「只有 N 条记录,画不出走势」——把 N 说出来 |

第二种是本批的常态(见第二节),**它与第一种必须分得开**:
"还没开始"和"开始了但太少"是两件事,而这个仓库反复付账的正是这条区别。

**受限态**:读不到底层数据的人拿到一条**具名的限制**,不是一张空图。
措辞与顶栏的「· 受限」逐字同源(`common.restricted` + `dashboard.restrictedHint`)。
权限码逐图如上;**唯一的例外是 B5 金属价格,它没有权限门**(`USING(true)`)。

## 六 · 建议的建造规模,以及【不要建】的清单

**不要建(四个,理由都在上面)**
- B2 任务状态构成 —— 三个列头的数字已经答得更好

- B7 加工产出 —— 损耗 0 行,形状不完整(**数据缺口,不是排期问题**)
- 任何"仪表盘首页把六张图堆一起"的做法 —— 本勘察没有为它找到依据

**建(六项,按顺序)**

| # | 位置 | 种类 | 今天有数据吗 | 新查询 |
|---|---|---|---|---|
| 1 | A1+A2 两条既有进度条换品牌色 | (既有) | 是 | 否 |
| 2 | `/finance/receivables` 账龄 | 横条 | **是** | **否** |
| 3 | `/inventory` 流水构成 | 横条 | **是** | 是(一次聚合) |
| 4 | `/hr` 组织架构 | 树 | **否(0 条汇报线)** | 是 |
| 5 | `/metal-prices` 价格走势 | 折线 | 否(每金属 ≤2 点) | 是(改分页) |
| 6 | `/finance/cash-forecast` 现金水位 | 面积 | **否(0 行)** | 否 |

**五种里用上了四种**:横条 ×2、折线 ×1、面积 ×1,**外加一棵树**。
**柱状图和饼图一个都没落地** —— 柱状图唯一的候选是 B7(数据形状不完整),
饼图在每一个候选上都输给了横条(桶有序 / 类别太多 / 标签太长)。
**R1 说"五种是调色板不是配额",所以这里照直说:饼图今天一个位置都不该有。**

**规模估计**:一个内联 SVG 的图元层(轴 + 刻度 + 条/线/面 + 空态/受限态两个
共用外壳)+ 一个客户端 tooltip + 六个调用点。**两刀**:
先图元层与前三项(它们今天就有数,看得出对不对),
再后三项与 sampler 的测试数据(R2:sampler 喂假数据,真页面等真数据)。
