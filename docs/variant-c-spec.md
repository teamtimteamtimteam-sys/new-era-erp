## 1 · 标准是 variant C,是 Tim 亲自指的

BRAND-1(2026-09-02)渲染了三个成体系的变体,**同一份内容**,让 Tim 指一个。
原始的备选清单,原文照抄自 `docs/brand-tokens.md` §7:

| | 密度 | 按钮 | 表格 | 卡片 | **拒绝态** |
|---|---|---|---|---|---|
| **A · Ledger** | 紧凑 | 实心 | 全边框 | 无投影 | 灰斜体 |
| **B · Workbench** | 宽松 | 描边 | 斑马纹 | 轻投影 | 描边小标签 |
| **C · Brand-forward** | 宽松 | 品牌实心 | 素表 + Hawaiian Ocean 表头线 | 明显投影 | 浅色填充片 |

**「Tim 选了 C」在仓库里有两处独立记录:**

* `app/components/ui/refusal.tsx:21` —— 「「填充色小片」是 Tim 在 sampler 上指的变体 C。」
* `docs/base-components.md:222` —— 「把那十几种收敛成一种(**Tim 在 sampler 上指的变体 C**,填充小片)」

而 `app/brand-sampler/page.tsx:73–83` 里那 9 行 `Spec`,是这套系统里**唯一**一处
把 C 写成机器可读数值的地方:

```js
{
    key: 'brand',
    name: 'C · Brand-forward(品牌前置)',
    cellPad: 'px-3 py-2.5', text: 'text-[15px]',
    primary: 'default', secondary: 'secondary',
    table: 'plain',
    card: 'border-[color:var(--brand-border)] shadow-md',
    headRow: 'border-b-2 border-[color:var(--brand-ocean)]',
    refusal: 'chip',
}
```

<a name="2"></a>
## 2 · ★ Tim 的范围裁定:标准是【整张取样页】,不是变化过的那五个轴 ★

STYLE-0 报告说 variant C「只覆盖 A/B/C 之间变化过的那五个轴」,
并据此把输入框、字体、文件控件划在标准之外。**Tim 否掉了这个说法,原话:**

> 「就算三个选项的输入框看起来都一样,三个也都和我系统里的输入框完全不同。
> 我要的是:**从 A、B、C 里挑一个,然后让系统里【每一个】前端元素都长成我挑的那个** ——
> 不只是 A、B、C 之间有差别的那些元素。」

**所以判据不是那五个轴,是【整张取样页在 variant C 之下渲染出来的样子】。**

> ☞ **一个轴在 A/B/C 之间没有变化,不等于它在标准之外 ——
> 它属于【从来没有人对它有过分歧的那一部分】。**

### 2.1 这件事本刀量过了,不是转述

把三个变体逐个角色并排比较(同一份内容、同一个视口、同一次渲染):

| 视口 | 三栏**完全相同**的角色 | 三栏**有差别**的角色 |
|---|---:|---:|
| desktop 1440px | **14** | 14 |
| phone 390px | **13** | 15 |

**三栏完全相同的那 14 个角色**(desktop,逐个实测比对签名):

`input.text` · `select.trigger` · `textarea` · `label` · `alert` · `alert.title` ·
`alert.description` · `badge` · `card.title` · `card.header` · `card.description` ·
`h2` · `p` · `button.destructive.default`

**这正是 Tim 说的那件事的实测形态:**
输入框、下拉、多行框、标签、横幅、徽章 —— 三个变体一模一样,
所以它们**从来不是被"选"的那个东西**;而按 Tim 的裁定,
**它们照样在标准里**,只是属于没有人有过异议的那一半。

> **两个视口 14 与 13 的那一个差额【不是】一处样式差别:** 手机上掉出名单的是
> `p`,而它掉出来是因为**同一段文字在 390px 上折行的次数不同**,于是三栏的
> 元素高度不等。**样式一个字节都没差。**
> ★ 值得单独说一句的是:**输入框、下拉、多行框、标签这四个,在【两个视口上】
> 都是三栏完全相同** —— 也就是说 Tim 那句「三个选项的输入框看起来都一样」,
> 在桌面和手机上都是实测成立的。

## 3 · 出处:这些数字是怎么来的

**每一个数字都带着这四件事,缺一不可:**

| | |
|---|---|
| **量的是哪里** | `http://localhost:3197/brand-sampler`,**`C · Brand-forward` 那一节内部** |
| **哪一天** | **2026-09-09** |
| **用什么量的** | `scripts/survey-variant-c.mjs --mode=spec`,chrome-headless-shell + CDP,`getComputedStyle` 解析值 |
| **哪两个视口** | **desktop 1440×900**(`mobile:false`)与 **phone 390×844**(`mobile:true`, dsf=3) |

**下面每一张表都写明了它的值在哪个视口成立。**
只有**两处**值随视口变化(§4.1 标了 ★);其余全部两个视口逐字节相同。

### 3.1 这份读数的覆盖断言

量具跑了 **17 条覆盖断言**(它自己报的数),全部通过:

* 空总体:视口数 ≥ 2;认出来的变体小节 ≥ 4;C 节元素数 ≥ 1;
  `input.text` / `select.trigger` / `textarea` / `label` / `table.th` / `table.td` /
  `card` / `badge` / `alert` / `refusal.sampler` / 按钮 —— **每一类各自 ≥ 1**
* **双向钉住(DOM ↔ 源码独立计数):**
  * 表头格数:DOM **7** = `Variant.tsx` 里 `<TableHead>` **7**
  * 拒绝态小片数:DOM **4** = `data.ts` 里 `REFUSALS` 的键数 **4**
  * 按钮数:DOM **5** = `Variant.tsx` 里 `<Button>` **5**
* **完备性(不按名单走):** 数了 C 节里的**每一个**元素 —— **114 / 159 被角色认领**,
  未认领的 45 个逐标签报出:`div`×26 `span`×14 `tbody`×2 `thead`×1 `svg`×1 `path`×1
  ——**全部是布局壳,没有一个是控件。**

### 3.2 致盲(六种,含一种登记在案的【废】致盲)

| 致盲 | 拿走了什么 | **量具自己的退出码** | 成员名单比对 |
|---|---|---|---|
| `noop` | **什么都没有** | **0** | **0 个成员变动 → 比对器 EXIT 1,判定「这一条不作数」** |
| `pick-a` | 把 **A 那一节当作 C** 交出去 | 0 | ★ **成员 1046→1046(一模一样),而 173 个成员的值变了** |
| `no-variant` | C 的选择器一个都命不中 | **2** ← 红 | 空总体断言:「变体小节实测 3 个,而 4 是下界」 |
| `no-buttons` | 不再把按钮当角色 | **2** ← 红 | 空总体断言:「variant C · 按钮:实测 0 个」 |
| `desktop-only` | 拿掉 390px 那一遍 | **2** ← 红 | 空总体断言:「量到的视口:实测 1 个,而 2 是下界」 |
| `round-height` | 把高度磨成 10 的倍数 | 0 | **成员 1046→1046,而 889 个成员的值变了** |

> ★★ `noop` 与 `pick-a` 是一对,它们证的是同一件事的两面:
> **只看总数,`noop`(什么都没动)与 `pick-a`(把 A 冒充成 C)在屏幕上长得一模一样 ——
> 两边都是 1046 → 1046。** 所以比对器**逐个成员比名单**,不比总数。
> 这正是 SMALL-BATCH-1 与 STYLE-0 各踩过一次的那个坑。

<a name="5"></a>
## 5 · ★ 按钮:三个尺寸档收敛成 `default`(Tim 的裁定)★

**Tim 在 STYLE-1 里裁定:按钮的三个尺寸档收敛成一个 —— `default`。**

**标准值就是 §4.2 那一行:`h-8`(32px)· 内边距 0/10 · 圆角 8px · 字号 14px。**

取样页的内容区(A+B+C 三节 + BASE-1 节)渲染了 **19 颗 `<Button>` 组件,
实测【每一颗的 `data-size` 都是 `default`】** —— 它一次都没有渲染过别的尺寸档。
**所以 Tim 的裁定与取样页的读数完全一致。**

> ⚠ **但同一块内容区里还有 15 个【不是 `<Button>` 的裸 `<button>`】**(实测,
> `data-slot` 为空):它们是 `<DataTable>` 自己的排序头、展开箭头、分页与列显隐控件。
> 实测高度 **20px×8 · 28px×5 · 30px×2**,圆角 4px / 6px,**一个都不是 32px**。
> (整页另有 10 个裸 `<button>` 在顶栏与 dock 里,那是应用外壳,不属于取样页内容。)
> ☞ **这不在 Tim 的裁定范围里**(裁定说的是按钮的尺寸档,而这些根本没走档位),
> 但它是「按钮为什么看起来不一样」的另一半答案,**记在这里,不替它定值。**

### 5.1 这条裁定要动多少个调用点 —— **实测,Tim 还没有看过这个数**

量法:`app/` 下 `.tsx` 里 `<Button>` / `<ConfirmButton>` / `<LinkButton>` 的开标签,
取其 `size=` / `triggerSize=` 字面量。**不含 `app/components/ui/` 自身。**
双向钉住:`<Button>` 判据数出 **547** = 裸 grep **547**(与 STYLE-0 的 547 独立吻合)。

| `size=` | 调用点数 | 在裁定里吗 |
|---|---:|---|
| `sm` | **243** | ★ **是** |
| `default`(隐式,没写 size) | 232 | 已经是目标档 |
| `inline` | 73 | **不是**(它不是一个盒子,见下) |
| `xs` | **45** | **裁定没有点名它** ⚠ |
| `default`(显式写了) | 16 | 已经是目标档 |
| `lg` | **5** | ★ **是** |
| **合计** | **614** | |

> ### ★★ 所以这次改动的大小是:**248 个调用点**(243 个 `sm` + 5 个 `lg`)★★

**其中 `lg` 只有 5 处,逐个点名 —— 它们全部会从 `h-9`(36px)降到 `h-8`(32px):**

```
app/inbound/receive/ReceiveForm.tsx:340
app/inbound/receive/done/[id]/page.tsx:95
app/inbound/receive/done/[id]/page.tsx:98
app/stocktakes/CountList.tsx:80
app/stocktakes/[id]/page.tsx:216
```

> ★ 这 5 处**都是收货与盘点的主操作按钮** —— 也就是**站在仓库里、多半拿着手机
> 或扫码枪在按的那几颗**。把它们从 36px 降到 32px,方向是**变小**。
> **这不是我该替 Tim 决定的事,所以本文只把它摆出来。**

`sm` 那 243 处的完整名单在普查输出里

## 6 · ★ 取样页【没有】覆盖什么 —— 这些元素今天没有标准 ★

> **这一节是本文最容易被略过、而后果最大的一节。**
> 一个取样页里没有的元素类型,**它没有标准** ——
> 说出这句话是诚实的结果,**不是一个应当拿一个我挑的数去填的洞**。

**下面每一个「0」都是量出来的**(量具在整页上跑同一套选择器,结果为零):

| 元素类型 | 取样页里的处数 | 于是 |
|---|---:|---|
| **文件上传 `<input type="file">`** | **0** | **没有标准。** 而全站有 8 处(STYLE-0 点过名) |
| **日期框 `<input type="date">`** | **0** | **没有标准** |
| **数字框 `<input type="number">`** | **0** | **没有标准** |
| **原生下拉 `<select>`** | **0** | **没有标准**(取样页只有 Radix 的 `SelectTrigger`) |

## 7 · 量的时候撞见的三件事(全部是实测,不是推断)

### 7.1 ★ C 的表头线写的是 2px,**在取样页上渲染出来是 1px** ★

`Spec.headRow` 写的是 `border-b-2 border-[color:var(--brand-ocean)]`。
**实测取样页里那条线:`border-bottom-width: 1px`,颜色 `rgb(0,142,188)` = `#008EBC`。
颜色赢了,粗细输了。**

**机制(查实,不是猜):** `app/components/ui/table.tsx:26` 的 `TableHeader` 带着
`[&_tr]:border-b`,它编译成一条**后代选择器**(特指度 0,1,1);
而行自己的 `border-b-2` 是一个普通类(特指度 0,1,0)。
**特指度高的那条 1px 赢了。**(`cn()` 已经把行上的 `border-b` 合并掉了 ——
实测行的 class 串里只剩 `border-b-2`,它仍然输。)

> ★★ **而【已上线的那条路是对的】** ★★
> `app/components/ui/data-table.tsx:391` 用的是**裸 `<thead>`**,不经过 `TableHeader`:
> `<tr className="border-b-2 border-[color:var(--brand-ocean)]">` ——
> **实测渲染 `border-bottom-width: 2px`,颜色 `#008EBC`。**
>
> **结论:标准值是 2px,`<DataTable>`(98 个文件在用)今天已经是对的。
> 那个 1px 只出现在 `table.tsx` 这条路上,而它至今仍在 `GUARDED` 名单里、禁止使用。**
> ☞ 这一条**只有实测量得出来**:读 class 串会读到 `border-b-2`,然后写下一个
> **从来没有在屏幕上出现过的 2px**。

### 7.2 C 的 `card` 里那个 `border-[color:var(--brand-border)]` 是**空转的**

实测卡片:`border-width: 0px`,而 `border-color: rgb(202,213,224)`(= `--brand-border`)。
**颜色设了,宽度是 0 —— 于是它什么都没画。**
屏幕上那条卡片边缘,是库自己的 **`ring-1`**(`oklab(0.204625 …/0.1)`,1px)。

☞ 所以 §4.4 把边缘记成 **ring,不是 border**。
**照着 C 的 spec 字面去写 `border-[color:...]`,画不出任何东西。**

### 7.3 手机上,输入框的字比紧挨着的下拉框大 2px

实测 390px:`<Input>` **16px**,`<SelectTrigger>` **14px**(desktop 上两者都是 14px)。
原因是 `input.tsx` 有 `text-base md:text-sm`,而 `select.tsx` **没有这一条**。
输入框那一条是**刻意的**(iOS 在 <16px 的输入框上会自动放大整页);
**下拉没有跟上,而它们在表单里通常上下紧挨着。**
☞ 这一条本文只**记录**,不裁定 —— 它落在 §9 Q3 那个更大的问题里面。

### 7.4 两个字色同时在用,而两个都是**明写过、都合规**的

`--foreground` = **`#171717`** 与 `--brand-text` = **`#182B4B`** 是两个不同的颜色,
`app/globals.css:48–49` 把两者的对比度都记在案上(16.84:1 与 13.27:1,都过 AA)。

**在 variant C 里,落到 `#171717` 的有三处:表头格 `<th>` · 徽章 `<Badge>` ·
次档按钮的字。其余一律 `#182B4B`。**

☞ **这不是缺陷**(两个都合规),但它就是 Tim 第 ④ 条抱怨(「文字颜色不一」)
在取样页里的实测形态:**两种深色,差一点点,同屏出现。**
**要不要收成一个,是 Tim 的决定,本文不替他收。**

## 8 · 与 `/login` 三处刻意偏离的冲突 —— 必须现在说

`docs/login-page.md` §4 记了三处**刻意偏离** variant C 的地方,每一处都有理由。
**Tim 的范围裁定(§2)一旦照字面执行,其中两处会被推翻:**

| # | sampler 里的 C(**本文实测**) | `/login` 今天 | 偏离的理由(原文) | 照 §2 会怎样 |
|---|---|---|---|---|
| ① | 卡片 `shadow-md` | `shadow-lg` | 它浮在一块**有起伏的底**上,差一档就分不开 | **会被推翻** |
| ② | 输入与按钮 **32px**(实测) | **44px**(`h-11`) | 手机上的**主操作**要够得着;44px 是 Apple HIG 与 WCAG 2.5.5 都指的那个数 | ★ **会被推翻** |
| ③ | 焦点环 `ring-ring/50` | 实心 `--brand-ocean` + offset | **实测半透明那一档对白底只有 1.6:1**,达不到 1.4.11 的 3:1;实心是 3.75:1 | **会被推翻,而这一条推翻它会掉到 AA 以下** |

> ### ★★ 这不是一句反对,是一句必须摆在桌面上的话 ★★
> **③ 是一条无障碍合规项** —— 把 `/login` 拉回 C 的 `ring-ring/50`,
> 那一页的焦点指示会从 3.75:1 掉回 **1.6:1**,低于 WCAG 1.4.11 要求的 3:1。
> **② 的 32px 也低于 44px 的触控建议**,而 `docs/brand-tokens.md` §5.4 明写
> 「Tim 在手机上用这个系统」。
>
> ☞ **建议(需要 Tim 拍板):把「刻意偏离」做成标准的一部分,而不是标准的例外** ——
> 也就是:**标准 = 取样页的读数 + 一份【带理由的、有限的】偏离清单**,
> 而这三条就是清单的头三行。
> **本刀没有替他这么定,因为这是形状,不是细节。**
